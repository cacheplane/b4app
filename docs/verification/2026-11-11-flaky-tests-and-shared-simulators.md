## 2026-11-11: Flaky tests, a shared layout Simulator, and the registration cleanup's running check

Every `ci.yml` failure in the last 150 runs was read for its failing test. Four failing tests still had their cause on `main`. The rest had already been fixed there: `LaunchAgentInstallTests` (9acbd02), `ThreadDeleteTests.aLateEventDoesNotBringTheThreadBack` (fenced by #137, after its three failures), and `MirrorRelayTests.presenceBecomesHostPresenceEvents` (3be4386, which the failing branch did not have). The iOS layout job's failures are other sessions' work in progress (`layout-back-cancel-flake`, `ios-ci-journey-consolidation`).

| Test | Cause | Fix |
| --- | --- | --- |
| `AccountCommandTests.logoutIsBoundedWhenTheRuntimeAndTheHubIgnoreCancellation` (7.64 s against 7.3 s, PR #168) | Wall-clock bound with 3 s of slack on a starved runner | Slack 7 s: still under the 7.5 s that a step at its standard bound would add, so a step that ignores its shortened bound still fails |

Each fixed test passed three times in a row here (load average 45 to 100).

**The layout Simulator.** `Scripts/test-ios-layout.sh` picked the first booted iPhone, so sessions in two checkouts ran on one Simulator. Each run installs and launches the harness under the same bundle id, so one run killed the other's tests: on 2026-11-09 a run reported a search field that its own build did not have, and two tests "crashed with signal kill/term". The script now makes and uses one Simulator per checkout, "B4App Layout <n>" (<n> is a checksum of the checkout's path, as `Hub/scripts/test-db.sh` does for databases). `--stop` deletes it.

**`fix-app-registrations.sh` never saw a running copy.** `running()` piped `ps` into `grep -q` under `set -o pipefail`. grep exits at its first match, ps dies of SIGPIPE (141), and the pipeline fails, so a running copy read as idle and `--apply` would unregister it. That happened for the running `/Applications/Agent Workspace (Local).app`, which the dry run listed without "(running …)". grep now reads all of ps's output. `--keep <path>` (repeatable) keeps another app or directory as well, for the Local app installed in `/Applications`. The bats file's `[[ … ]]` and `! grep` lines now end in `|| false`: under macOS's bash 3.2 a failing one that was not a test's last line did not fail the test, so the new running-copy test first passed against the broken script.

**Applied.** `--dist ~/repos/b4app/dist --keep "/Applications/Agent Workspace (Local).app" --apply` unregistered 20 stray copies (old Debug builds, other worktrees' `dist/`, `/private/tmp` experiments, the 2026-11-09 backups) and registered the kept apps again.

**The prod and Beta apps, restored.** `~/repos/b4app/dist` held only a Local build packaged at 2026-11-10 18:54: `package.sh` empties `dist/` first, which removed the prod and Beta apps (2026-11-09, `706bfe7`). Their coordinators still ran from the deleted bundles, and both LaunchAgents pointed at executables that no longer existed, so a restart or reboot would have left them with none. Both were packaged from `main` 3cea9e2 in a scratch checkout (Developer ID, notarization accepted, stapled, `spctl` accepted) and installed in `/Applications` beside the Local app. Opening an app does not swap a running coordinator: it connects to whatever answers on the socket and installs its LaunchAgent only when nothing does. So each old job was booted out (its coordinator exited in order) and the app opened again, which wrote the plist for its own helper and bootstrapped it. Afterwards `coordinator status` names the `/Applications` executable for both; `hub status` shows the relay connected and 0 unsynced changes on hub.b4.run and hub.test.b4.run; `db status` shows the schema through `0012_app_folders` and the rows kept (prod 18 threads, Beta 5).

**The registration cleanup's re-registration.** `--dist /Applications --apply` then unregistered the 7 strays left (the deleted bundles' coordinators, a Debug build, `~/repos/b4app/dist`'s Local copy, the scratch build), but also ran `lsregister -f` on every other app in `/Applications`. It now registers again only bundles whose `CFBundleIdentifier` is one of the flavours' ids, with a bats test that a foreign app and a bundle without an Info.plist in a kept directory are left alone (it failed first).
