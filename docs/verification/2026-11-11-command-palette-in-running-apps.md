## 2026-11-11: Command palette and composer commands in running apps

The palette (D-207) and the runtime commands (D-211) had been rendered and unit-tested but never driven. This run drove them: the Mac with real keys through XCUITest, the iPhone by hand in the Simulator. Both used the fixture apps (the shipped `WorkspaceRootView` over an isolated coordinator, or an in-memory mirror), never the owner's account or data.

- **Mac, `PaletteSmokeTests.testPaletteAndSlashByKeyboard`** (new, in `Tests/macOSSmoke`; the real coordinator and the fake Codex): ⌘K with the field focused, a typed query, Return opening the thread; the cursor back in the composer at the end of the draft, which was kept; ⇧⌘P and a command run by Return (Pin, confirmed by `thread.read`); Up and Down; `>` into Commands and Backspace back to Find; Escape; Tab to a thread's actions; Rename with the title in the field, confirmed stored; `/` in an empty draft listing the app's six commands and Codex's `/review` and `/compact`; narrowing; Return completing `/review ` in the draft; a setting's values and Escape stepping back; a path left alone; a row clicked with the pointer. No `turn/start` reached the runtime. Passed four times in a row once the focus fix was in, and again on the final code after the list's presentation moved, on a Mac under load (average 24).
- **iPhone 17 Pro Simulator (iOS 26.5), by hand in the layout fixture app:** the Search sheet from the list, a thread's actions from its trailing button, the Rename page, opening the thread, and the composer's `/` list with a row tapped through to the model's values. The fixture connection carries no runtime commands, so the phone's list of them was not seen.
- **What the run found, all fixed:**
  - Opening a thread from the palette left the cursor nowhere: the composer did not exist yet when focus was requested. The composer now answers a request made before it appeared, and asks until the field has the cursor (it failed once in seven runs before that).
  - Backspace in the empty Commands field did nothing on the Mac: the key arrives as U+007F, not the U+0008 the handler matched.
  - Return with the `/` list open added a line instead of picking: the editor has the key before the round control's shortcut. Return is now handled in the editor.
  - Tapping a row of the `/` list did nothing on the iPhone: the composer is in the system's bottom bar, and a view drawn outside the bar takes no touches. The thread view (and the new-thread view) now presents the list, placed from the field's anchor.
  - The existing iPhone journey `testWorkspaceNavigationJourney` looked for the old "Search threads" field; it now looks for the palette's.
  - On the phone: Find's prompt was cut mid-word (it is shorter there now), the Rename page used the system's grouped look (it is the app's surface now), and `/new` showed ⌘N (key hints are the Mac's only).
- **Still unchecked:** VoiceOver (XCUITest could not find a hit point for a `/` row through accessibility, though the pointer reaches it, so the list's accessibility structure needs a look); IME composition; Reduce Motion; hover; a turn running while the list is open; the new-thread draft's list below the field in a running app; the full 13-journey iPhone suite (two journeys were run); a physical iPhone; and runtime commands against a live Claude Code or Codex session inside the app.
