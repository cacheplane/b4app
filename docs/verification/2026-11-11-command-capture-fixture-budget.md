## 2026-11-11: Migration grants, socket shutdown and regression qualification

Concurrent public Hub migration runners can reach permission grants after SQLx releases its migration lock. Native CI caught a catalog ACL collision there. The seven existing grant/revoke statements now commit as one transaction, retried as a unit on serialization/deadlock errors or the exact PostgreSQL `XX000` / `tuple concurrently updated` collision. Other failures return immediately; bounded exhaustion retains its actual error. The application role still cannot mutate the migration ledger or Hub settings. Published migrations and role-password policy are unchanged.

Two deterministic native controls inject a fault at the later default-privilege step. A nontransactional counter proves the retry reached that step, and the final policy retains restricted-table read-only access. The permanent-fault control proves exactly one trigger firing, the intended native error and rollback of all earlier grants. The original real concurrent-runner regression remains intact. PostgreSQL documents this supported boundary in its [event-trigger matrix](https://www.postgresql.org/docs/16/event-trigger-matrix.html).

The command-capture happy-path fixture now has an explicit 120-second budget while retaining stdout, stderr, exit-code and no-timeout assertions. Production `CommandRunner` still defaults to ten seconds, and the dedicated hung-command test still uses 300 milliseconds. The iOS Back helper requires the destination list dock before the next action, using the existing 60-second layout-state budget; it neither repeats the Back tap nor skips layout or journey coverage.

[First PR CI](https://github.com/cacheplane/b4app/actions/runs/43140838561) passed all 1,606 package tests, including the capture fixture after 37.880 seconds, but exposed the Hub catalog collision and one immediate-after-Back iOS failure. [The corrected-source run](https://github.com/cacheplane/b4app/actions/runs/43143538290) passed all 1,606 package tests in 190.139 seconds, including capture after 46.346 seconds, and passed the Hub, app-build, Node, lint and iOS jobs. The Hub run includes the actual concurrent-runner regression and both new deterministic controls. This run still failed one of seven macOS smoke cases: owner-pipe closure trapped during coordinator shutdown.

The smoke artifact's host log identifies `NIOAsyncWriter` deinitialization without `finish()`, and its detailed result reports signal status 5. The fixture intentionally closes ownership before its external client necessarily receives hello. The server correction preserves that legitimate window: it closes listener admission normally, drains accepted wrappers into their scoped handlers, joins actual handlers and the accept owner, then stops the event loop. Repeated/concurrent closers wait for one retained cleanup task. No borrowed writer is manually finished and the accept owner is not canceled.

The close-order argument is specific to pinned SwiftNIO `6db9d9abd92ad7399b8a564cafbb87d3507245fa` (2.104.0), one shared event loop and the existing completed child initializer. Bootstrap queues one transform hop; the event loop drains immediate-task batches to empty before another selector phase, so a nested close turn follows in-flight transforms. A scheduler, child-loop or asynchronous-initializer change requires renewed ownership review. Three source-first controls cover buffered wrappers, raw-accept/initializer ordering and a held actual dispatch. These new controls and the corrected smoke path still require current-source native CI.
