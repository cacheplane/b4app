## 2026-11-13: three CI flakes

Three tests that failed on unrelated pull requests and on `main`, each traced to its cause from CI's logs and results. Branch `blove/ci-flakes`, from `main` f8a28e0.

### The package tests' stall (`MirrorSyncTests`)

- Seen: seven `MirrorSyncTests` waits ("first page", "parked in its long poll", "snapshot applied") timed out together at 79.5 s on #191 and #193, and twice on the palette branch. Each waits at most 60 s.
- Cause: in #193's two attempts no test of the 1,791 finished in the first 50 s (the passing attempt) or 70 s (the failing one), then hundreds finished at once; in the passing attempt the same seven took 58 to 62 s, just under their limit. Every test that needs PostgreSQL calls `EphemeralPostgres.endpoint()` synchronously from Swift's cooperative threads (one per core), and all but one wait on the lock while that one starts the shared cluster. With as many waiters as cores, nothing else in the process runs, the waits' own timers included (they fired 19 s late). Locally (10 cores) the stall reproduced: `sample` showed nine cooperative threads in `ensureStarted`'s lock and the tenth in `sweepStale` and then `initdb`; a trivial synchronous mirror test took 69.6 s.
- Change: with `B4APP_TEST_POSTGRES_DIR` set, the cluster lives in that directory, outlives the process, and is used at once by a later process that finds it running; CI starts it with one test before `swift test`. The sweep of earlier runs' clusters runs on its own thread, never under the lock. The start prints how long it took to stderr, so the next CI log says.
- Checked locally: the same eight suites, before and after: `MirrorSyncTests` 71.0 s and the run 108.6 s, then 8.2 s and 47.9 s with the in-process start (1.7 s; earlier runs had already swept the old clusters) and 8.3 s and 48.8 s on a warmed cluster ("in use after 0.0 s"). A directory whose socket path would pass 104 bytes is refused by name.

### The palette's drag (`PaletteSmokeTests.testPalettePanelDragsSnapsAndKeepsItsShadow`)

Failed four times (twice on `main`), in two ways.

- 12 pt short (main at 00:32): the press's own trace showed the last drag event 12 pt before the release; the panel moved on drag events only, so it ended one step short. `PalettePanel` now takes the release as the drag's last step (and a release past the threshold with no drag event is a drag). Unit test `aDragEndsWhereThePointerIsReleased`: failed at 12.0 pt, passes.
- Into the Dock (main at 19:42): the screen recording shows no window at launch; the test checked once, without waiting, and opened one with File > New Window. That window never showed the command centre, so the palette opened at its fallback place, 140 pt lower, and the 130 pt drag down was clamped against the Dock (286 + 422 = 708, the Dock's top). Two causes: `CommandCenterPresenter` attached its panel only from a SwiftUI update, and the first came before the view had a window; a window opened while the workspace already shows (New Window here, a window reopened from the Dock in the app) brings no later update. The presenter's view now attaches when it moves to a window. Unit test `theButtonComesWithAWindowThatArrivesLater`: failed (no panel), passes. The smoke tests now wait up to 15 s for the launch window before New Window (`launchWithWindow`, in all six places).

### The banner journey's rotation (`BannerLayoutTests.testConnectionNoticeJourney`)

- Seen once on `main`: "Failed to set device orientation: Timed out waiting for confirmation of orientation change", from `launch()`'s portrait reset in the run's first test, straight after the Simulator booted; the confirmation came 15 s later.
- Change: `launch()` turns the device upright only when it is in landscape; the landscape journey turns it back in a teardown block too, so a failed step cannot leave it on its side.
