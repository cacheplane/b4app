# Research: B4 runtime contract (verified 2026-10-30)

All source claims were read from https://github.com/cacheplane/b4run at commit `547c4ecbf3f7f7bf5662ed78522fbe8f6fe0b522`, which is also `main` HEAD on 2026-10-30 (2026-10-28, "Allow empty historical adoption placeholder (#1123)"). Docs were fetched from https://b4.run.

## Package and project shape

- `@b4run/cli` 0.15.7 on npm (latest, modified 2026-10-28), `"type": "module"`, bin `b4`, `engines.node >= 24.0.0` (needs unflagged `node:sqlite`). The npm package `b4` is an unrelated placeholder.
- Install as a project dependency and invoke the bin (`pnpm exec b4`, `node_modules/.bin/b4`). `create-b4-app` 0.15.7 scaffolds a project.
- App root is the nearest ancestor containing both `b4.config.ts` and a `package.json` with `"type": "module"`. Routes live under `src/app/<route>/index.ts` exporting `agent({...})` (or `workflow` / `graph` / `chain`); `_`-prefixed dirs are skipped. `.b4/` holds the sqlite stores, `permissions.json`, `b4.generated.d.ts`, `build/`.

## CLI commands

- `b4 routes [--cwd PATH] [--json]` prints `RouteManifest { appRoot, routes: RouteDefinition[] }` with `RouteDefinition { id, pathname, kind: "agent"|"workflow"|"graph"|"chain", entryFile, routeDir, segments }`. `id === pathname`, e.g. `/navlog`. Protocol route key is `${id}#${kind}`.
- `b4 dev [--port N] [--env-file PATH]`: no `--cwd`. Binds `127.0.0.1`. Loads env from `--env-file`, then config `env`, then `<appRoot>/.env`. Runs typegen before each child spawn, watches the app dir, restarts on change. Readiness via IPC then `GET /healthz`. Prints `B4.run dev ready at http://127.0.0.1:<port>`. Stops the child with SIGTERM then SIGKILL after 1000 ms.
- `b4 start [--host H] [--port N]`: no `--cwd`, no `--env-file`, does not load `.env`, does not run typegen. Host defaults to `HOST` then `0.0.0.0`; port to `PORT` then `8000`. Prints `b4 start listening on http://127.0.0.1:<port>`.
- `b4 build [--cwd] [--clean] [--out-dir]` writes `.b4/build/server.mjs`. `b4 run <route> [--cwd] [--url]` is a one-shot JSON command. `b4 threads tail <id> [--url] [--header]` is a reattach client. Exit codes: 0 ok, 1 validation, 2 config/runtime.

## HTTP Agent Protocol (`packages/cli/src/lib/dev/runtime-fetch-core.ts`)

| Method and path                       | Request                                                               | Response                                                                                                  |
| ------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `GET /healthz`                        | none                                                                  | 200 `{ status: "ready" }`                                                                                 |
| `GET /readyz`                         | none                                                                  | 200/503 `{ status, checks }`                                                                              |
| `POST /threads`                       | `{ metadata?, workspace? }`                                           | 200 `Thread`                                                                                              |
| `GET /threads/:id`                    | none                                                                  | 200 `Thread`; 404                                                                                         |
| `DELETE /threads/:id`                 | none                                                                  | 204                                                                                                       |
| `POST /threads/:id/runs/stream`       | `{ route: "<id>#<kind>", input?: { messages: [{ role, content }] } }` | 200 SSE; 400; 404 unknown route; 409 `run_in_flight`                                                      |
| `GET /threads/:id/runs/stream`        | none                                                                  | 200 SSE reattach; 404 `thread_not_found`; 409 `thread_route_unknown`                                      |
| `POST /threads/:id/runs/wait`         | same body                                                             | 200 final state                                                                                           |
| `GET /threads/:id/state`              | none                                                                  | 200 `{ config, created_at, metadata, next, parent_config, values }`; 404 before first checkpoint          |
| `GET /threads/:id/pending_interrupts` | none                                                                  | 200 `{ interrupts: [{ interruptId, resumeKey, value, grant? }] }`                                         |
| `GET /threads/:id/turns`              | none                                                                  | 200 `{ threadId, status, turns, warnings, truncated }`                                                    |
| `GET /threads/:id/events`             | none                                                                  | 200 AG-UI replay                                                                                          |
| `POST /threads/:id/resume`            | exactly `{ resume: [...], route }`                                    | 200 SSE; 400; 409 `resume_in_progress`, `run_in_flight`, `stale_interrupt`, `interrupt_set_mismatch`, ... |
| `POST /threads/:id/cancel`            | none                                                                  | 200 `{ status: "interrupted", thread_id }`; 409 `no_run_in_flight`                                        |

There is no thread list endpoint. Error bodies are `{ error: { message, details: { code } } }`.

```ts
type ThreadStatus = "idle" | "busy" | "interrupted";
interface Thread {
  thread_id: string;
  created_at: string;
  updated_at: string;
  metadata: Record<string, unknown>;
  status: ThreadStatus;
}
interface B4ResumeEntry {
  interruptId: string;
  status: "resolved" | "cancelled";
  payload?: "once" | "always" | "deny";
  grant?: string;
}
```

`resolved` requires `payload`; `cancelled` must omit it; extra keys are a 400; entries must match the pending set exactly. Route resolution order: `metadata.parked_route`, in-memory map, `metadata.route`, body `route`.

## SSE

Frames are `event: <type>\ndata: <JSON>\n\n` with a `: ping` comment every 15 s. Events: `chunk` (data is a JSON string text delta), `tool_call { id?, name, input, messageId? }`, `tool_result { id?, name, output }`, `tool_call_args { id, name, delta }`, `reasoning`, `message_end { messageId }`, `interrupt { interruptId, type: "permission-request", kind, detail, callId?, grant? }`, and terminal `done` with `{ output: <final state> }` on success, `{ output: { error } }` on failure, `{ output: { cancelled: true } }` on cancel, `{ output: null }` on a non-live reattach. Reattach streams start with a `state` frame `{ status, live, anchor, values, input, turn, interrupts }` and may end with `detached { reason }`.

`interrupted` thread status means cancelled or parked on a human; disambiguate with `pending_interrupts`. Client disconnect does not stop a run. `GET /healthz` checks liveness without inference.

## Authentication

No built-in bearer or API-key middleware. A project may define `src/auth.ts` (`defineAuth`), `src/middleware.ts` (`defineMiddleware`, runs only on execution paths: `runs/*`, `resume`, `pending_interrupts`, `turns`, `events`, `/agui/*`), and `src/thread-access.ts` (gates every `/threads/*`). `healthz`, `readyz`, `POST /threads`, `GET/DELETE /threads/:id`, `state`, `cancel` bypass middleware, so a deployed server needs outer auth or a proxy. The header convention is app-defined (`authorization: Bearer ...` in the `threads tail` example).

## Persistence

Defaults under `<appRoot>/.b4/`: `threads.sqlite`, `checkpoints.sqlite`, `permissions.json`, `memory.sqlite`, `interrupt-grants.sqlite`, `client-tool-calls.sqlite`. Threads, route metadata, checkpoints, pending interrupts and grants survive restart; the run registry, resume claims and live buffers are process-local, so after restart a thread may read `busy` or `interrupted` with no run.
