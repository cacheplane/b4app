# Bundling the Codex CLI and Claude Code in a third-party Mac app: licensing, packaging, and authentication (as of 2026-11-01)

Scope: whether b4app may ship its own copies of `codex` and `claude` (or the Claude Agent SDK) inside its app bundle, and how users would sign in to those copies. Mac App Store sandbox mechanics (entitlements, helper signing) are only touched on where they affect auth; another researcher covers them.

Fetch notes: Pages were read through a summarizing fetch tool. Quotes marked "verbatim" come from pages returned in full: Anthropic's Agent SDK overview, the Claude Code legal-and-compliance page, the Claude Code setup page, and the Claude Code authentication page. Quotes from OpenAI pages are as relayed by the summarizer. npmjs.com and help.openai.com returned HTTP 403.

## 1. Codex CLI: license, binaries, app-server as an embedding interface, OpenAI's stance on third-party embedding

### Takeaway
Codex is Apache-2.0 open source and ships as standalone Rust binaries for `aarch64-apple-darwin` and `x86_64-apple-darwin`, so bundling it is legally simple. You keep the license and NOTICE files. `codex app-server` is OpenAI's documented interface for "deep integration inside your own product", the same one that powers the VS Code extension. OpenAI marks it experimental, and its schema is tied to each Codex version.

### Cited Findings
- License: "This repository is licensed under the Apache-2.0 License." — [openai/codex README](https://github.com/openai/codex)
- Distribution: the README lists `npm install -g @openai/codex`, `brew install --cask codex`, and a curl install script. The standalone installers "download from `https://releases.openai.com/codex` by default". Prebuilt GitHub Release archives include `codex-aarch64-apple-darwin.tar.gz` (Apple Silicon) and `codex-x86_64-apple-darwin.tar.gz` (Intel). — [openai/codex README](https://github.com/openai/codex)
- What app-server is for: "Codex app-server is the interface Codex uses to power rich clients (for example, the Codex VS Code extension)." The docs add "Use it when you want a deep integration inside your own product" (auth, conversation history, approvals, streamed events), and "If you are automating jobs or running Codex in CI, use the Codex SDK instead." — [Codex app-server docs (developers.openai.com/codex/app-server, now redirects to learn.chatgpt.com/docs/app-server)](https://learn.chatgpt.com/docs/app-server)
- Protocol: bidirectional JSON-RPC 2.0. stdio, the default transport, uses newline-delimited JSON, and the WebSocket transport is experimental. "Clients must send a single `initialize` request per transport connection before invoking any other method." — [Codex app-server docs](https://learn.chatgpt.com/docs/app-server)
- Stability, as the summarizer relayed it: "The app-server command and WebSocket transport are experimental and aren't supported for production workloads." Some methods and fields sit behind the `experimentalApi` capability. — [Codex app-server docs](https://learn.chatgpt.com/docs/app-server). *Caveat: I could not confirm whether "experimental" covers the whole `app-server` command or only the WebSocket transport. The page is 144k characters and was read in two chunks, so verify on the page.*
- Version locking: the schemas come from `codex app-server generate-ts` / `generate-json-schema`, and "Each output is specific to the Codex version you ran, so the generated artifacts match that version exactly." — [Codex app-server docs](https://learn.chatgpt.com/docs/app-server)
- Client identification: set `clientInfo.name` to identify your client to the OpenAI Compliance Logs Platform. — [Codex app-server docs](https://learn.chatgpt.com/docs/app-server)
- Codex SDK (TypeScript): "The TypeScript SDK wraps the `codex` CLI from `@openai/codex`. It spawns the CLI and exchanges JSONL events over stdin/stdout." It requires Node 18+ and injects `CODEX_API_KEY` into the CLI's environment. — [openai/codex sdk/typescript](https://github.com/openai/codex/tree/main/sdk/typescript)
- Xcode integration, reported: Xcode 26.3 (February 2026) added agentic coding with OpenAI Codex and Anthropic's "Claude Agent". Users sign in with "Sign In With a ChatGPT Account..." (a device-code variant came later) or use an API key. Forum users describe a downloadable "Codex component" under Settings → Components and an `xcrun agent codex login` command. That suggests Xcode downloads and runs its own Codex binary rather than the user's install. — [Apple Developer Forums 814650](https://developer.apple.com/forums/thread/814650), [Apple Developer Forums 840995](https://developer.apple.com/forums/thread/840995), [Apple Developer Forums 825837](https://developer.apple.com/forums/thread/825837?page=2), [Kodeco guide](https://www.kodeco.com/ios/paths/ai-assisted-ios-dev/53684496-getting-started-with-ai-augmented-coding-in-ios/01-getting-started/03). These are forum and third-party reports, not Apple documentation.

### Inferences
- Bundling Codex in b4app is permitted under Apache-2.0. Ship the LICENSE (and NOTICE, if present) and don't imply OpenAI endorsement.
- b4app already uses the interface OpenAI documents for product embedding (`codex app-server` over stdio). Bundling only changes which binary the app spawns.
- Because the schemas are tied to each version, pinning a bundled binary makes the protocol contract more stable than running whatever version the user has installed. Each Codex bump still needs schema regeneration and fixture updates.
- Xcode appears to download and manage its own Codex rather than embed it at build time. b4app could do the same outside the App Store, but App Store rules on downloading executable code (Guideline 2.5.2) likely forbid it inside the store build. That rule is out of scope here.

### Gaps
- I found no explicit OpenAI statement that names third-party IDEs (JetBrains, Zed) embedding the Codex binary. Their Codex integrations were not researched in this pass.
- I did not confirm whether the "experimental, not supported for production" language covers stdio app-server or only WebSocket.
- I did not check whether the Codex binary needs anything outside the bundle at runtime, such as ripgrep, `/bin/sh`, or a Seatbelt `sandbox-exec` (Codex's own macOS sandbox). How Codex's own sandboxing interacts with the App Sandbox (nested sandbox-exec is generally not allowed in a sandboxed process) needs a separate check.

## 2. Codex authentication for a bundled copy: CODEX_HOME, credential storage, the ChatGPT OAuth flow, and third-party use of ChatGPT plans

### Takeaway
A bundled Codex keeps its login under `CODEX_HOME` (default `~/.codex`, file `auth.json`), in the OS keyring, or in memory only, as `cli_auth_credentials_store` selects. app-server exposes the whole login flow to the host app: browser ChatGPT login with a localhost callback, device code, API key, and experimental host-supplied tokens. OpenAI explicitly supports the ChatGPT login in Codex clients, and since September 2026 it also has a "Sign in with ChatGPT" program that lets third-party tools draw on a user's plan.

### Cited Findings
- Storage: "`file` stores credentials in `auth.json` under `CODEX_HOME` (defaults to `~/.codex`)". "`keyring` stores credentials in your operating system credential store and fails if it is unavailable". "`auto` uses the OS credential store when available, otherwise falls back to `auth.json`". "`ephemeral` keeps credentials in memory only for the current process." — [Codex authentication docs](https://learn.chatgpt.com/docs/auth) (also at [developers.openai.com/codex/auth.md](https://developers.openai.com/codex/auth.md))
- Browser login uses a local callback server on `localhost:1455`. Docs suggest SSH-tunnelling that port for headless machines. — [Codex authentication docs](https://learn.chatgpt.com/docs/auth)
- Device code (beta): "choose **Sign in with Device Code**, or run `codex login --device-auth`". The user must first enable it in ChatGPT security settings, or a workspace admin must allow it. — [Codex authentication docs](https://learn.chatgpt.com/docs/auth)
- API key: `printenv OPENAI_API_KEY | codex login --with-api-key`. "When you sign in with an API key, Codex uses standard API pricing instead of included ChatGPT plan credits." — [Codex authentication docs](https://learn.chatgpt.com/docs/auth)
- app-server login methods:
  - `account/login/start` with `type: "chatgpt"` returns a `loginId` and an `authUrl` for the host to open in a browser, and "The app-server hosts the local callback."
  - `type: "chatgptDeviceCode"` is for cases where "your client owns the sign-in flow or the browser callback is unreliable". It returns a `verificationUrl` and a `userCode`.
  - With `type: "apiKey"`, "the caller supplies an OpenAI API key".
  - Experimental `chatgptAuthTokens`: the host supplies an access token, an account id, and optionally a plan type. It needs `capabilities.experimentalApi = true` at `initialize`, and the server asks for fresh tokens after a 401.
  - `account/read`, `account/logout`, `account/updated`, and `account/rateLimits/read` cover account state.
  - Source: [Codex app-server docs](https://learn.chatgpt.com/docs/app-server)
- README: "Run `codex` and select **Sign in with ChatGPT**", recommended for Plus, Pro, Business, Edu, and Enterprise plans. — [openai/codex README](https://github.com/openai/codex)
- Third-party plan usage (reported, late September 2026, announced at DevDay): Plus and Pro subscribers can use their plan allowance inside participating third-party tools such as Devin, Amp, Warp, and OpenClaw. Users set a weekly cap per app, and when the cap is hit, included usage stops instead of moving to the tool's own billing. — [The New Stack](https://thenewstack.io/sign-in-with-chatgpt/), [daily.dev summary](https://daily.dev/posts/openai-makes-sign-in-with-chatgpt-a-way-to-use-your-subscription-in-third-party-developer-tools-7ewaoo6ze)
- "Sign in with ChatGPT" developer docs: "ChatGPT plan usage is an optional capability within Sign in with ChatGPT", and it "does not grant access to their ChatGPT conversations or other account context." The docs cover "ChatGPT plan usage for open-source and locally hosted apps". Paid or remotely hosted apps should "complete the interest form". Plan usage applies to "eligible Responses API requests". Settings and limits are tied to an issued `client_id` bound to one user and workspace, and the OAuth flow returns to a loopback callback. The docs also describe configuring the Codex app-server with an OAuth access token "authorized for ChatGPT plan usage". — [OpenAI SIWC: token sharing / open source](https://developers.openai.com/siwc/token-sharing-open-source), [SIWC quickstart](https://developers.openai.com/siwc/quickstart)
- History: in 2025 OpenAI previewed "Sign in with ChatGPT" in Codex CLI and took developer interest through a form. *(Older, May 2025.)* — [TechCrunch, 2025-05-27](https://techcrunch.com/2025/05/27/openai-may-soon-let-you-sign-in-with-chatgpt-for-other-apps/)

### Inferences
- In a sandboxed Mac App Store app, `HOME` points at the app's container, so the default `CODEX_HOME` would be `~/Library/Containers/<bundle-id>/Data/.codex`. The bundled Codex would have its own login, separate from the user's terminal `codex` login, and the user signs in once inside b4app. Setting `CODEX_HOME` explicitly to an Application Support path inside the container makes the location predictable.
- The browser flow needs the sandboxed process to listen on `localhost:1455`. That likely requires the `com.apple.security.network.server` entitlement, in addition to `network.client`, for the bundled `codex` helper, which inherits the app's sandbox. `chatgptDeviceCode` avoids the inbound socket but requires the user to have enabled device codes in ChatGPT settings first.
- For keyring storage, the sandboxed helper would use the app's keychain access group. `file` mode keeps a plaintext `auth.json` in the container. Either way, under the AGENTS.md secret rules b4app should leave storage to Codex rather than pass tokens around.
- Running OpenAI's own unmodified Codex binary, which signs in with OpenAI's Codex OAuth client, is how Xcode and the VS Code extension work. That differs from b4app registering its own SIWC client to call the Responses API directly. b4app does not need SIWC registration to bundle Codex.

### Gaps
- I found no OpenAI statement that settles whether a paid, closed-source third-party app (such as a paid App Store app) bundling the unmodified Codex binary with Codex's built-in ChatGPT login must join the SIWC program or file the interest form. The SIWC docs speak to apps calling the Responses API with their own OAuth client.
- help.openai.com "Using your ChatGPT plan in other apps and sites" (article 20001542) returned 403, so per-plan details are unverified.
- I did not test whether Codex's keyring mode works from inside an App Sandbox.

## 3. Claude Code: license, redistribution, and running it inside another product

### Takeaway
Claude Code is proprietary: "© Anthropic PBC. All rights reserved." under Anthropic's Commercial Terms. Anthropic's legal page does document "preinstalling or running Claude Code in your products". The conditions are that you accept the Commercial Terms, ship the binary unmodified with all of its built-in sign-in methods intact, and have each end user authenticate with their own API key, Claude subscription, or cloud-provider credential. You may not pay for, resell, or intermediate Claude usage on their behalf.

### Cited Findings
- License file: "© Anthropic PBC. All rights reserved. Use is subject to Anthropic's Commercial Terms of Service." — [anthropics/claude-code LICENSE.md](https://github.com/anthropics/claude-code/blob/main/LICENSE.md)
- Governing terms: the "Commercial Terms of Service - for Team, Enterprise, and Claude API users", and the "Consumer Terms of Service - for Free, Pro, Max, and Ultra users". — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Verbatim, under "Can customers offer Claude Code in their products?": "Unless we've mutually agreed otherwise, preinstalling or running Claude Code in your products or services (e.g. in hosted sandboxes or other agent infrastructure) requires agreeing to our Commercial Terms of Service and complying with the conditions below:
  - **The Claude Code binary must not be modified.** Claude Code must be installed and run as published by Anthropic, and customers may not remove, disable, or restrict any authentication method built into it (including methods that permit signing in with a Claude account or the user's own API key).
  - **Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf.** Each end user must authenticate with their own Anthropic API key, Claude subscription plan credentials, or 3P inference provider credential (Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry)." — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Naming, verbatim: "You can accurately say, in plain text, that your product has Claude Code preinstalled or that it runs Claude Code. But you can't use the Claude Code or Anthropic names or logos as part of your own product, feature, or company name, in your own logo, or in a way that suggests Anthropic built, endorses, or is partnered with your product." — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Anthropic supports distributing pinned versions, verbatim: "To block all update paths, including manual updates, set `DISABLE_UPDATES` instead. Use this when you distribute Claude Code through your own channels and need users to stay on the version you provide." — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- macOS binaries are "signed by 'Anthropic PBC' and notarized by Apple". Each release publishes a GPG-signed `manifest.json` with SHA256 checksums, signed from `2.1.89` onward, at `https://downloads.claude.ai/claude-code-releases/<VERSION>/`. — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)

### Inferences
- Under the current legal page, shipping the unmodified, Anthropic-built `claude` binary inside b4app and letting each user sign in with their own account or key looks like the documented "preinstalling or running Claude Code in your products" case. Anthropic expects the Commercial Terms to govern it.
- For an App Store build, "must not be modified" is the hard part. Apple requires every nested executable to be re-signed with the app's Team ID and sandbox entitlements (`com.apple.security.app-sandbox` plus `com.apple.security.inherit`). Re-signing replaces Anthropic's code signature. Whether Anthropic treats re-signing as "modified" is not addressed anywhere I found, so this is an open legal question to put to Anthropic. Patching code is clearly out; changing only the signature is ambiguous.
- b4app must not hide or remove Claude Code's own login choices (claude.ai account or API key) even if it would prefer one.

### Gaps
- No statement found on whether re-signing the binary, which Mac App Store submission requires for nested executables, counts as modifying it.
- No statement found on whether "preinstalling" covers bundling inside a distributed desktop app, as opposed to hosted sandboxes, beyond the "e.g." in the text. The wording looks broad, but its examples are server-side.
- I did not read the Commercial Terms themselves for redistribution clauses.

## 4. Claude Agent SDK: license, whether it bundles the binary, and the subscription-login rule

### Takeaway
The Agent SDK (TypeScript `@anthropic-ai/claude-agent-sdk`, Python `claude-agent-sdk`) falls under Anthropic's Commercial Terms. It runs the Claude Code binary, and the TypeScript package bundles a per-platform native binary as an optional dependency. Anthropic's docs say: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK." They direct developers to API keys. The legal page separately allows an end user to sign in to the unmodified `claude` binary with their own subscription. The line Anthropic draws is between the app offering claude.ai login (not allowed) and the user signing in through Claude Code's own flow (allowed).

### Cited Findings
- SDK definition: "A library that runs the Claude Code binary, with Claude Code's capabilities, such as built-in tools, permissions, sessions, and hooks." Other languages can "run the CLI as a subprocess with the `-p` flag and `--output-format json`". — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- License, verbatim: "Use of the Claude Agent SDK is governed by Anthropic's Commercial Terms of Service, including when you use it to power products and services that you make available to your own customers and end users, except to the extent a specific component or dependency is covered by a different license as indicated in that component's LICENSE file." — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- Subscription login, verbatim: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods described in the Quickstart instead." — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- Credential use, verbatim: "**Developers** building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider. Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow." — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Carve-out, same page, verbatim: "Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code as described under *Can customers offer Claude Code in their products?* above." The page also says "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice." — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Usage limits: "Advertised usage limits for Pro, Max, and Ultra plans assume ordinary, individual usage of Claude Code and the Agent SDK." — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Bundled binary (from localized TypeScript reference pages): the TypeScript SDK "bundles a native Claude Code binary for your platform as an optional dependency", for example `@anthropic-ai/claude-agent-sdk-darwin-arm64`. If the package manager skipped optional dependencies, it throws `Native CLI binary for <platform> not found`. `pathToClaudeCodeExecutable` points it at a separately installed `claude`. — [Agent SDK TypeScript reference (de)](https://code.claude.com/docs/de/agent-sdk/typescript), [(es)](https://code.claude.com/docs/es/agent-sdk/typescript.md), [(ja)](https://code.claude.com/docs/ja/agent-sdk/typescript.md). *I did not read the English page directly.*
- Branding: the allowed forms are "Claude Agent", "Claude" (inside an "Agents" menu), and "{YourAgentName} Powered by Claude". "Claude Code" and "Claude Code Agent" are not permitted, nor is Claude Code-styled ASCII art. — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- Policy history (secondary sources, dates partly conflicting):
  - February 2026: Anthropic's compliance page stated that Free/Pro/Max OAuth tokens are only for Claude Code and Claude.ai, "including the Agent SDK". The Register notes the Consumer Terms had barred third-party harnesses since at least February 2024. — [The Register, 2026-02-20](https://www.theregister.com/software/2026/02/20/anthropic-clarifies-ban-on-third-party-tool-access-to-claude/5014546), [GIGAZINE, 2026-02-20](https://gigazine.net/gsc_news/en/20260220-anthropic-third-party-block/)
  - Reports put the start of enforcement at January 9, 2026 (Max OAuth in third-party clients) or April 4, 2026 (subscriptions stop covering third-party tools). — [decodethefuture](https://decodethefuture.org/en/anthropic-blocks-third-party-tools/), [apiyi blog](https://help.apiyi.com/en/anthropic-claude-subscription-third-party-tools-openclaw-policy-en.html). Low-confidence secondary sources.
  - 2026-05-13: VentureBeat reported a separate monthly "Agent SDK" credit for paid subscribers (Pro $20, Max 5x $100, Max 20x $200, Team Premium $100/seat, Enterprise Premium $200/seat). It could cover third-party agents such as OpenClaw and Conductor that "authenticate through the Agent SDK", effective by June 15, 2026. — [VentureBeat, 2026-05-13](https://venturebeat.com/technology/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch), [GIGAZINE, 2026-05-14](https://www.gigazine.net/gsc_news/en/20260514-anthropic-claude-agent-sdk-credits)
- Current help-center status, as the summarizer relayed it: a June 15, 2026 update paused the announced Agent SDK usage change and says "third-party app usage still draw from your subscription limits". An October 7, 2026 update says "Claude Max, Ultra, and Team plans now include monthly API credits". Those credits apply to the Agent SDK and `claude -p` only when run with an API key from the linked Console organization. When signed in with the plan, the SDK and `claude -p` "still draw from your subscription limits". — [Claude Help Center 15036540: Use the Claude Agent SDK with your Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan). *Conflict: search snippets of older versions of the same article described a credit that "isn't available". The live article, marked "Updated this week", describes API credits on Max, Ultra, and Team. Treat the October version as current.*

### Inferences
- The current rule, as I read the primary pages:
  - b4app may not build its own claude.ai login screen.
  - b4app may not store, collect, or proxy a user's claude.ai OAuth tokens.
  - b4app may not market subscription rate limits as a feature without Anthropic's approval.
  - b4app may let the user sign in to the unmodified Claude Code binary through Claude Code's own browser flow (`claude auth login` / `/login`). The resulting usage counts against that user's plan.
- Today's b4app, which spawns the user's own `claude` and inherits their existing login, already fits the carve-out. A bundled copy fits too if b4app triggers Claude Code's own login (for example by running `claude auth login`), never touches the token, and lets Claude Code store it in its own Keychain entry or `.credentials.json`.
- API-key mode is unambiguous. If b4app offers it, the key should go to Claude Code through `apiKeyHelper` or the environment from a `SecretStore` reference, in line with AGENTS.md. The legal page allows a customer to configure their own API key.
- Positioning b4app as "built on the Agent SDK" (using the TypeScript SDK's bundled binary) puts it under the Agent SDK sentence, which disallows claude.ai login unless approved. Positioning it as "runs Claude Code" puts it under the more permissive "Can customers offer Claude Code in their products?" section. The wire behavior is the same either way, since b4app uses `claude` stream-json, but the framing changes which sentence applies. Get written confirmation from Anthropic before a commercial App Store launch that relies on subscription login.

### Gaps
- No primary statement found that names Zed (`claude-code-acp`), JetBrains, or Xcode 26.3's "Claude Agent" and the auth each uses. Xcode offers "Sign In With a Claude.ai Account", which opens the browser, per forum and blog reports ([Kodeco](https://www.kodeco.com/ios/paths/ai-assisted-ios-dev/53684496-getting-started-with-ai-augmented-coding-in-ios/01-getting-started/03), [Apple forums 840995](https://developer.apple.com/forums/thread/840995)). Apple is presumably a "previously approved" partner, but that is unconfirmed.
- The npm page for `@anthropic-ai/claude-code` returned 403, so I could not read the license field or latest version directly. The setup page's example version is `2.1.211`.
- The Python `claude-agent-sdk` packaging (whether its wheel bundles the binary) was not checked.

## 5. Native single-file builds: does a bundled `claude` need Node?

### Takeaway
No. The official `claude` is a native single-file executable for `darwin-arm64` and `darwin-x64`, and "the installed `claude` binary does not itself invoke Node". Even the npm package now installs that same native binary through a per-platform optional dependency. Reports say it is a Bun-compiled executable of about 100 MB that embeds JavaScriptCore. Codex is a native Rust binary, so neither agent needs a bundled Node runtime.

### Cited Findings
- Verbatim: "The npm package installs the same native binary as the standalone installer. npm pulls the binary in through a per-platform optional dependency such as `@anthropic-ai/claude-code-darwin-arm64`, and a postinstall step links it into place. The installed `claude` binary does not itself invoke Node." The page also says, "Supported npm install platforms are `darwin-arm64`, `darwin-x64`, ..." — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- The npm package declares Node.js 22+. On older Node, npm prints `EBADENGINE` but "`claude` still runs, since the package downloads a native binary that doesn't use your Node.js at runtime." — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- Requirements: macOS 13.0+, 4 GB+ RAM. "ripgrep: usually included with Claude Code". — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- The native installer layout is a launcher at `~/.local/bin/claude`, symlinked into `~/.local/share/claude/versions/`. "A running session reads parts of the Claude Code executable from disk as it works, not only at startup." — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- Bun, reported: the native build is TypeScript packaged with `bun build --compile`, about 100 MB, most of it the Bun runtime and JavaScriptCore. — [DEV Community](https://dev.to/frr149/claude-code-native-build-100mb-binary-to-ditch-node-for-good-2gi6). The Agent SDK docs mention an `extractFromBunfs()` helper (SDK v0.3.144+) for apps that are themselves Bun-compiled. — [Agent SDK TypeScript reference (ja)](https://code.claude.com/docs/ja/agent-sdk/typescript.md). Claims about a Rust-ported Bun or a `--runtime rust-bun` flag are unverified and come from low-quality aggregators, so they are excluded.
- Codex ships as native Rust release archives per architecture. — [openai/codex README](https://github.com/openai/codex)

### Inferences
- A universal b4app would ship two `claude` binaries (arm64 and x64, roughly 100 MB each by report; a universal `lipo` is not documented) and two `codex` binaries, or ship arm64 only. Bundle size grows by a few hundred MB.
- Bun-compiled executables use JIT, so a re-signed `claude` under the hardened runtime and App Sandbox likely needs `com.apple.security.cs.allow-jit`, and possibly `allow-unsigned-executable-memory`. App Review accepts JIT entitlements in Mac App Store apps, but this needs testing.

### Gaps
- No Anthropic primary source confirms Bun. Whether the binary needs specific hardened-runtime entitlements is not documented, and whether it runs under App Sandbox at all was not found in any source and needs a test.
- Whether Claude Code's bundled ripgrep is embedded in the binary or extracted to disk at runtime was not checked. Extraction to a writable, executable location matters in a sandbox.

## 6. Update cadence and pinning: implications for App Review-gated releases

### Takeaway
Both agents ship very often, and Claude Code's own docs warn that new models can require newer Claude Code builds. Anthropic documents `DISABLE_UPDATES` for "distribut[ing] Claude Code through your own channels" at a pinned version. Codex's app-server schema is tied to each version. A Mac App Store build would therefore take on every model launch and agent fix through App Review latency. An in-app self-updater for the agents is not an option there, since auto-update writes new executables.

### Cited Findings
- Claude Code channels: `"latest"` (default) and `"stable"`, which is "typically about one week old, skipping releases with major regressions". — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- Verbatim: "A newly launched model can require a Claude Code version newer than the stable channel serves. To run the model now, move to the latest channel." — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- Native installs "automatically update in the background". `DISABLE_AUTOUPDATER` stops only the background check. `DISABLE_UPDATES` blocks all update paths, "when you distribute Claude Code through your own channels and need users to stay on the version you provide." Managed settings `requiredMinimumVersion` and `requiredMaximumVersion` make Claude Code refuse to start outside a range. — [Claude Code advanced setup](https://code.claude.com/docs/en/setup)
- Version numbering: the setup page's examples are `2.1.89` and `2.1.211`. The auth page mentions features gated on v2.1.242, v2.1.290, and v2.1.299, which shows a very high release count within 2.1.x. — [Claude Code advanced setup](https://code.claude.com/docs/en/setup), [Claude Code authentication](https://code.claude.com/docs/en/authentication)
- Codex app-server schema: "Each output is specific to the Codex version you ran". — [Codex app-server docs](https://learn.chatgpt.com/docs/app-server)
- Xcode, reported: users fix Codex sign-in problems by deleting and reinstalling the Codex "component" under Settings → Components. — [Apple Developer Forums 825837](https://developer.apple.com/forums/thread/825837?page=2)

### Inferences
- For a bundled `claude`, b4app must set `DISABLE_UPDATES=1`, because a sandboxed bundle is read-only and an auto-updater would try to write into `~/.local/share/claude/versions` inside the container. b4app then ships agent updates as app updates.
- Each new Claude or OpenAI model that needs a newer agent build means an App Store release, delayed by review time. The Developer ID build, which uses the user's own installed agents, stays current independently. That argues for keeping "use installed agents" as the primary path and treating bundled agents as the App Store-only mode.
- Pinning is a stability benefit for b4app's protocol layer, which relies on Codex app-server schemas and Claude stream-json event shapes. Record the pinned versions in `docs/compatibility.md`.

### Gaps
- No published release-frequency statistics for either agent were collected. The claim of very frequent releases rests on version numbering, not a measured cadence.
- No source found on how OpenAI or Anthropic view agent binaries going stale inside App Store apps, such as minimum supported versions enforced server-side.
