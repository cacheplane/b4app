Known limitations of M8a (fixed ones are marked, with the M8b commit; the rest still stand):

- Disconnecting the phone is deleting the app; that leaves its hub device unrevoked. There is no Disconnect control yet.
- The phone's thread header shows the Mac's working directory from `threads.context`. That is a project path crossing the wire; the design's list of what never syncs names secrets, executable paths, pids, ports, sockets, and log paths, not this. The owner decided in M8b (D-046) that `threads.context` and project folder paths sync.
- The shell shows Mac wording on the phone ("Coordinator connected").
- Fixed in M8b (`35945a0`, `6c46334`): turns and runtime requests that arrive while a thread is open used to appear only on reopen; the mirror now reports the thread of every touched turn or request and the transport publishes `thread.updated` for it.
- No rate limit on `/v1/enroll`. Still open after M8d: the sign-in limits cover the `/v1/auth/` and `/v1/me/` ceremony routes only, and enrollment codes stay eight characters, ten minutes, single use.
- Fixed in M8b (`7293e72`, `911e58e`): `GET /v1/changes` pages had no byte limit; they now stop at 8 MiB of stored value sizes (D-050).
- Fixed in M8b (`6ee5d6c`, `5088ad3`, `21c2c40`): a value over 2 MiB was refused with a permanent 413 that blocked the Mac's queue and showed only in `hub status`; it is now rejected per change (`payload_too_large`), covered by `acceptedThrough`, and counted in `lastError` (D-049). Known limitations (the full reasoning is under D-048 to D-050):

- Rows that existed before the migration have no column clocks, and a missing clock counts as oldest, so the first clocked edit after the migration wins whatever its time.
- A phone edit the hub refuses (a Mac-only column, an oversized value) stays applied on the phone until a snapshot or a newer write replaces it; only the count shows, in Diagnostics.
- A local edit that waits behind a pull is stamped at the start of its transaction, before the pulled clock; the Mac and the hub can then disagree about that column until its next edit. Receivers clamp a clock more than five minutes ahead against their own wall clock, so a receiver whose clock is more than five minutes behind rewrites legitimate clocks, and two stores can hold different clocks for one change.
- The snapshot is one unpaged response, built in memory; the first prune after a long gap deletes the whole prefix in one transaction under the push lock.
- A permanent push error also blocks pulling on the phone (no read-only fallback); a repeatable non-data error in `applyRemote` stalls the Mac's pull with backoff; a second Mac's first edits can apply as a phone's for up to a minute. One Mac per user is assumed.
- The phone names a project's folders by path or from the folders its Mac already knows; it cannot browse the Mac's filesystem (D-180). The Mac's own project sheets (with its folder picker) stay Mac-only.
- Every `thread.updated` refetches the whole thread (debounced about 200 ms), so a large pull is many reads.
- The `serve` role check counts ownership of `changes` only, and a `NOINHERIT` member of a superuser can still `SET ROLE` (for a security review).
