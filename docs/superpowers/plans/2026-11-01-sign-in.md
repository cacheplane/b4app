# Sign-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Mac and iPhone apps open on a sign-in screen (b4.run wordmark, "Continue with Apple", "Continue with a passkey") that signs in or signs up against the hub. A new account gets a private org and one onboarding question, its full name. The Mac keeps one local database per account and resumes each exactly where it was left. Log out returns to the sign-in screen. A phone pairs, and signs in, by scanning the Mac's `https://<site>/pair#c=…` code.

**Architecture:**
- **Flavours.** Three flavours, `prod`, `beta` and `local`, are chosen at build time and read at run time from `Info.plist`. Each fixes the hub URL, the site domain (the passkey relying-party id), and every identifier that lets flavours sit side by side on one Mac.
- **Hub.** The hub gains identities (Apple `sub`, WebAuthn credentials), personal orgs, ceremonies and handoffs stored in PostgreSQL, and routes that end in today's device token. Logout deletes a token but keeps the device.
- **Coordinator.** The coordinator splits into a Mac-wide part (cluster, event log, runtimes, socket) and an `AccountScope` per signed-in account (its `WorkspaceDatabase`, `SessionService`, `LocalServerService`, `ProjectService`, `HubSync`, and M8c's `HubLink`). An `AccountManager` holds the scopes over a `registry` database.
- **Sign-in UI.** `WorkspaceUI` gains `SignInView`, `OnboardingView`, and an Account settings page. The app processes run only the system credential sheets; on the Mac every hub call goes through the coordinator.

**Tech Stack:**
- **Hub:** Rust 1.93.1, axum 0.8.9, sqlx 0.8.6, plus new pins: `webauthn-rs` 0.6.2 with features `danger-allow-state-serialisation` and `conditional-ui`; `jsonwebtoken` 11.1.0; `reqwest` with rustls, for Apple; `aes-gcm`, for refresh tokens at rest.
- **Swift 6.2:** `AuthenticationServices` (`ASAuthorizationController`, `ASWebAuthenticationSession`, `ASCredentialUpdater`) and `SafariServices`.
- **Website:** Next.js in `~/repos/b4run`.

**Spec:** `docs/superpowers/specs/2026-11-01-sign-in-design.md`. Read it with `2026-11-01-m8c-relay-design.md`, `2026-11-01-sidebar-profile-settings-design.md` (D-053), `Hub/API.md`, and `AGENTS.md`. The research is `docs/research/reports/Mac App Store sandbox for agents.md`.

**Prerequisite:** the M8c plan (`2026-11-01-m8c-relay.md`) is merged, so `0004_relay.sql`, `POST /v1/pairing-codes`, `hub.pair`, `hub.pairStatus`, `HubLink`, the "Remote access" page, and the phone's scanner exist. If it is not merged when this starts, stop and ask the owner which goes first. Do not build M8c's pieces here.

- Resolution order: `B4APP_FLAVOR` in the environment, then `B4AppFlavor` in the enclosing `.app`'s `Info.plist` (a CLI in `Contents/Helpers/` walks up to its `.app`), then `local`.

**Hub**
- Ceremony lifetime 5 minutes; handoff 2 minutes; both single use.
- Sign-up policy `B4HUB_SIGNUP=open|closed`, default `closed`. Compose `.env.example` sets `open`.
- Usernames are `u-` plus 8 random base32 characters. Org slugs are `o-` plus 8. The placeholder org name is "My Org". After onboarding it becomes "<first word of full name>'s Org", or "My Org" if the name is empty.
- Passkey registration: `user.name` and `user.displayName` are "Agent Workspace account", resident key required, user verification required, attestation `none`.
- Rate limits per IP per minute: `begin` routes 20; `finish`, `native` and `handoff` 10. Over the limit: `rate_limited`. The IP is the TCP peer, or the right-most `X-Forwarded-For` entry when `B4HUB_TRUST_X_FORWARDED_FOR=1`.
- Every hub secret is a plain environment variable read at start, never a file path; `B4HUB_APPLE_PRIVATE_KEY` holds the PEM contents.
- New error codes, on the hub and as Swift `ErrorCode`: `signup_closed`, `ceremony_expired`, `credential_rejected`, `last_identity`, `merge_refused`, `signed_out` (coordinator only), `work_running` (coordinator only).
- New environment: `B4HUB_WEBAUTHN_RP_ID`, `B4HUB_PUBLIC_URL` (from M8c), `B4HUB_SECRET_KEY` (32 bytes, base64), `B4HUB_APPLE_TEAM_ID`, `B4HUB_APPLE_KEY_ID`, `B4HUB_APPLE_PRIVATE_KEY`, `B4HUB_APPLE_AUDIENCES` (comma-separated: the iOS bundle id and the Services ID `com.cacheplane.b4app.signin`), and `B4HUB_APPLE_BASE_URL` (tests only; default `https://appleid.apple.com`). Apple routes answer `not_found` unless all Apple variables are set.

## Review Focus

1. **A Mac account whose token the hub refuses (401)**, because it was removed from the account on another device or deleted. That account becomes signed out, and the window shows the sign-in screen with "This Mac was signed out of <org name>." It must not loop on 401s or keep showing stale threads. Test in Task 9.
2. **The coordinator restarts while signed in** (an app update, a crash, `coordinator restart`). It comes back signed in to the same account with the same database, and the window never flashes the sign-in screen. Test in Task 9.
3. **The hub is unreachable at Log out.** Log out still completes locally: the token is forgotten and the scope closed. The undeleted hub token is reported once, in `hub status` for the next sign-in of that account. Log out never hangs past the two 10 s bounds. Test in Task 10.
4. **Two finishes race for one ceremony or handoff**, from a double tap or a retried request. Exactly one gets a token; the other gets `ceremony_expired`. Tests in Tasks 4 and 13.
5. **Signing in to an account whose database is missing or fails to migrate.** The sign-in is refused with the migration's error, the previous account is not left half-open, and the registry row is unchanged. Test in Task 9.
