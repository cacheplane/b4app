# M4 Managed B4 Execution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The coordinator registers local B4 projects, inspects their routes, starts/stops/restarts an owned `b4` server per project with verified ownership and redacted logs, and route connections on that server converse through the existing adapter from both the GUI and the CLI.

**Architecture:** `LocalServerService` (an actor in `Coordinator`) owns the `localServers` rows, spawns servers through a new `ManagedProcess` (posix_spawn, own process group, output to a log file), verifies ownership through `ProcessIdentity` (sysctl), waits on `/healthz`, and monitors health. `SessionService` consults it before touching a managed connection; `B4Adapter` is unchanged. The CLI gains the `server` commands and the GUI the Local servers surface.

**Tech Stack:** Swift 6.3, Darwin `posix_spawn` and `sysctl`, Foundation `URLSession` (existing `B4HTTPClient`), GRDB migration `v2`, Swift Testing, Python fixtures.

**Spec:** `docs/superpowers/specs/2026-10-31-m4-managed-b4-design.md`

## Global Constraints

- The project CLI is `<node> <project>/node_modules/@b4run/cli/dist/index.js`; never `.bin/b4`, never a shell, never downloaded; minimum CLI version `0.15.7`; Node major >= 24.
- The child environment is built by the coordinator (`PATH`, `HOME`, `TMPDIR`, `LANG`, `USER`, `SHELL`, env-file pairs); env-file values never appear in rows, results, events, logs, or UI state.
- Signals go only to a process whose identity (`pid`, start time within 1 s, argv containing the CLI path and the port) was verified; a port in use is `owned_process_conflict` and nothing is stopped.
- Readiness is `GET /healthz` → `{ "status": "ready" }` within 90 s; `b4 start` always gets `--host 127.0.0.1 --port <n>`; `b4 dev` always gets `--port <n>` and `--env-file <p>` when configured.
- Log files are `<dataDir>/logs/servers/<name>.log`, mode 0600, bounded at 4 MiB (keep the last 1 MiB), redacted on read; log lines are never events.
- `swift format lint --strict --recursive Sources Tests Apps Package.swift` clean; commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; `docs/roadmaps/*.md` untouched.

## Review Focus

1. A registration whose pid now belongs to an unrelated process after a reboot (pid reuse): the coordinator must mark it stopped and never signal it (Task 5 test `stalePidIsLeftAloneOnCoordinatorStart`).
2. `b4 dev` SIGKILLed while its runtime child holds the port: the group kill must take the child too, or the next start reports the conflict honestly (Task 5 test `stopReachesARuntimeGrandchild`).
3. An env file with `export KEY="va#lue"` and a `#` comment line: parsed without shell evaluation, the `#` inside quotes kept (Task 2 test `dotenvParsesQuotesCommentsAndExports`).
4. A route connection used while its server is stopped: `endpoint_unavailable` with the start hint, no adapter call, no turn row left running (Task 7 test `managedConnectionRefusesWhileStopped`).
5. A server that exits on its own while a thread is mid-turn: the monitor marks it stopped, the route connection goes `offline`, and the turn reconciles honestly on the next read (Task 7 test `serverExitMarksRouteConnectionsOffline`).
