# M8f APNs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The hub delivers M8f's notifications through Apple's push service, withdraws them when they are answered or read, and badges the app icon with the threads that need Brian.

**Architecture:** M8f's push transaction gains withdrawal detection and a badge count (the attention rules in SQL, checked by the shared fixture); `PushSender` carries alerts and withdrawals; a new `ApnsSender` speaks HTTP/2 to APNs with an ES256 provider token and deletes tokens Apple rejects. The phone sets its push environment from the build, removes withdrawn or stale notifications, and sets the badge after every sync.

**Tech Stack:** Rust (axum, sqlx, reqwest with `http2`, jsonwebtoken ES256, PostgreSQL), Swift 6 (UserNotifications, system SQLite), Terraform and the Infra shell scripts, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-02-m8f-apns-design.md` (approved 2026-11-02). It builds on M8f (`docs/superpowers/plans/2026-11-02-m8f-attention.md`, PR #63).

## Global Constraints

- Branch `blove/m8f-apns` (stacked on `blove/m8f-attention`); the PR opens after #63 merges.
- Hub migration `0013_push_withdrawal.sql` (main holds 0001–0012 once #63 lands). No Mac or mirror migration.
- Decisions from D-141 (main and open PRs hold up to D-140 on 2026-11-02); re-check main and open PRs before numbering.
- Configuration: `B4HUB_PUSH_SENDER=apns` needs `B4HUB_APNS_KEY_ID`, `B4HUB_APNS_TEAM_ID`, `B4HUB_APNS_PRIVATE_KEY` (each also `_FILE`); `serve` refuses to start on a bad or missing value, naming the variable, never echoing the key.
- APNs: `api.sandbox.push.apple.com` for `sandbox` tokens, `api.push.apple.com` for `production`, HTTP/2 over TLS; JWT `alg` ES256, `kid` key id, `iss` team id, `iat`, reused up to 50 minutes; headers `apns-topic` = the token's `bundle_id`, `apns-push-type` `alert`/`background`, `apns-priority` 10/5, `apns-collapse-id` = the notification key.
- Apple's answers: 410 `Unregistered`, 400 `BadDeviceToken`, 400 `DeviceTokenNotForTopic` delete the token row; 403 `ExpiredProviderToken`/`InvalidProviderToken` re-mint and retry once; 429 and 5xx retry once; anything else logged (reason, `apns-id`, device id, key) and dropped.
- Notification key: `request:<id>` or `turn:<id>`. Alert payload adds `"key"` and `"aps.badge"`; withdrawal payload is `{"aps": {"content-available": 1}, "withdraw": [keys]}` with no alert, sound, or badge.
- Badge: non-archived, non-deleted threads whose band is needs-input or unread.
- Phone push environment: Simulator (compile time) `sandbox`; device with `embedded.mobileprovision` its `aps-environment` (`development` → `sandbox`); device without one `production`.
- Never log or return a token, the key, or a JWT. `WorkspaceMirror` stays free of `UIApplication` and `UserNotifications`. Attention rules: one per language, checked by `Tests/Fixtures/sync/attention.json`.
- Gates: `swift build`, `swift test`, `swift format lint --strict --recursive Sources Tests Apps Package.swift`; from `Hub/`: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked` (test DB); both app builds; Infra's own tests for what Task 4 touches.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A token Apple calls dead is deleted, and a send to it is never retried forever (Task 3 `dead_token_is_deleted`).
- An expired provider token is re-minted once and the send succeeds (Task 3 `expired_jwt_is_reminted_once`).
- A request answered in the same batch it was created in neither notifies nor withdraws (Task 2 `answered_in_same_batch_is_silent`).
- A read of a later turn withdraws every earlier notified turn of that thread, once (Task 2 `read_withdraws_earlier_turns_once`).
- A TestFlight device build (no profile) registers `production` (Task 5 `device_without_profile_is_production`).

### Task 2: Withdrawal, badge, and token de-duplication in the push transaction

**Files:** Create `Hub/crates/b4hub-db/migrations/0013_push_withdrawal.sql`; modify `Hub/crates/b4hub-db/src/push.rs`, `src/changes.rs`, `tests/push.rs`, `tests/migrate.rs`.

**Interfaces:**
- Consumes: Task 1 `key`, `Kind`.
- Produces: `notifications_sent.withdrawn_at timestamptz` (nullable); `Notification` gains `key: String`, `badge: i64`; `pub struct Withdrawal { device_id, token, environment, bundle_id, keys: Vec<String> }` (hand-written `Debug` redacting the token); `PushOutcome.withdrawals: Vec<Withdrawal>`; `pub async fn needs_you_count(conn, org_id, user_id) -> Result<i64>`; `pub async fn bands(conn, org_id, user_id) -> Result<HashMap<String, Band>>` with `pub enum Band { NeedsInput, Unread, Working, Quiet }`.
- Rules: `bands` follows `Sources/WorkspaceProtocol/Attention.swift` (`band(of:)`): needs input when any request of the thread is `pending`; else working when the latest turn (greatest `createdAt`, ties by greatest `id`) is not `terminal`; else unread when that turn is not the thread's `readTurnId`; else quiet; no turn is quiet. Rows with `deleted_at` or a thread's own deletion marker are left out. The badge is the count of non-archived threads in needs-input or unread, computed after the batch is applied and set on every `Notification` of that push.
- Withdrawal detection, in the same transaction: a touched `runtimeRequests` row no longer `pending` whose `request` ledger row has `withdrawn_at IS NULL`; and a touched `threads` row whose `readTurnId` was applied, for every `turn` ledger row of that thread with `withdrawn_at IS NULL` whose turn's `createdAt` is at or before the read turn's. Set `withdrawn_at`, group the keys per target phone (the same targeting as notifications, the pushing device included), one `Withdrawal` per phone.
- `save_token` deletes other `push_tokens` rows of the org holding the same token.

- [ ] Tests in `tests/push.rs`: `answer_withdraws_once`, `expiry_withdraws`, `answered_in_same_batch_is_silent` (pending inserted and resolved in one push: no notification, no withdrawal), `read_withdraws_earlier_turns_once`, `withdrawal_reaches_the_reader_too`, `badge_counts_needs_input_and_unread`, `bands_match_the_shared_fixture` (push `attention.json`'s rows as a Mac, compare `bands` with `expected.bands`), `token_moves_to_its_new_device`; migrate test expects `[1..=13]`.
