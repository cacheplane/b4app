## 2026-11-05 (thread event publication)

- **D-185 Session events are checked for thread visibility at publication.** Implements D-119's rule that late runtime events may update retained rows but must not publish for a deleted thread. `SessionService` routes its implicit thread events through `WorkspaceStorage.withVisibleThread`: the existing shared remote-apply advisory lock is taken before a live-thread `FOR SHARE` row lease, then a synchronous callback publishes in the `EventLog` actor before commit. Local deletion conflicts on the row lease; pulled deletion conflicts on the exclusive advisory lock. Publication either completes before deletion or observes the committed deletion and suppresses the event. Explicit deletion notifications remain with their separate owner.
  - **Follows D-049's lock order.** The callback must be brief, non-suspending and nonreentrant to storage. Visibility-check errors prevent publication; rollback releases the lease. No schema, HLC, application-data or change-log mutation is added; row locks can still incur physical storage/WAL work.
  - **The cost and scope.** Four synchronous SQL round trips per thread event occupy the event-log actor. Existing pool, advisory and row waits can delay unrelated publication, replay and cursor access; there is no new hard wall bound or production streaming-throughput certification. This guards SessionService's implicit publications, not every event producer.
  - **The regression boundary.** The original slow-stream in-flight deletion test remains, with every original assertion and deadline. A producer cursor captured with deletion in one actor turn and an additional replay assertion distinguish delayed delivery from real post-deletion publication. Real PostgreSQL controls check visible/deleted/missing/closed callbacks and observed blocking of local and pulled deletion; removing the row lease makes the local ordering control fail. A held-stream replacement was rejected because it excluded the original in-flight race.
  - **The accompanying CI change.** Both fake B4 servers bind numeric addresses without unused reverse-DNS canonicalization and close their server on exit. Real bind/listen and HTTP/SSE behavior remain, with additive DNS-disabled and occupied-port controls. The measured integrated candidate includes this correctness fence and added tests; no exact attribution of seconds to DNS is claimed. Cache policy, supported targets, test selection, worker count and existing deadlines remain unchanged. No release, deployment or migration follows from this decision.
