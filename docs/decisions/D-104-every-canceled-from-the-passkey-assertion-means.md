## 2026-11-02 (sign-in build)

- **D-104 Every `.canceled` from the passkey assertion means "no passkey here", and the app asks before it creates an account.** `SystemPasskeyCeremony.meansNoCredential` (`Sources/WorkspaceUI/SignIn/PasskeyCeremony.swift`). With `preferImmediatelyAvailableCredentials` the system reports "no passkey for this domain" as `ASAuthorizationError.canceled`, the same code as a person's cancel, by design (Apple Developer Forums threads 735867 and 713321; Apple's passkeys sample). The first build told them apart by timing (a cancel within 0.6 s, or no presentation anchor asked for), which could leave a new user unable ever to sign up. So `.canceled` and `.notInteractive` both lead to "No passkey for <site> on this device. Create a new account?", whose own Cancel registers nothing; a person who cancelled sees the question once more. Registration passes the hub's `excludeCredentials`, and `.matchedExcludedCredential` reads "This device already has a passkey for this account." A cancelled Apple sheet, or `?error=cancelled`, shows nothing.
