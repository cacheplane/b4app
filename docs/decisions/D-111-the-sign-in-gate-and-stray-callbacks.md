## 2026-11-02 (sign-in build)

- **D-111 The sign-in gate, and stray callbacks.** `WorkspaceModel.rootScreen`, `Sources/WorkspaceUI/SignIn/AccountHost.swift`, `AuthCallback`. The root is blank while the account state is unknown, so a restart never flashes the sign-in screen; a coordinator that cannot be reached shows the existing unavailable state, even after a sign-out; a transport that answers `account.status` with `unsupported_capability` or `method_unknown` (an older coordinator) counts as signed in. Leaving `signedIn`, or switching account, forgets every row on screen, closes Settings and its sheets, and moves an account generation that drops answers to reads sent for the previous account; a `signed_out` answer to an ordinary command never changes the state. On the Mac every hub call goes through the coordinator (`account.*`; the Apple verifier never leaves it, and one Apple ceremony runs at a time, in memory); on the phone `MirrorAccount` makes them, reached through the `AccountHost` protocol so that `WorkspaceUI` imports no `WorkspaceMirror`. The Mac uses Apple's web flow in an ephemeral `ASWebAuthenticationSession`; the phone uses only the native sheet. A `b4app*://auth` URL handed to either app is dropped unread, ceremony in flight or not, because a ceremony reads only its own session's answer. While signed out, every CLI store command prints "Nobody is signed in. Sign in from the Agent Workspace app." and exits 4.
