## 2026-11-13 (selection motion)

- **D-222 The selected row's highlight glides the same way in the command palette, the folder and environment picker, and the `/` list (amends D-207).** At the owner's direction ("implementing the same smooth animation and smooth modern feeling in the folder/environment selector. Also in the command palette. These should really feel very much the same, although I'm okay with the command palette being more dense"; asked what "the same" meant: "I'm referring to the active/selection motion").
  - **What differed.** The folder picker's highlight slid on a 0.12 s ease-out under both the keys and the pointer, animated by the list as a whole. The command palette's slid on a 0.09 s spring under the keys only; under the pointer it jumped (D-207's "the pointer selects at once"). The `/` list had no moving highlight: each row filled or cleared its own background.
  - **The rule.** `SelectionMotion.glide` (`Sources/WorkspaceUI/Theme/SelectionMotion.swift`) is the one animation: a 0.16 s spring with no bounce, which retargets when a key repeats or the pointer sweeps across rows. `selectionHighlight(_:in:)` is the one shape (the raised surface, the input radius) carried between rows by a matched geometry. All three lists use both.
  - **When it moves.** Only when the person moves it: an arrow key or a pointer that itself moved. Each such change is made inside `withAnimation`; the picker no longer animates on every change of its highlighted index. A selection that changes because the rows did (typing a filter, a page opening) is placed without motion, so rows never cross-fade while typing.
  - **Density.** Unchanged, as the owner allowed: the palette's rows are 32 pt and the picker's 36 pt.
  - **Reduce Motion.** No glide: the highlight is on the new row at once (`SelectionMotion.animation(reduceMotion:)`; the `/` list's keys, handled in its controller with no view to ask, read the system's setting through `SelectionMotion.current`).
  - **Not done here.** Opening, closing and height changes still happen at once in both panels (the panel takes each size immediately so the window's shadow never lags the card). The owner asked only for the selection.
  - **Tests.** `SelectionMotionTests` for the rule; the palette, picker and composer suites and the snapshot renders still pass. The motion itself was not watched in a running app.
