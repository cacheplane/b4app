## 2026-11-16 (a task list changes on a result)

- **D-245 Claude Code's `TodoWrite` changes the list when its result arrives, and a dense running turn whose list has no step in progress has a running line (amends D-243).** The four minors D-243's review left, fixed at the owner's request.
  - **A failed `TodoWrite`.** D-243 replaced the list when the tool use arrived, so a `TodoWrite` Claude Code then reported as failed (a refused permission, a bad input) had already replaced it. `ClaudeTaskFold` now holds the use until its result, as it does for `TaskCreate` and `TaskUpdate`, and a failed result changes nothing and names no item. The item is still named after the tool use, so the live turn and the history import agree. A `TodoWrite` whose result never arrives (a turn stopped between the two) changes nothing: what Claude Code then holds is not known.
  - **The ids the fold keeps.** The fold kept the id of every task tool use for the life of the session to tell its results from other tools'. It now forgets an id when its result arrives. A use with no result is still kept; a turn stopped mid-call leaves one. The tracker also forgets a refusal recorded for a task tool use when that use's result arrives.
  - **A session started again.** D-243 read and folded the session's whole transcript on the adapter's actor before the first turn. The read and the fold now run off the actor (`ClaudeAdapter.seededTasks`), so the adapter's other sessions are not held while a long transcript is read. The session being started still waits for it: an update in its first turn needs the list.
  - **A dense running turn with only a list (amends D-239).** D-243 gave such a turn the list and no running line, on the reasoning that a step in progress says the turn is working. A list whose steps are all pending or all done says no such thing, so the turn showed nothing working. The running line is now drawn before the list unless a step is in progress or the turn has a message.
