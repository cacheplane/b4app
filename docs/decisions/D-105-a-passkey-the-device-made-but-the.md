## 2026-11-02 (sign-in build)

- **D-105 A passkey the device made but the hub refused is reported to the password manager, only when the refusal proves the hub kept nothing.** `WorkspaceModel.orphanProvingCodes`. When a registration's finish fails with `credential_rejected`, `ceremony_expired`, `signup_closed`, or `rate_limited`, the app reports the credential it just made as unknown, for the relying party named by the registration options' `rp.id`. Any other failure (`internal`, `incompatible_version`, `endpoint_unavailable`, a lost answer) is never reported: the hub may have stored the passkey, and reporting it would delete a live account's only credential. The calls go to `ASCredentialDataManager` on macOS and iOS 26.2 and later and to `ASCredentialUpdater` (deprecated in 26.2) on 26.0 and 26.1. After a sign-up's onboarding the same API renames the new passkey to the full name (`reportPublicKeyCredentialUpdate`, by user handle); the pending rename is kept in memory only, so quitting mid-onboarding leaves the placeholder name.
