## 2026-11-17 (a request offers only the allow its runtime applies)

- **D-248 A request says how far its wider allow reaches, the card offers it only then and names it for what it does, an unsupported one is refused, and a question that takes several answers takes several (amends D-018 and D-021).** The hill climb's audit found the card offering "Allow for session" on every runtime (defect 8, the one hard gate that failed). On Claude Code it did what "Allow once" does (D-018 sent a plain allow); on B4 it did more than it said, since B4 keeps an "always" itself, past the session; only on Codex was the label true.
  - **`allowScope`.** Each adapter writes it into the request payload it already builds (`request.allowScope`), read by `AllowScope` in `WorkspaceProtocol`: `session` on Codex's command and file-change approvals, new and legacy (`acceptForSession`); `always` on a B4 prompt unless it said `allowAlways: false`; none on Claude Code. A request with none can be allowed once or denied.
  - **The card.** `RequestChoices` gives its buttons: "Allow once" and "Deny", with "Allow for session" between them for `session` and "Always allow" for `always`. Both wider buttons send `allow_always`; no wire or schema change. The phone draws the same card from the synced payload.
  - **Refused, not narrowed.** `SessionService` refuses `allow_always` on a request with no scope (`unsupported_capability`) before the adapter is called, so the CLI's `--accept-session` and a phone's relayed answer are held to what the card offers; the request stays pending and can still be answered. The adapters no longer narrow: Claude Code refuses it where D-018 sent a plain allow, and B4 refuses it on an every-call prompt where D-021 sent `once`. The CLI's answer hint lists `--accept-session` only for a request with a scope.
  - **Several answers.** An `AskUserQuestion` with `multiSelect` and options draws a toggle per option, and its answer is the ticked labels in the question's order. (`RequestChoices.answer` appends typed text too, but no runtime sends a question with both `multiSelect` and `isOther` today.) The wire already carried a list per question, which the Claude adapter joins with ", ". A question that takes one keeps its picker.
  - **Left out.** Codex's other decisions (an execpolicy amendment, a network rule, `cancel`); showing or revoking a grant already given; a wider allow on Claude Code, which is the next step (a session rule through `updatedPermissions`, after a live recording); the Mac's buttons coming back briefly (defect 14). A request stored before this change has no scope and offers once and deny; a pending request does not outlive its turn.
  - **Verification.** `docs/verification/2026-11-17-a-request-offers-only-the-allow-its-runtime-applies.md`. Fixture-tested; the card was not seen on screen, and no live runtime.
