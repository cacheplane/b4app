## 2026-11-09 (checkpoint message identity)

- **D-200 B4 checkpoint messages retain their completed live app identities (amends D-031).** The real B4 workspace smoke trial found saved checkpoint ids differing from streamed synthetic ids, duplicating user and assistant messages during Check again.
  - **Turn scope.** `SnapshotItem` may carry a native turn id, absent by default for other adapters. B4 tags user/assistant messages at HumanMessage boundaries, the same ordinal used by its published turn-list projection and the adapter's existing `turn-N` identity.
  - **Safe fallback.** Exact native-item matches have priority across the entire incoming snapshot. A message with no exact match may reuse an unused live row only within one unambiguous terminal acknowledged native turn, with equal role, type and nonempty text. Preserve its app id, turn link and live payload, and adopt the canonical checkpoint id. A tagged item never falls through to D-031's global id-less text matching. Prepared refusals, unknown/running turns and ambiguous turn identities are excluded.
  - **Limits.** This reconciles display identity; it does not establish upstream exactly-once execution. Already-duplicated caches are not automatically deleted or rewritten. Existing fast fixtures and the real UI/model-fixture journey independently verify repeated reconciliation, saved drafts, native thread continuity and no provider/tool replay.
  - **Refused input.** The same trial exposed local input loss on a stopped-endpoint send. A failed local command restores its input only under the existing account, selected/open-thread, deletion and newer-text guards, without resending. A successful command's returned turn still clears the submitted draft.
