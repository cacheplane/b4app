## 2026-11-09 (CI: the layout tests leave the app-build job)

Its layout step took 1027 to 1503 s and the four builds 357 to 691 s together. The layout step generates its own project and builds the fixture app from the package; it uses none of the four builds' products, so running it after them only added their time to the critical path.
  - **The split.** `ci.yml` gains an `ios-layout` job named "iOS navigation and banner regression tests" with the same Xcode, XcodeGen, `.spm` cache, script invocation, and results upload. The "macOS and iOS app builds" job keeps its name and its four builds unchanged. No test, selection, assertion, cache key, or toolchain changes.
  - **Limits.** 20 minutes for the builds and 40 for the layout job, in place of 60 for both.
  - **Not measured yet.** The layout step no longer shares `.build/DerivedData` with the iOS simulator build that ran before it, so the 257 to 313 s it spent before the first app launch may grow. The expected saving is the builds' time less that growth; the pull request's first hosted run is the first measurement, and this entry claims no speedup.
  - **Required check.** Branch protection on `main` lists "macOS and iOS app builds", "Package build and tests", and "Hub (Rust)". The owner adds "iOS navigation and banner regression tests" before this merges; until then a layout failure would not block a merge.
