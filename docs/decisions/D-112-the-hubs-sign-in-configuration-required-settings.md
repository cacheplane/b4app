## 2026-11-02 (sign-in build)

- **D-112 The hub's sign-in configuration: required settings, `_FILE` forms, its own limiter, no OpenSSL.** `Hub/crates/b4hub/src/config.rs`, `auth_limits.rs`, `logging.rs`, `cli.rs`. `serve` requires `B4HUB_WEBAUTHN_RP_ID` (a bare lowercase domain; the origin is `https://<rp id>`) and `B4HUB_SECRET_KEY` (32 bytes, base64); the Apple set is all or none and checked at start (a `.p8` that does not sign exits 2). `B4HUB_SECRET_KEY`, `B4HUB_APPLE_TEAM_ID`, `B4HUB_APPLE_KEY_ID`, and `B4HUB_APPLE_PRIVATE_KEY` also take a `_FILE` form, as the database URLs do (both set exits 2; one trailing line ending is stripped), which revises the design's "every secret is a plain environment variable" for Compose and Kubernetes file secrets. The per-IP limits are the hub's own fixed one-minute windows (`auth_limits.rs`: IPv4 per address, IPv6 per /64, at most 100,000 clients per limit, swept once a minute), not M8c's relay limiter, whose keys are devices. webauthn-rs 0.6.2 verifies with RustCrypto, so the image gains no OpenSSL (the design said it would). The pool turns sqlx's statement logging off, and a filter layer apart from `B4HUB_LOG` drops every `webauthn*` target, which logs responses and challenges. Registration asks for a resident key and user verification; webauthn-rs's defaults ask for neither.
