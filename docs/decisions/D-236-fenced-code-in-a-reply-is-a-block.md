## 2026-11-14 (fenced code in a reply)

- **D-236 A fenced block in a reply is drawn as code with its language and a Copy button; the rest of the reply is the inline Markdown it was.** A reply was one text through Foundation's parser with inline syntax only. A closed fence became inline code with its language word joined to the first line ("bash swift test --filter SyncTests"), which is also what a selection copied; a fence still open as the reply streamed showed its backticks. No decision covered Markdown. The code is commit 99a558b0.
  - **The cut.** `MarkdownBlocks.split` cuts a reply's text into prose and code, without SwiftUI. A fence opens on a line of three or more backticks or tildes, indented at most three spaces, and closes on a line of at least as many of the same character and nothing else; a backtick line that holds another backtick is inline code. The language is the first word after the opening fence. A fence that has not closed is a code block marked open. The code is exactly the lines between the fences.
  - **Drawing.** `MarkdownText` draws a reply with no fence as the one text it was, so nothing else changes. With a fence, each prose block is that same text and each code block is a `CodeFence`: the language (or "code"), Copy, and the code at its full height in the code colours, scrolling sideways inside the block when a line is wider than the column. Copy puts the block's exact text on the pasteboard and reads "Copied" for two seconds. A block that is open while the reply is still arriving has no Copy; once the reply has ended it has one, closed or not.
  - **While it streams.** A block that has closed is never changed by later text (`blocksThatHaveClosedStayAsTheyAreWhileTheReplyStreams` checks every prefix of a reply). `MarkdownProse` and `CodeFence` are `Equatable`, so SwiftUI may skip the blocks whose text did not change; that this saves work was not measured.
  - **What it costs.** A selection no longer runs across a code block's edges: each block selects by itself. Copy is the way to take a block whole.
  - **Not done.** Headings, lists and tables stay literal text. Tool output and diffs have no Copy. Links stay as Foundation draws them. No syntax colouring.
  - **Verification.** `MarkdownBlocksTests` (nine cases: language, exact text with Unicode and trailing spaces, tildes, nested fences, Windows line endings, every prefix), `CodeFenceViewTests` (a 1,000-character line does not widen a 420 pt reply; a reply with no fence measures as before; Copy arriving does not move the code), captures `docs/screenshots/transcript-code-reply-before.png` and `-after.png`. In the harness app (`ReadingSmokeTests`) Copy put exactly the block's text on the pasteboard and read "Copied". Not checked: the phone, VoiceOver, Dynamic Type at accessibility sizes.
