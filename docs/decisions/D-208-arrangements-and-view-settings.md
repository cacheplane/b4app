## 2026-11-11 (arrangements and view settings)

- **D-208 The thread list has two arrangements and three view settings, stored per account and synced (amends D-048, D-053; extends D-204).** D-048 put a Pinned group and attention bands in the sidebar's sections, and D-053 made the sections the environments. The list is now drawn by one of two arrangements, "Needs you first" (the default) or "By environment", and three settings (the arrangement, how the threads that do not need you are drawn, and whether archived threads show) live in one synced row, so every device of an account shows the same list. Design: `docs/superpowers/specs/2026-11-10-thread-list-and-environments-design.md`. The code is commits d1d4dcd (hub), 08569c6 and 1e8366d (coordinator), 4f92eee (phone), 953ea60 and d91b9fb (model and menu), 082dd4e (Needs you first) and d4c4b62 (By environment); the review's fix wave is f60422e (view settings from another Mac, two hub tests) and 46c6041 (the stowed rows); the owner's changes of 2026-11-11 are 6c0b71d.
  - **One row.** Table `viewSettings`, key `id`, the id always the literal `view`; columns `id`, `arrangement`, `quietThreads`, `showArchived`, `updatedAt`. Hub migration `0019_view_settings.sql`, coordinator migration `0013_view_settings.sql` (which adds a `viewSettings` case to the change-log trigger function), and phone mirror schema version 8. `ViewSettings` is in `WorkspaceProtocol`.
  - **Values and defaults.** `arrangement`: `needsYouFirst` or `byEnvironment`. `quietThreads`: `small`, `tiny`, `collapsed` or `hidden`. `showArchived`: a boolean. A missing row, a null column, or a value this build does not know reads as the default (`needsYouFirst`, `small`, false). An unknown value stays in the row untouched; the hub stores whatever text arrives and never checks it, so a newer device's value survives an older one.
  - **Who writes.** Any device. The phone may insert the row (as it may insert a draft) and write the four columns `arrangement`, `quietThreads`, `showArchived` and `updatedAt`; all four merge by column clock. Nobody deletes the row. The hub's `PHONE_WRITABLE` and `CLOCKED` lists and Swift's `SyncColumns` carry the same columns.
  - **The one table a Mac takes from a Mac.** A Mac's remote apply skips every change made by any `macos` device of the user, by attribution or by clock (D-049: the Mac is the source of truth for its threads and environments, so their copies coming back are its own history). `viewSettings` is the one exception, on the feed and the snapshot path alike: its source of truth is the hub, not a Mac, so a second, new or reinstalled Mac must take the settings another Mac wrote, or it would show the defaults for good and two Macs would diverge. The merge is by column clock, so this Mac's own write coming back is a no-op and an older write loses; remote apply still never records what it applies in this Mac's change log. With that, every device of the account shows the same settings.
  - **Per-column inserts (a ruling).** A first insert of the row carries, and clocks, only the columns it sets, on the Mac (migration 0013's trigger, for `viewSettings` only) and on the phone (`partialInsertTables`); a pulled insert never applies a null. This is what lets two devices' different offline choices both survive: one device's first write of `quietThreads` does not overwrite, with a null, another device's `arrangement`. A pulled update to null is still an update.
  - **Fixture and suites together.** `Tests/Fixtures/sync/changes.json` gained two entries (an insert of `view` and an update of `quietThreads`) in Task 1, together with the hub's suite and the Swift suites that decode it; the Swift side needed only test changes then, since the decoders read the table generically.
  - **One row per org on the hub (a known limit).** The hub keys synced rows by `(org_id, key)` and applies an upsert only for the row's own user, so in an org with several users only the first user's `view` row is stored and the other users' devices do not sync these settings with each other. Every account today is a single-user org, so nothing is lost now. Lifting it needs a per-user key: either a row id derived from the user (`view:<userId>`, with the Swift and Rust rules that accept only `view` changed to match, and the fixture and both suites changed together) or a user column in the key, plus a migration that moves the existing row. It is not done here.
  - **Fallbacks.** `ViewSettings.shown(on:)` is the whole table: Tiny shows as Collapsed on a device that relays through the hub (the phone and the iPad); everything else shows as stored. A device that falls back never writes the shown value back; the row keeps `tiny`. The phone's menu lists Tiny with the note "Shown collapsed on this device".
  - **Needs you first.** The top list is the states approve, reply, failed and finished, newest first inside each state; a 24 pt gap; then the lower list, working then quiet, newest first. A pinned thread sorts first within its own state; there is no Pinned group. The Mac has no environment headings in this arrangement.
  - **Threads that do not need you.** Small is plan 3's row. Tiny (Mac) is a 20 pt row with 11 pt type and an 8 pt mark. Collapsed is one row, "9 more, 2 working" (the count of stowed threads, with ", N working" and the orbit mark only while something runs); activating it opens the lower list in place, and it closes when the pointer leaves the sidebar on the Mac or on a second tap on the phone. Hidden shows nothing below the top list (and no gap) except, while agents run, one muted row above the profile footer, "2 working" with the orbit; activating it shows those working threads as the list's last rows (on the Mac inside the scrolling list, after a 24 pt gap when something is above them, the row staying pinned). Collapsed and Hidden stow working threads too. The opened state is per window and never stored; besides the pointer leaving the sidebar or a second tap, it closes when the arrangement or the mode changes or nothing is left to stow (`ListLayout.stowing`, `keepsStowedOpen`), so the row never comes back already open.
  - **By environment.** One heading per environment that has live threads, then its threads in state order; "No folder" last. Groups sort by name (case-insensitive, then id) and the order does not change with thread states. A collapsed group shows its most urgent thread's mark at the trailing edge. The quiet-threads setting does not apply and the menu shows it disabled. An environment with no live threads has no group.
  - **Headings.** 28 pt rows on the Mac (44 pt on the phone), the name at 12 pt Medium, muted, starting where a row's title starts. On the Mac, hovering turns the name ink and shows a collapse chevron and a new-thread button, which opens the composer with that environment (or "No folder") preselected. On the phone a tap collapses or expands and a long press offers "New thread here". Which groups are collapsed stays per device (`collapsedEnvironments`), as does what the composer remembers.
  - **Archived.** With Show archived on, archived threads are a final block after a 24 pt gap in both arrangements, newest first, with no heading. "No threads yet." is printed only when there is no live thread and no archived row is drawn, on both platforms.
  - **The menu.** View options, top to bottom: Arrange, Threads that don't need you, Show archived, Connections. The environment filter (`EnvironmentFilter`) and the per-device storage of the three settings are deleted, not kept beside the new ones.
  - **Optimistic writes.** The model shows the new value at once and sends `viewSettings.set` carrying only that field. A refused write puts the old value back for that field only if it still holds what the write set, and shows the sidebar's existing error line. A set's answer applies only its own field, and a read that was overtaken by a newer value is dropped, so a late answer never undoes a newer choice from this or another device.
  - **Deviations and rulings.** The phone keeps "New Environment…" and an "Edit Environment" submenu at the foot of its menu until the environment-form plan. The Mac heading keeps its Rename, Add Folder and Delete context menu, and the Mac's view options gained an interim "Environments" submenu with the same actions (below), so under either arrangement, and for an environment with no live threads, every environment can be renamed, given a folder, or (a manual one) deleted on the Mac.
  - **The owner's changes (2026-11-11, rulings).** The owner looked at the running app and changed four things the design had settled, and fixed two defects:
    - *Rows have a 1 pt gap.* The design said rows touch; the owner changed it after seeing the app. Every list the sidebar draws on the Mac (the top list, the lower list, the opened stowed rows, the rows of a group, the archived block, Hidden's opened rows) has `LLA.Metrics.rowGap` (1 pt) of space, not a drawn line, between consecutive rows; a section gap (24 pt, 8 pt, or none after a heading) replaces it above a list's first row, never adds to it. Row heights (28 pt, 20 pt tiny) are unchanged. The phone's rows, which touched too, get the same 1 pt as padding above each row outside its button, so its 44 pt button height is unchanged.
    - *The selected thread holds its place until the selection moves.* The design said a thread leaves the top list the moment it is read. Now the list orders the selected thread by `min(its state now, the most urgent state it has had since it was selected)`, so a finished thread read on opening stays in its slot, and a held thread that needs the owner again moves up. The hold lives in the model (`WorkspaceModel.selectionHold`, restarted whenever `selectedThreadId` changes, so opening another thread, the new-thread composer, deleting the selected thread, and sign-out all release it; an archived selected thread has none) and reaches `ListLayout.build` as data (`ListLayout.Selection`), so the layout stays a pure function. It changes the order and top-list membership only, in both arrangements and on both platforms: the mark and the title, `Attention.state(of:)`, the badge, the widget, and the arrival tracker keep the real state. Releasing a hold changes no thread's state, so it is not traced as an arrival, nor is any row that shifts with it. The hold lasts only while the thread's detail is on screen, so on the phone it ends when you go back to the list (`WorkspaceModel.isDetailColumnShown`), and opening the thread again starts a fresh hold from its state then; on the Mac and a regular width the detail column always shows, and a window that loses focus keeps the hold. An approval arriving on a held thread still traces as an arrival, because arrivals follow real states. A collapsed group's mark is its most urgent real state, no longer its first thread's.
    - *The selected thread is never stowed.* Under "Needs you first" with Collapsed or Hidden, a selected thread that would be stowed is drawn as an ordinary row where the lower list starts (after the 24 pt gap when the top list is not empty), above the Collapsed row; it is counted in neither "N more" nor "N working", is not repeated among the opened stowed rows, and with nothing else stowed the Collapsed row is absent. Small and Tiny are unchanged.
    - *The Mac's interim "Environments" submenu.* Last in the Mac's view options, after Connections and a divider: every environment by display name (ignoring case, then id), threads or not, each a submenu of "Rename…", "Add Folder…" and, for a manual environment as on the heading, "Delete Environment…". It and the heading's context menu share one set of items and one presenter on the sidebar (`EnvironmentActionItems`, `EnvironmentActionPresenter`, through `WorkspaceModel.environmentAction`); the heading's item now reads "Delete Environment…" too. It is absent without environments; the phone's menu is unchanged. It is a home until the environment-form plan.
    - *Defects.* The Mac's view-options button read "Filter" to VoiceOver once a thread was open: its label sat on a wrapper outside the menu's own label, and the symbol `line.3.horizontal.decrease` (and its filled face) describes itself as "filter". The label is now `TopBarButton.accessibilityLabel`, "View options", set on the symbol and the menu. Pressing Hidden's "N working" now scrolls the first opened working row into view (animated unless Reduce Motion is on); closing scrolls nothing.
  - **A D-205 control relaxed.** On the merged tree the first hub run failed 6 of the 11 tests in `Hub/crates/b4hub-db/tests/environment_history_controls.rs` at "one complete legitimate ledger through eighteen": those controls required the migration ledger to end at 18, and this branch adds `0019`. Commit 1c0fb65 changed only that file's `complete_ledger`, so the ledger must run from 1 with no gaps and reach at least 18, with no extra or failed rows; the check on version 18 itself is unchanged. This relaxes a D-205 control so later migrations can exist; it does not amend D-205's decision.
  - **Compatibility.** The hub (migration 0019) and both apps must be on this version for the settings to sync. An older hub records and skips `viewSettings` changes (it counts them skipped and still covers them with `acceptedThrough`); an older app ignores the table.
  - **Follow-ups (not fixed here).** A dropped settings read is not retried: only a set that changes nothing, made during the first-connect read, leaves the other fields on their defaults until the next snapshot; settings load after threads, so the list can draw once with defaults on connect. Deferred minors: the hub accepts any `viewSettings` row id (a phone update of `id` is accepted and recorded but never renames the row); `ViewSettingsSet.Params` decodes enums strictly (a newer client's unknown value is a decode error); restoring an archive with no `viewSettings` onto a store without a connection deletes the local view settings; a pulled update that creates the row and then fails a constraint leaves a bare row and reports skipped; the phone does not bump `updatedAt` on an equal-value set (the Mac does); the tiny-metrics test only re-reads constants; `SidebarView` reads `listLayout` twice per pass; the collapsed group's accessibility value says "collapsed, Quiet"; hovering a collapsed heading hides its mark even when new thread is disabled; the snapshot test asserts titles only.
  - **Main's store-history tests updated for migration 13.** Merging main on 2026-11-11 (D-206, the store's environment-history preservation) brought `EnvironmentHistoryGuardTests`, four of whose assertions took `0012_app_folders` to be the last store migration. They now count 13 files, name `0013_view_settings` last, take 0012 by name, and expect all three pending migrations from a database stopped before 0011. No guard code changed.
