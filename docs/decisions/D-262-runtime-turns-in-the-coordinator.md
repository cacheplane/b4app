## 2026-11-19 (runtime turns in the coordinator)

- **D-262 The coordinator makes a row for a turn the runtime starts, keeps each turn's open work, closes open work that cannot end, and stops it; a thread holds one unfinished turn (amends D-259).** Design: `docs/superpowers/specs/2026-11-19-runtime-turns-and-open-work-design.md`. Plan: `docs/superpowers/plans/2026-11-20-runtime-turns-coordinator.md`. This is the second part, on `blove/runtime-turns-coordinator`: the coordinator's side. No adapter emits the new events yet, so nothing here changes what the running app does until the Claude Code and Codex changes land.
  - **A runtime turn row.** A `turn.acknowledged` event whose payload `origin` is `runtime` and whose native turn id no row of the thread has makes a turn row, when the thread has no unfinished turn: status running, submission acknowledged, `origin` `runtime`, and `operationId` `runtime:<thread id>:<nativeTurnId>`. The operation id is scoped to the thread because that column is unique across all threads and some runtimes number their turns per thread. A repeated acknowledgement of the same native id makes no second row. The runtime's `turn.finished` may carry its own word for the origin (`task-notification` for Claude Code), and for a turn that has an origin it replaces the stored one.
  - **One unfinished turn per thread (settles D-259's open point).** D-259 left open that its rules read the latest turn by `createdAt`, which is wrong if an owner's turn and a later runtime turn are unfinished together. Three more recordings (`send-meets-wake.jsonl`, `task-ends-during-turn.jsonl` and `second-turn-start.jsonl`, in the test fixtures and described in `docs/verification/2026-11-19-live-sub-agent-recordings.md`) show that neither runtime overlaps turns. The one case that would give two unfinished rows, a message sent as Claude Code wakes itself, is to be folded into one turn in the Claude adapter (a later change). So the rules that read the latest turn stand. When an acknowledgement with origin `runtime` arrives while the thread has an unfinished turn, no row is made, the event is logged and names no turn, and its native id is remembered for that thread so its later turn-state events never fall back to the owner's turn. The memory is dropped when an event that does not name a known turn arrives while the thread has no active turn.
  - **The lookup (`resolveTurn`).** A turn-state event (`turn.acknowledged`, `turn.state_changed`, `turn.finished`) that names a native turn id the store does not know applies to the active turn only when that turn has no native id yet and the id was not refused a row. Otherwise it is logged and joins no turn, so a stray finish ends no turn. Item events, request events and events naming no turn keep the fallback to the active turn: dropping them would lose drawn text or a runtime request, and a request that is lost cannot be answered.
  - **A turn's open work.** `recountOpenWork` sets a turn's `openWork` to the number of its display items whose payload has `agent` true and `status` `inProgress`. It runs when a `tool.started` or `tool.completed` item is stored with `agent` true, or for a turn whose count is above zero, counts from the stored items every time so it cannot drift, writes only when the number changes, and publishes `turn.state_changed` after the item's own event so a client sees the agent before the count. The write moves the turn's `updatedAt`, on purpose. The store replaces an item's payload, so an adapter must put `agent: true` on the completion as well as on the start; an agent seen only at its end counts nothing.
  - **Closing open work that cannot end.** `closeOpenWork` marks each open agent `stopped` with an `endedAt`, announces it with `tool.completed`, and recounts. It runs when an adapter reports one thread's exit or a connection's exit (a connection's exit closes each thread of that connection that has open work), and at coordinator start-up for agents left behind by a process that did not survive. Start-up takes its list synchronously, before any session can start, and closes only those agents, so one opened later is not touched. Each agent is read again immediately before it is written, with no suspension between, so an agent that really completed is never overwritten. One thread's failure is logged and recorded, and stops no other thread's close in the start-up loop. An adapter restarting a session on its own is the adapter's to report as an exit (a later change); the coordinator cannot see it.
  - **Stop.** `AgentAdapter.stopOpenWork(_:)` asks the adapter to stop every background agent of a session; the agents' ends arrive as ordinary item events. Its default throws `unsupportedCapability` naming the later changes, so an adapter never reports a stop that did not happen. `turn.interrupt` interrupts the active turn if there is one, publishing its update, and then stops open work if the thread has any; with neither it refuses as before. Quit (`stopLocalWork`) and log-out (`interruptLocalTurns`) take their entries from the unresolved turns and call `turn.interrupt` only for a local turn that is running, waiting for the user or stopping, ignoring its errors; so they ask the adapter to stop open work only for a thread that also has such a turn. A thread with open work and no unresolved turn is not reached by either. Until the Claude Code and Codex changes implement `stopOpenWork`, Stop on a thread with open work interrupts the turn and then returns the unsupported error; no thread can have open work before those changes.
  - **The shared UI model.** A terminal turn event clears a thread's recorded running turn, and its Stop state, only when it is that same turn or no turn is recorded. A `turn.finished` ends the open thread's live text only when it leaves no turn running there. Without this, a runtime turn ending, or the open-work update of an earlier turn, would clear a running owner's turn.
  - **Fixes after the whole-change review.** Start-up recounts every turn whose `openWork` is above zero, not only those with an agent item in progress: each thread such a turn belongs to is handed to the start-up close, whose trailing recount brings a count with no open agent back to 0. A count could be left that way if the coordinator died between an item's write and its recount, or if a close stopped the item and failed before its recount. A `tool.started` or `tool.completed` item event also recounts its stored turn when that turn's `openWork` is above zero, even if the payload has no `agent` flag, so a completion that leaves the flag out still closes the count. The count is still written only when the number changes.
  - **Stop, as now built.** `turn.interrupt` reads whether the thread has open work again after the adapter's `interrupt` returns, and calls `stopOpenWork` from that reading, not from the one taken before the interrupt. When the interrupt throws and the thread has open work, `stopOpenWork` is still called and the interrupt's error is the one thrown; with no open work the interrupt's error is thrown at once, as before. When the interrupt succeeds, the active turn's update is stored and published before any error is thrown. `AgentAdapter.stopOpenWork` must be safe to call when nothing is open and right after `interrupt`.
  - **Deleting a thread.** When a deleted thread has a turn with open work, deletion calls the adapter's `stopOpenWork` for the thread's session before it deals with the active turn, whether or not there is one. An `unsupportedCapability` error is ignored and any other error is logged. What deletion does about an active turn is unchanged.
  - **A send while agents work.** The design refuses a send that would restart Claude Code while its agents work (reason `open_work`). `turnSend` has no place for that refusal yet: it inserts the turn row and the user item before it calls the adapter, so an adapter that throws leaves a failed turn, not a refusal. The plan for the Claude adapter change decides between a question put to the adapter before the row is made and a refusal that `turnSend` unwinds.
  - **Quit.** `activeWork()` lists unresolved turns only, so the quit warning does not count open work. `shutdown()` cancels the event pumps before the adapters are disposed, so the agents are ended by their process ending and no exit event closes them. The hub keeps the count until the next coordinator start, when start-up closes them, and an unread latest reply is then announced, as D-259 has it. The transcript and composer change owns the quit warning and what quit does to agents.
  - **A runtime turn across a restart.** A runtime turn left running when the coordinator stops goes to reconciling at the next start like any other turn, and for Claude Code to failed on its first read. The owner then sees "Turn failed." with no message above it.
  - **What an adapter owes the coordinator,** beyond the flags already recorded: agent items arrive as `tool.started` and `tool.completed`, and only those two kinds recount; an agent left in progress by a turn that was interrupted or failed must be closed by the adapter; a background agent's permission request must be resolved by the adapter when the agent ends or is stopped, since otherwise only a session exit expires it; and `stopOpenWork` must be safe with nothing open.
  - **Known gaps, deferred.** A remembered refused id is dropped only when an event that does not name a known turn arrives while the thread has no active turn. `openWork > 0` has no index. In the connection-exit loop, one thread's failed read still skips the threads after it (logged). An active turn with no native id plus open work refuses before the open work is stopped (intended, untested). Two test wrappers duplicate about 25 lines. The Mac-model test iteration that could pass vacuously now waits on a turn of its own.
  - **To bound before an adapter emits agent items.** While a turn has open work, every tool event on that turn recounts it, and a recount reads all of the thread's display items. An agent's own steps carry that turn's id, so a long agent run would read the thread once per step. The Claude Code adapter change bounds this first: a count in SQL, or a recount only when the stored row was an open agent. `ThreadDeleteService` asks for open work to stop before it interrupts the turn, the reverse of Stop's order; `stopOpenWork` must be safe at any time.
