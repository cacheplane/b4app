## 2026-11-02 (M8f, attention on the phone)

- **D-128 The fetch background mode, in the Debug configuration, for the Simulator's background push.** `xcrun simctl push` delivers a `content-available` payload by launching the app for a background fetch, and SpringBoard refused that launch ("this app doesn't declare the proper UIBackgroundMode") while the app declared only `remote-notification`. The Debug configuration (the local flavour) also declares `fetch`, and `performFetchWithCompletionHandler` runs the same refresh; the iOS target's post-build script removes it, with the localhost ATS exception, from every other configuration, Debug-Beta included, because on a device APNs wakes the app through `remote-notification` and an unused background mode only invites review questions. Found in the live gate. iOS does not schedule fetches of its own without a minimum interval, which the app does not set; asking for periodic refreshes would be a `BGAppRefreshTask`.
