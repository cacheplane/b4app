## 2026-10-31 (M8a)

- **D-043 The hub is a Rust service in `Hub/`, one shared schema with `org_id` on every tenant table and row-level security enforced by the database.** The Cargo workspace is `b4hub-core` (pure types and rules), `b4hub-db` (sqlx), and `b4hub` (axum binary with `serve`, `migrate`, `seed`, `enroll`), edition 2021 on Rust 1.93.1, exact `=` pins, `Cargo.lock` committed, builds and tests run `--locked`, `unsafe_code` forbidden. It follows the conventions of the b4 Rust rewrite (`~/repos/b4`): B4's error envelope (`error.kind`, `error.message`, `error.details.code`; public errors never carry SQL, panics, or another tenant's data), authentication before the body is read, `deny_unknown_fields` on inbound bodies, a non-root container (uid 10001) with a `HEALTHCHECK` on `/readyz`, and a bounded drain on SIGTERM (`/readyz` fails first, new work is refused, long-polls finish, exit within `B4HUB_SHUTDOWN_WAIT_MS`, default 30000); configuration errors exit 2. Tenancy: RLS is enabled and forced on every tenant table with the policy `org_id = NULLIF(current_setting('b4hub.org_id', true), '')::uuid`, and each request transaction begins with `SELECT set_config('b4hub.org_id', $1, true)` using the org from the verified credential. The application role `b4hub_app` is provisioned by `migrate` from the password in `DATABASE_URL` (printable ASCII; the server receives only a client-computed SCRAM-SHA-256 verifier), is `NOSUPERUSER NOBYPASSRLS`, and does not own the tables, so there are two URLs: `DATABASE_ADMIN_URL` (owner; `migrate`, `seed`, `enroll`) and `DATABASE_URL` (`b4hub_app`; `serve` only). **Three tables carry no RLS.** `orgs` is the tenant directory. `device_tokens` and `enrollment_codes` are looked up by the hash of a secret the caller presents, before any org is known, so a tenant policy cannot apply; they hold only hashes, ids, and expiry, never synced content, and everything they lead to is then read under the org they name. The change log has `(org_id, device_id, device_seq)` unique for idempotent pushes and a per-org `hub_seq` bigserial as the reader's cursor; a per-org advisory lock keeps commit order equal to sequence order so a reader never skips a row that commits late. The six synced tables are materialised with the Mac's quoted camelCase columns plus `org_id`, `user_id`, `device_id`, keyed `(org_id, id)` with the client's text ids; hub-minted ids are UUIDv7. Every read and write is scoped to the token's `user_id`, and a missing resource and an inaccessible one answer the same generic 404. Limits: 2 MiB per change value (`MAX_PAYLOAD_BYTES`), 32 MiB per push body, 1000 changes per push, 1000 per pull page, and a long-poll `wait` capped at 25 s whose waiter is registered before the final emptiness check, so a push between the check and the wait is not missed. The retention horizon is 0 because M8a never prunes; `resync_required` (410) is answered only for a negative cursor until pruning exists. *Amended by D-049/D-050 (2026-11-01): a value over 2 MiB is rejected per change (`payload_too_large`) and no longer 413s the push (only a body over 32 MiB does); a pull page also stops at 8 MiB of stored value sizes; the hub prunes every 24 hours (`B4HUB_RETENTION_DAYS`, default 30), so the horizon moves and `resync_required` is answered for any cursor below it, restored from `GET /v1/snapshot`.*
