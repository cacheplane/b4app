## 2026-10-31 (M6)

- **D-039 Signing is ad hoc until a Developer ID certificate exists on the build Mac; the package script takes `B4APP_SIGN_IDENTITY` and then adds the hardened runtime and a timestamp.** No signing identity is installed on the target Mac (`security find-identity -v -p codesigning`: 0), so notarisation and Gatekeeper-clean distribution stay open; the ad hoc build runs where it was built. Helpers are signed before the bundle and `--deep` is never used. The Keychain stays file-based (D-008) for the same reason. **Amended 2026-10-31 (Developer ID):** the owner enrolled in the Apple Developer Program, and the build Mac now holds one identity of the form `Developer ID Application: <name> (<team id>)` in the login keychain, plus a notarytool keychain profile named `b4app` that the owner created themself with `xcrun notarytool store-credentials`, so no Apple ID or app-specific password passes through the script. When `B4APP_SIGN_IDENTITY` matches a Developer ID Application line in `security find-identity -v -p codesigning` (by name or SHA-1), `Scripts/package.sh` checks the notary profile before building; signs every Mach-O under `Contents/SharedSupport/postgres`, then both helpers, then the bundle (with `B4App.entitlements` again, since re-signing drops what Xcode embedded), all with `--options runtime --timestamp`; checks `codesign --verify --deep --strict` and that the signed `TeamIdentifier` is the certificate's; zips with `ditto -c -k --keepParent`; runs `xcrun notarytool submit --keychain-profile "${B4APP_NOTARY_PROFILE:-b4app}" --wait`, printing `notarytool log` and failing on any status but Accepted; staples and validates; re-zips the stapled app; and fails unless `spctl -a -vv --type exec` reports `source=Notarized Developer ID`. `B4APP_SKIP_NOTARIZE=1` signs without submitting; any other identity keeps the old behaviour (hardened runtime, no notarization), and no identity keeps the ad hoc path unchanged. The team id is read from the certificate at package time, so `project.yml` keeps `DEVELOPMENT_TEAM` empty and Xcode still builds ad hoc before the re-sign. **No entitlements were added**, and `B4App.entitlements` stays an empty dictionary: the first submission was accepted and the first launch ran clean under the hardened runtime. The coordinator `dlopen`s `libpq.5.dylib`, and the server loads `plpgsql.dylib` and `dict_snowball.dylib`; library validation lets each of those load because it is signed by the same team. The PostgreSQL binaries find their libraries through `LC_RPATH @loader_path/../lib`, not `DYLD_LIBRARY_PATH` (which the hardened runtime strips), and nothing JITs or maps writable code. So `com.apple.security.cs.disable-library-validation`, `allow-dyld-environment-variables`, `allow-jit`, and `allow-unsigned-executable-memory` are all unneeded. With a team-signed coordinator the `SMAppService` agent's code requirement survives a rebuild (`docs/verification.md`), but the per-user plist of D-042 stays until the owner asks to switch. D-008's file-based Keychain is unchanged by this amendment.
