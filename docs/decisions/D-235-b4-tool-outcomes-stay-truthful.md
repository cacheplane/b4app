## 2026-11-14 (B4 tool outcomes, live, in history and on the card)

- **D-235 A B4 tool call is failed only when its result says so, history keeps what the checkpoint recorded for each call, and an opened tool card shows the call's input, output, exit code and changes in place of a dump (amends D-230).** Three places gave a call an outcome it did not have. The code is commit b958a6cb.
  - **Live.** `B4TurnTranslator.toolFailed` read a bare result as failed when it had an `error` key at all, so `{"error": null}` was a failure. It is failed when `error` holds something. For a `ToolMessage` the rule is `B4Protocol.toolMessageFailed`: LangChain's `status` is `error`, or B4's own step (`additional_kwargs.b4_step.status`, D-230) is `failed`. `false`, `0`, an empty string and an empty list are results.
  - **History.** `B4Protocol.snapshotItems` stored every call `completed` unless its step was `denied`. A call whose `ToolMessage` failed is now `failed`, by the same rule as live. A call with no `ToolMessage` is `inProgress` with no output: nothing recorded says it finished, and D-234 draws it "Unfinished" unless the turn it stands in is running.
  - **The card.** `ToolEvidence.detail(of:)` reads a tool item's payload without SwiftUI: the directory, the input (`input` or `arguments`; text as it is, anything else as JSON with sorted keys), the output, the exit code and the changes. The output is one of three things: none recorded, recorded with no text ("No text output."), or the text, with a non-text value such as `false` drawn as JSON. Only an item with none of these falls back to its payload, as sorted JSON cut at 2,000 characters, and the card says when it was cut. Before, the fallback was drawn whenever the item had no `aggregatedOutput` and no `changes`, which is every B4 and Claude Code call and every command that has not printed yet.
  - **Why not the words.** As in D-227 and D-230: the result's text is not read to decide an outcome.
  - **Not covered.** Claude Code stores an image-only result as an empty string, so its card says "No text output." for it. Claude Code's history still has no `declined`. A tool's input is drawn whole; a large `Write` is as long as its file.
  - **Verification.** `B4TranslatorTests.aNullErrorAndFalsyResultsAreNotFailures` and `historyKeepsAFailedCallFailedAndACallWithNoResultOpen` fail on the baseline (five expectations) and pass here; `ToolEvidenceTests` (six cases); `TranscriptCorpusTests` reserved case R2. Not checked: a real B4 server sending a failed tool result (the fake never does), and the opened card on screen.
