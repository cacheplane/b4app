## 2026-11-04 (phone project edits)

- **D-180 The phone creates projects, changes their folders, and deletes them by relayed commands to the Mac whose folders they are; a rename alone stays a phone-writable column. Amends D-048, D-049, and D-057.**
  - **Shape.** `project.create`, `project.update`, and `project.delete` join the relay's allowlist on the hub (`b4hub-core::relay::RelayMethod`) and the Mac (`RelayMethod` in `WorkspaceSync`, `RelayExecutor`), which runs them through the same `ProjectService` calls as the Mac's own sheets. Phone-writable rows applied by `applyRemote` were rejected: a folder is a path on one Mac and only that Mac can say whether it exists, a project edit moves `threads.projectId` and `connections.projectId` and deletes emptied automatic projects in one transaction there, and a row queued offline that the Mac later refuses would have no way to tell the phone why. A rename needs none of that, so `projects.name` stays in the phone-writable list (D-049) and works with the Mac offline. The phone's Edit sheet sends a name-only change as `project.rename` through the outbox, and any folder change as one `project.update` that carries the name too.
  - **Routing.** `project.update` and `project.delete` route by `params.projectId` to the project's owner, like `thread.start`. A new project has no row, so `project.create` carries `params.deviceId`, the Mac the phone chose (the only one, or a picker when the user has several), and the hub routes to that device after the usual check that it is a non-revoked `macos` device of the caller's own user; a missing or malformed `deviceId`, another user's Mac, or the user's phone is `not_found`. The Mac ignores `deviceId`. The project edits count toward the per-device limit only (not the per-user send limit), wait 15 s for the Mac's reply on the hub and 30 s on the phone, and are refused while the hub is in maintenance.
  - **Offline.** Never held and never queued, like a send (D-045): an offline Mac is `device_offline` at once, which the sheet words as "<Mac> is offline · last seen <time>". While the phone already knows the Mac is offline or has left the hub, Create, a folder change, and Delete are off with that notice as the reason; the name field still saves.
  - **Folders.** The phone never browses the Mac's filesystem (an M8b non-goal that stands). It names a folder by picking one the Mac already knows (the folders of that Mac's automatic projects, which a manual project may take over; a manual project's folder would be refused) or by typing a path, `~` meaning the Mac user's home. The Mac validates every folder exactly as for its own sheets (it must exist and be a directory, a folder of another manual project is refused, the whole edit is refused if one folder is bad) and its error text (for example "Folder /x does not exist.") is the phone's message. Paths already cross the wire under D-046.
  - **Idempotency.** `project.create` carries a lowercase-UUID `projectId` the phone mints once per sheet; a create whose id names an existing manual project returns it as it stands, so trying again after "Not confirmed" makes no second project (any other id form is `protocol_invalid`, reason `invalid_project_id`). Update and delete are not resent by the phone: a lost reply shows "Not confirmed", and the synced rows show what happened.
  - **Owner on the phone.** The Mac returns projects without `ownerDeviceId`; the mirror's transport puts back the owner it holds, so an edited project stays routable. A new project has no owner on the phone until its row syncs, which is also when the hub can route to it, so until then its Edit sheet says "Your Mac made this project. It hasn't reached this phone yet."
  - **Where.** The filter menu on the iPhone gains "New Project…" and "Edit “<project>”…" (which replaces the rename alert); the sheet is `PhoneProjectSheet`, mounted by the root view from `WorkspaceModel.projectSheet`. Delete is in the sheet, for manual projects only (an automatic project cannot be deleted anywhere, and keeps its own folder).
  - **Amends.** D-048's and D-049's known limitation that projects and their folders are created and changed only on the Mac, and that the phone refuses `project.create`, `update`, and `delete` (a phone with no hub link still refuses them, naming pairing); D-057's method list, which is now eight.
