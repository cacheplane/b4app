## 2026-11-02 (deleting threads: the review's minors)

- **D-138 "Already gone" needs proof, and the delete mark is never cleared anywhere.** Amends D-119 and D-120 from the final review's deferred minors.
  - **Gone means gone.** Codex: an error counts as already gone only when its message says "not found"; an invalid params without it is thrown and retried (no longer any `-32602`). B4: a `404` from `DELETE /threads/:id` may come from a server without the route, so `GET /threads/:id` confirms it: `404` is already gone, `200` (the server still has it) is unsupported, anything else is retried. Claude Code: already gone only when the projects root lists and no project folder holds `<id>.jsonl`; a root that can't be read (or is missing) throws and is retried. Every project folder holding the transcript has it and its `<id>/` folder removed, as the Claude desktop app's `find … -exec rm` does; the id check and the parent-equals-root guard stay.
  - **Never cleared, enforced.** The hub refuses an update that sets `threads.userDeletedAt` to null from any device with a new per-change code, `cannot_clear` (`NEVER_CLEARED` in `b4hub-core/src/writable.rs`); an insert's null for it is not carried, so it cannot clear a set mark either. The Mac's `applyRemote` skips a pulled null for it (`SyncColumns.neverCleared`) without taking its clock.
  - **The confirmation.** The runtime is not named when the connection is now signed in as another identity (`ConversationThread.identityChanged(on:)`, shared by the alert and the sweep), as for a disabled connection.
