## 2026-11-06 (bounded documentation recording)

- **D-189 Documentation recording is an explicit, bounded client operation with private intermediate output.** The `agent-workspace docs-record` command records app-observed events from one initially empty B4 conversation through `WorkspaceClient`. It adds no coordinator method, database schema, or UI filesystem access.
  - **Observation fidelity.** Subscribe before setup reads, check global stream continuity before filtering, enforce time/event/byte limits, and finish only after a replay barrier and settled-thread audit. Missing observations or a desynchronized stream fail the recording rather than being reconstructed from a snapshot. Runtime decisions absent from the protocol remain unavailable.
  - **Privacy boundary.** Output retains an allowlist of observation fields. Credential-shaped fields and home paths are masked; a secret split across streamed chunks aborts without output. The destination must be outside public and Git directories, and output uses owner-only permissions and an atomic no-overwrite operation. Sanitization is defense in depth, not permission to record personal conversations or publish without review.
  - **Publication ownership.** The website separately normalizes, validates and reviews the private capture before admitting immutable public assets. App binary identity, recorder revision and runtime/example revisions are recorded independently. A beta recording is not production-release qualification.
  - **Evidence.** `docs/verification/2026-11-06-docs-recording.md` records fixture and live qualification separately. The admitted aircraft lookup contains two completed turns; approval and cancellation remain fixture-only coverage.
