## 2026-11-02 (sign-in build)

- **D-113 (Resolved by D-150, 2026-11-02: the step-up below is built.) Destructive account changes need only a device token for now; a fresh-assertion step-up is planned.** `POST /v1/me/passkeys/begin|finish`, `DELETE /v1/me/identities/{id}`, and `DELETE /v1/me` (`Hub/crates/b4hub/src/routes/me.rs`) accept any valid device token, as every other `/v1/me` route does. The risk, accepted until the step-up lands: anyone holding a stolen token (from a Mac's keychain, a phone's, or a log line that should never have had it) can add a passkey of their own, then remove the owner's passkeys and Apple ID (`last_identity` still passes, since the thief's passkey remains), and so take the account over, or delete it outright with its synced data. D-098 accepted the add-passkey case alone; this extends the acceptance to removal and deletion. The planned fix: each of these routes requires a recent assertion (a passkey or Apple sign-in finished within a few minutes) bound to a ceremony of the same user, sent with the request. Until then the defences are that tokens are kept only in the Keychain, never logged, and ended on log-out, and that a deleted device's token is `401` at once. Final review M3, 2026-11-02.
