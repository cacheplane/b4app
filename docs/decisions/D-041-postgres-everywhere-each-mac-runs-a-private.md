## 2026-10-31 (storage)

- **D-041 Postgres everywhere: each Mac runs a private Postgres cluster as the coordinator's store, and a remote Postgres is the multi-device hub; GRDB and SQLite leave the package.** The owner chose one engine and one migration toolchain end to end over the recommended SQLite-on-device design. The server binaries are pinned, fetched by checksum, and bundled under `Contents/Helpers/postgres`; the cluster lives in the data directory, listens only on a Unix socket in the runtime directory, and runs under a second LaunchAgent in the packaged app or as a coordinator-owned child elsewhere. One set of versioned SQL migrations serves the local cluster and the hub; a `pg_dump` precedes every local migration; the existing SQLite file is imported once. Amended the same day: the iOS companion keeps SQLite as its own local store and syncs through the same change log (offline-capable, a limited feature subset only if necessary); the hub is multi-tenant and multi-user, so synced rows carry a tenant and a user and devices authenticate as users. Settled while building M7: PostgreSQL 17.11 from the zonky embedded build, pinned by SHA-256, thinned to arm64 and pruned to 62 MB (`Scripts/fetch-postgres.sh`), shipped under `Contents/SharedSupport/postgres` because `Contents/Helpers` admits only nested code; the coordinator starts the cluster through `pg_ctl` and stops one it started, adopting one already running after the D-025 identity check, so there is no second LaunchAgent; the store speaks libpq bound at runtime with `dlopen`, synchronously, behind the unchanged `WorkspaceDatabase` API; the pinned build has no `pg_dump`, so backups and major-version moves are the store's own JSON-lines export and restore (`db backup|restore`); the pre-0.2 `workspace.sqlite` is imported once at first start in one transaction and retired as `.imported`; the change log is written by triggers (`0002_changes.sql`) with a session setting that silences them during replay and restore. Design: `docs/superpowers/specs/2026-10-31-storage-and-sync-design.md`.
