## 2026-11-02 (hosted hub deployment)

- **D-072 Self-hosting ships as a Compose production profile and a `b4hub` Helm chart with an external database, a pre-upgrade hook migration Job, and file-mounted secrets; both are built in this project.** The owner: "lay it out even if they come later, I want the docs", then "Built here." The chart uses no library chart (Bitnami's catalogue was paywalled in 2025), requires `database.existingSecret` with a CloudNativePG example, defaults to one replica with `strategy: Recreate` and Restricted Pod Security Standard settings, renders a controller-agnostic Ingress or a Gateway API `HTTPRoute`, and is published as an OCI artifact on GHCR signed with cosign. Compose keeps the migrate-then-serve split (`service_completed_successfully`), reads secrets through the hub's `*_FILE` variables, and offers Caddy for TLS as an optional profile. Both tell operators their proxy must append the client address, which is what `B4HUB_TRUST_X_FORWARDED_FOR=1` assumes and what the AWS load balancer does.

**Implementation notes (2026-11-02).** Building D-068 to D-072 changed a few things the design stated, with no new decision numbers. `*_FILE` secret reading already existed for the database URLs (D-072), so only the remaining variables needed it. Fargate has no tmpfs, so the read-only root filesystem gets a bind-mounted task volume for scratch space instead (D-068). In the admin task the `psql` container is the essential one and the `hub` container is not (D-068). The test deploy job declares no GitHub Environment, because the test infra role trusts `ref:refs/heads/main` and not `environment:test` (D-069, D-070). The GHCR image is copied into ECR by digest, and the digest is checked after the copy; there is no pull-through cache (D-070). The Compose database healthcheck uses TCP (`-h 127.0.0.1`) rather than the socket (D-072). The Helm migration Job uses `args`, and the evaluation Secret is a pre-install and pre-upgrade hook so the Job can mount it (D-072). The chart's install job prefers the image built from the pull request's head commit, then `main` (D-072). GitHub issues this repository's OIDC tokens with the immutable subject (`repo:<owner>@<owner id>/<name>@<repository id>:...`), so the bootstrap trust policies pin the owner and repository ids (`github_owner_id`, `github_repository_id`), which also makes them immune to a rename or transfer of the repository. The cacheplane Organization's root carries a customer-editable region-restriction SCP (`AdvancedModeRegionRestrictionSecurityControlPolicy`) that permits most services only in `us-east-2`; production's cross-region backup copy (D-071) needed `backup:*`, `backup-storage:*`, and `kms:*` added to its `us-west-2` exception list, done at the owner's direction on 2026-11-02, and `rds:*` on 2026-11-04 after the first scheduled copy failed on `rds:CopyDBSnapshot` in the destination region (the previous policy is kept at `~/.b4app/aws-org/`). SNS refuses a wildcard action in a topic policy, so the alerts topic's owner statement lists its actions (D-071). The admin task's `hub` container runs without a read-only root filesystem because ECS Exec's agent needs a writable one, and it needs `B4HUB_APPLE_AUDIENCES` whenever it carries the Apple secrets (D-068).
