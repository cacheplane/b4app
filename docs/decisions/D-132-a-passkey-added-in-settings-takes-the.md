## 2026-11-02 (sign-in polish from the live gate)

- **D-132 A passkey added in Settings takes the account's name in the password manager; the hub's identity name stays the placeholder.** `WorkspaceModel.addPasskey`, `addedPasskeyName` (`Sources/WorkspaceUI/SignIn/AccountSettingsView.swift`). Amends D-105, which renamed only the sign-up passkey. After the hub keeps a passkey added from Settings → Account, the app renames it through the same password-manager call as onboarding (`PasskeyCeremony.renamePasskey`, `reportPublicKeyCredentialUpdate`), to the account's display name (else the profile button's name), for the registration's relying party and user handle. A per-device name was considered and not used: the password manager renames by user handle, which every passkey of an account shares (`POST /v1/me/passkeys/begin` reuses the first one's), so a device name would rename them all. The hub has no route to rename an identity, so Settings → Account still lists an added passkey as "Passkey · Agent Workspace account · added …"; naming identities at the hub is left for later. A refused or cancelled add renames nothing.
