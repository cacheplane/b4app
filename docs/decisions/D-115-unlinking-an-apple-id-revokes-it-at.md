## 2026-11-02 (sign-in build)

- **D-115 Unlinking an Apple ID revokes it at Apple first; deleting an account or merging a phone ends its relay links at once.** `DELETE /v1/me/identities/{id}` (`accounts::remove_identity`, `Removal`) treats an Apple identity holding a sealed refresh token as `DELETE /v1/me` treats one (D-095): it is opened (the identity id is the associated data) and revoked through the hub's revoker before the row goes, inside the same user-locked check that refuses the last identity, which is decided before anything is revoked. A token that does not open, a failed revoke, or a hub without Apple (whose revoker refuses) removes nothing and fails with `500`, so it can be retried; a token replaced by a sign-in meanwhile is revoked too. Without this, unlink-then-delete left a live grant at Apple the hub could no longer revoke. After a deletion or a phone merge commits, the gone user's relay links on that instance close with 4001 (`Relay::close_user`, `Close::revoked()`), and the same transaction deletes the user's `user_links` claim, which has no foreign key (`delete_org`). A link of that user served by another instance still ends only at its next authenticated request or its 30 s silence. Final review I1 and M1, 2026-11-02.
