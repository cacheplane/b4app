## 2026-11-04 (new-thread composer)

- **D-182 The directory lock is removed.** Amends D-033 and departs from spec 10.1.5: Codex and Claude threads may run turns in one folder at the same time, on one connection or across connections. `SessionService.turnSend` no longer refuses with `protocol_invalid` / `directory_locked`, `assertCanStart` (the relay's pre-check for `thread.start`) keeps only the runtime-outage check, and `WorkspaceDatabase.activeHarnessTurns` and the "Open that thread" remediation that went with the refusal are gone. The per-thread rule stays: a thread with an unresolved turn answers `turn_active` until the turn ends, is stopped, or (when `reconciling`) is abandoned.
  - **Why.** The lock covered one thing, a second writable turn in the same canonical working directory. Every project folder is now attached to a thread (a turn hands the runtime the project's other folders as writable roots), so a thread can write to folders other than its own working directory, and a per-directory lock no longer covers what a thread can write. A lock that covers only part of that is a promise the app cannot keep. Neither the Claude app nor the Codex app has one. The owner decided on 2026-11-03 to drop it.
  - **What the user takes on.** Two agents may edit the same files; the app does not arbitrate. Git, and the agents' own file tools, are the safeguard.
  - **Left as they were.** `turn_active` still names the blocking turn as `details.turnId`, and the relay still moves it to `details.blockingTurnId` at its boundary. D-033's file and the spec are not edited.
