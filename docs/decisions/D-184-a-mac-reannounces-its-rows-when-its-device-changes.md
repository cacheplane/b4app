## 2026-11-05 (sync ownership)

- **D-184 A Mac re-announces its own rows when its hub device changes.** A row's owner, on the hub (`owner_device_id`) and in the phone's mirror (`ownerDeviceId`), is the device of its latest insert (D-048, M8c). A Mac whose device changed (a sign-in that got a new device after a revocation, for example) kept its rows owned by the old device, because nothing inserted them again; the phone, which offers a project only its own Mac's connections, then found none ("No ready connection on your Mac can start a thread in this project"), and per-project notices looked at the old device. Found at the new-thread composer's live gate (2026-11-04) and, for projects, at the phone-projects gate the same day.
  - `hubLink.ownedAs` (Mac migration `0010_owned_rows`) holds the device the Mac last announced its rows as. `HubSync.start` calls `WorkspaceDatabase.claimOwnedRows()`: when `ownedAs` is not the link's `deviceId` and something in the change log was already pushed, it appends an `insert` for every row of `connections`, `projects`, and `threads` as the current device and records it; the normal push carries them. With nothing pushed yet (a first join, a join after `hub leave`, a fresh account), it only records the device, since the coming upload is the whole log as this device. A link from before the migration (`ownedAs` null) re-announces once.
  - The inserts carry the oldest clock there is (`000000000000-0000-<device>`). The hub and the mirror merge an insert column by column: ownership and the Mac-only columns follow it, a clocked column keeps whatever a newer change set (a phone's rename, pin, or read marker stays). So a re-announce can move ownership but never undo a phone's edit.
  - Not changed: the phone's rule that a project offers only its own Mac's connections; how the hub routes relayed commands (by its own owner, which the re-announced inserts also move).
