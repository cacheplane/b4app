## 2026-11-19 (open work and origin)

- **D-259 A turn carries `openWork` and `origin`; open work keeps a thread working, and a reply notifies only when its thread is at rest (amends D-204 and D-121).** Design: `docs/superpowers/specs/2026-11-19-runtime-turns-and-open-work-design.md`. Plan: `docs/superpowers/plans/2026-11-19-open-work-fields-and-state.md`. The code is commits d61271c3, e9bed438, 44c93d07, 3f0791cf, 862e61df and a5a9807a. This is the first part: the fields and the rules that read them. Nothing writes either field yet, so every row reads as no open work and no origin, and no thread or notification changes until the coordinator change lands.
  - **The fields.** `Turn.openWork` (`WorkspaceProtocol`, `Domain.swift`) is how many agents the turn started are still running; absent or null on the wire reads as 0. `Turn.origin` is nil for a turn the owner sent and the runtime's word for a turn it started itself. `ThreadActivity.openWork` is the sum of `openWork` over the thread's turns, absent on the wire reads as 0, and is computed in the coordinator's activity query and the mirror's.
  - **Storage.** Coordinator migration `0016_turn_open_work.sql` adds `openWork integer NOT NULL DEFAULT 0` and `origin text` to `turns`; neither column is clocked, since only the Mac that owns the thread writes them, and the `0015` trigger function stands. Mirror schema 11 adds both columns, nullable, so a Mac from before them sends neither. Hub migration `0023_turn_open_work.sql` adds both columns, nullable, and both names are in the `turns` `TableSpec` (`change.rs`), so a push that carries them is stored and a push that lacks them is not refused.
  - **Thread state (amends D-204).** In `Attention.state(of:)` the rule `openWork > 0` gives `working`. It sits after the failed check and before finished: a thread whose latest turn failed is still failed, and a thread whose latest turn ended with agents still running is working instead of finished or quiet, read or not. Every earlier rule is unchanged, so a pending request, a turn waiting for the user and a turn that has not ended still win.
  - **The hub's band.** `BANDS` in `Hub/crates/b4hub-db/src/push.rs`, which computes the badge, gives `working` when the thread's live turns hold open work, unless the latest turn's outcome is `failed`; deleted turns do not count. This is the same rule in SQL, and `Tests/Fixtures/sync/attention.json` now holds four threads with open work (`t-open-work-unread`, `t-open-work-earlier`, `t-open-work-read`, `t-open-work-failed`) that the Swift rule, the mirror's query and the hub's SQL all agree on.
  - **When a turn notifies (amends D-121).** `turn_reason` takes a fourth argument, `at_rest`, true when the thread's summed open work over its live turns is zero. Three cases:
    - A failed, recent turn notifies ("Turn failed"), keyed by that turn, whether or not the thread has open work.
    - A reply ("Replied") notifies keyed by the thread's latest live turn, not the turn the push touched, when that turn is terminal and completed, the thread's summed open work is zero, and the touched row is recent. Recency is the touched row's, so open work ending late still notifies.
    - Anything else does not: a completed turn while open work remains, a completed turn that is not recent, a cancelled turn, a running turn. The `push.json` turn cases gained `atRest` (absent reads as true) and four cases.
  - **Two consequences.** First, several completed turns of one thread that arrive in one push now give one "Replied", for the latest turn, where each gave one before; the test `read_withdraws_earlier_turns_once` was changed to push them in separate batches. Second, a reply the owner has already read is, as before, written to the ledger and withdrawn in the same push, so it stays silent when open work ends later; a newer reply than the read turn still alerts then. The tests are `a_reply_already_read_does_not_alert_when_open_work_ends` and `a_newer_reply_than_the_read_turn_alerts_when_open_work_ends`.
  - **A touched failed turn and the latest reply (whole-change review).** A touched turn is checked for both notifications, each keyed and written to the ledger on its own, the failure first: its own failure, keyed by the touched turn, and the reply of the thread's latest live turn when that is a different turn, under the reply conditions above. Before this, a touched turn that had failed returned its failure only, so when an earlier turn failed holding open work and later dropped it to 0, its failure was already in the ledger and the later reply it held back was never sent. When the touched turn is itself the latest turn and failed, only the failure applies. The tests are `a_reply_is_not_lost_when_an_earlier_failed_turns_open_work_ends` and `a_failed_turn_and_the_reply_after_it_both_notify_in_one_push`.
  - **Open point, for the coordinator change's plan.** The state rule, the hub's bands and the reply rule all read the latest turn by `createdAt`. If an owner's turn that is still submitting and a runtime turn created after it ever exist together, and the runtime turn ends first, the thread would read finished and "Replied" would be sent while the older turn still runs. Today a send is refused while a turn is active, so the readings agree.
  - **A stop (amends the design).** A Stop that ends open work is, to the hub, the same as the agents ending: the phone is told "Replied" for the latest reply if it is unread. The design said a stop sends nothing; that sentence is replaced.
  - **Ledger retention (accepted).** A reply is keyed by the latest turn while recency is the touched row's, so after the ledger's retention period (30 days by default) a fresh touch of any turn of a thread whose latest reply is still completed, unread and at rest can notify again.
  - **Deferred to the transcript change.** `lastActivityAt` does not move when open work ends on an earlier turn, so a thread that comes to rest does not move up the list. The phone's "Working" label for a Mac that is offline reads the latest turn's status, not open work.
  - **Not here.** The coordinator and the adapters do not yet set `openWork` or `origin`, nothing draws them, and the phone's own notification check (`MirrorNotifications.swift`) is unchanged.
