## 2026-11-02 (sign-in build)

- **D-095 Account deletion refuses a member of a shared org, and revokes at Apple before it deletes.** `Hub/crates/b4hub-db/src/accounts.rs`, `Hub/crates/b4hub/src/routes/me.rs`. `DELETE /v1/me` deletes only the owner of a personal org; anyone else (an operator-seeded user such as `blove` in `cacheplane`) gets `409 shared_org` before anything is revoked, because shared orgs are not designed yet and their devices own rows other members read. Every sealed Apple refresh token is opened first, then each is revoked; a token that does not open, a failed revoke, or a hub without Apple configured fails the request with `500` and deletes nothing, so it can be retried. The delete is one transaction that locks the user row and reads the tokens again; an Apple ID linked meanwhile is revoked and the delete retried, up to three rounds. A rotated `B4HUB_SECRET_KEY` or a corrupt row therefore leaves an account undeletable until an operator steps in. On the Mac, deleting signs out, drops the account's database, and only then removes its registry row; a failed drop keeps the signed-out row and says the data stayed ("Your account was deleted, but its data on this Mac couldn't be removed.").
  - *Amended by D-115:* unlinking an Apple ID revokes it the same way first, and a deletion closes the account's relay links and deletes its `user_links` claim.
