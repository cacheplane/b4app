## 2026-11-02 (M8f, attention on the phone)

- **D-125 The mirror lives in the flavour's App Group.** The App Group is per flavour, `B4APP_APP_GROUP` in `Config/Flavor-*.xcconfig`: `group.com.cacheplane.b4app` (prod), `group.com.cacheplane.b4app.beta` (beta), and `group.com.cacheplane.b4app.local` (local), so flavours installed side by side (prod and beta share one iPhone bundle id, D-109) never share a mirror. The app and the widget read the group id and the URL scheme from the Info.plist keys `B4AppAppGroup` and `B4AppURLScheme`, which `project.yml` fills from `$(B4APP_APP_GROUP)` and `$(B4APP_URL_SCHEME)`; each flavour's iOS entitlements file (`B4APP_IOS_ENTITLEMENTS`) and the widget's `Apps/iOSWidget/B4AppWidget.entitlements` name the group as `$(B4APP_APP_GROUP)` (a scheme that is empty or not a valid scheme falls back to `b4app`). The widget's bundle id is the app's plus `.widget`, through `B4APP_BUNDLE_ID_SUFFIX` in the same xcconfigs. Inside the group the mirror keeps the flavour's folder name (`PhoneFlavor.directoryName`: `b4app`, `b4app-beta`, `b4app-local`), which the widget reads from its own `B4AppFlavor`. On launch a `mirror.sqlite` with its `-wal` and `-shm` in `<Application Support>/<flavour's folder>` moves to `<group container>/<flavour's folder>` when the group has none (side files first, the main file last; a failed move puts the side files back), and `device.json` (the remembered devices) follows it when the group has none; when both exist the group's copy wins and the old one is left where it is; without a group container the app keeps the old location and the widget shows "Open Agent Workspace to see your threads.", as it does for any mirror it cannot read. The widget opens the file read-only (`SQLITE_OPEN_READONLY`, `query_only`, no migration; a file at another schema version reads as unpaired).
