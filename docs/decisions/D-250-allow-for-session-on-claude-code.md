## 2026-11-17 (Allow for session on Claude Code)

- **D-250 On Claude Code, "Allow for session" is the allow rule the request suggests, kept in the process; a suggested mode change or directory is never sent (amends D-248 and D-018).** D-248 left Claude Code with "Allow once" and "Deny", because a plain allow is all D-018 sent. Its design made a wider allow depend on a live recording, which passed on Claude Code 2.1.282.
  - **What the CLI sends and takes.** A `can_use_tool` request carries `permission_suggestions`. For a Bash command they were three: `addRules` with `behavior: "allow"`, the exact command as its one rule (`{toolName: "Bash", ruleContent: "touch one.txt"}`) and `destination: "localSettings"`; `addDirectories` for the working directory; and `setMode` to `acceptEdits`. An allow answer takes `updatedPermissions`, and a rule sent there with `destination: "session"` is applied: the same command was not asked again in that process, a different one was, and no settings file was written.
  - **The scope.** A tool permission whose suggestions include an allow rule gets `allowScope: "session"` and `allowRule`, the rule as Claude Code writes it (`Bash(touch one.txt)`, or a bare tool name when the rule has no content). One with no allow rule has no scope, as in D-248, and `allow_always` on it is still refused.
  - **The answer.** `allow_always` sends the allow with those `addRules` updates, each re-addressed to `session` whatever destination the suggestion named, so D-018's objection to writing the user's settings files stands. `addDirectories` and `setMode` are dropped: echoing every suggestion (the first recording did) switched the session to `acceptEdits`, which is far more than the button says.
  - **The card says how far it reaches.** The rule is the exact command, not a prefix, so the card draws "Allow for session covers Bash(touch one.txt)" above its buttons (`RequestChoices.reach`), and the CLI's request listing prints the same under its answer hint. Codex's session allow names no rule and draws no such line.
  - **What "session" means here.** The rule lives in the Claude Code process. A process the coordinator starts again with `--resume` (after a restart, an idle exit, or a change of model or permission mode that relaunches it) asks again.
  - **Left out.** A wider rule than the one suggested (a prefix such as `Bash(touch:*)`); showing or revoking rules already granted; suggestions on tools other than Bash, which get the button when they carry an allow rule but were not recorded live.
  - **Verification.** `docs/verification/2026-11-17-allow-for-session-on-claude-code.md`. Fixture-tested and live-tested through the adapter; the card was not seen on screen.
