## 2026-11-11 (Hub environment history preservation)

- **D-205 Preserve opaque sync history during pending Hub migration 18 (amends D-202).** The environment rename still rewrites structural references. A pending migration must preserve an opaque application payload such as `{"projectId":"external"}` and its stored byte count. Keep the published SQL and checksum unchanged; the public migration runner adds the preservation transaction.
  - **One transaction.** A public SQLx `Migrate` adapter delegates all operations, intercepting only the exact frozen simple transactional migration 18. It locks the affected relations before capture, stores native JSONB and byte counts in a temporary table keyed by organization and sequence, delegates original SQLx application through its tracked savepoint, restores and verifies the preimages and RLS/FORCE flags, then commits before SQLx releases the migration lock. The public runner closes its owned connection on success and failure.
  - **Errors.** Beginning, applying, restoring, rollback and commit failures return a fixed preservation error without native payload-bearing DETAIL or CONTEXT in the application error chain. Operator database logs are a separate configuration concern. Unsupported custom-trigger interactions must refuse and roll back; no trigger is disabled for compatibility.
  - **Existing data.** This prevents loss while migration 18 is pending. It does not reconstruct history in an already upgraded database. Such repair needs trustworthy original values. The local workspace Store needs its separate migration-11 fix, and broader protocol-client qualification and release remain open.
