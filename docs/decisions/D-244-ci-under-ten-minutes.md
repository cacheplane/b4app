## 2026-11-16 (CI under ten minutes)

- **D-244 CI keeps three iPhone journeys and five macOS smoke tests, builds the debug apps in a job of their own and no beta app, and reuses build output saved by clean builds on main (amends D-187, D-197, D-225).** The owner asked for a run under ten minutes that still gives broad assurance a merge can ship, relying on a few broad smoke and integration tests rather than exhaustive layout checks. A run took about 18 minutes and held four macOS runners: two layout shards of 17 to 18 minutes (41 app launches against D-187's 129-checkpoint contract), the smoke job at 16 (9 of tests, 6 building the two macOS apps), and the package job at 16 (4.6 building the two iOS apps). Design: `docs/superpowers/specs/2026-11-16-ci-under-ten-minutes-design.md`.
  - **iPhone.** One job runs `testWorkspaceNavigationJourney`, `testHealthyComposerJourney` and `testNotificationOpenJourneys` (five launches; 92 s of tests locally). Removed: the other ten journeys (sync copy, secondary notices, connection notice, startup and empty, landscape, maximum text, dark refusal, recovery, entry roots, notification cancel), the three UIKit component tests, D-187's coverage contract (`coverage.json`, `JourneyCoverage.swift`, `Scripts/verify_ios_layout_coverage.py`, `Scripts/verify_ios_layout_results.py`) and D-225's shards (`shards.json`, `Scripts/ios_layout_shards.py`). The script now fails when xcodebuild fails or no test ran. `SyncBannerContentTests` in the package still checks the banner's copy and precedence.
  - **macOS smoke.** Kept: `testDesktopDarkRecovery`, `testDesktopDarkB4Recovery`, `testPaletteAndSlashByKeyboard`, `testALongThreadShowsEarlierRowsOnRequest`, `testHostExitsWhenItsOwnerPipeCloses`. Removed: the compact-light, compact-dark and desktop-light recovery journeys, the compact-light B4 journey, the palette panel's drag, snap and shadow test, the command centre test, jump-to-latest and copy-code, and the tall first message. No UI test now runs the compact width; `RecoveryCompressionTests` and `DetailMinimumSizeTests` cover compression.
  - **App builds.** A new macOS job, "App builds", builds `B4App-iOS` (generic Simulator) and `B4App-macOS` in one DerivedData beside the tests; the required check "macOS and iOS app builds" reads its two step outcomes. The beta schemes differ only in `Config/Flavor-beta.xcconfig` and are no longer built in CI; `Scripts/package.sh` and `Scripts/upload-ios.sh` still build them at release. Putting the app builds at the end of the UI jobs was rejected: D-232 measured that an app build shares no compiled modules with a fixture project's build.
  - **Build caches.** The package job caches SwiftPM's `.build`; the three Xcode jobs cache DerivedData's `Build` and `ModuleCache.noindex`. A push to main restores nothing, builds from clean, runs everything and then saves under its commit; pull requests and merge groups restore the newest of main's and never save. Each job first runs `Scripts/restore_mtimes.py`, which sets every tracked file's time from its git blob id (a fixed epoch plus the id's first 30 bits): a checkout's own times would make every restored build rebuild everything, and unchanged content now gets the same time in every checkout while changed content gets a new one, which Swift's build systems rebuild on. A push to main no longer cancels the run before it (`cancel-in-progress` holds only for pull requests and merge groups): the merge queue pushes once per group, and a cancelled main run would never save. GitHub keeps one waiting run per group, so a third quick merge replaces the waiting one, not the running one.
  - **Required checks.** Unchanged in name. "iOS navigation and banner regression tests" now reads one job's result.
  - **Verification.** `Scripts/tests/test_ci_scope.py`, `test_ios_layout_simulator.py` and `test_restore_mtimes.py`; actionlint; the three iPhone journeys passed locally and an empty run failed; the smoke tests built for testing. Not yet shown: the hosted run's times and that a restored cache recompiles a changed file and nothing else. Both need main's caches, which exist only after this merges; they go in a gate record, and a cache that saves under two minutes is removed then.
