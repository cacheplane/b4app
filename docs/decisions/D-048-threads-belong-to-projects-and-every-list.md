## 2026-11-01 (M8b)

- **D-048 Threads belong to projects, and every list shows them in one attention order computed by the same code on both devices.** A project is a named set of folders on one Mac; a thread belongs to the project that owns its working directory exactly, so a subfolder is its own project. Paths are matched in the coordinator's canonical form (tilde expanded, symlinks resolved, no trailing slash), `projectFolders.path` stores that form, and `threads.context` is never rewritten, because Codex and Claude receive it as the working directory. The coordinator creates an automatic project (empty name, shown as the folder's last path component) when a thread's folder has none, resolving the project and inserting the thread in one actor section so a concurrent create cannot split them. A thread on a local B4 connection belongs to the project of its managed server's directory; a thread on a remote B4 connection has none and appears under "Other". A folder belongs to at most one project: adding one to a manual project moves it out of its automatic project, an automatic project left with no folders is deleted, and adding a folder that already belongs to another manual project is refused (`protocolInvalid`) rather than moved, as is an unknown path in `project.update`. Deleting a manual project returns its folders to automatic projects; renaming one to the empty string restores the folder-name display. `project.list|create|update|rename|delete` and the `project.changed` event are coordinator commands (the mirror answers `project.list` and `project.rename`); local migration `0004` backfills automatic projects from existing threads' canonical folders and local servers' directories, with the log recording it so it syncs, and marks every existing thread read at its latest turn when that turn is terminal (latest by `createdAt`, then greatest `id`, `COLLATE "C"`; a thread still working keeps a null marker), also through the logging trigger, so the upgrade turns no old reply unread and the markers reach the phone. Each thread falls in one band, tested in this order: needs input (a runtime request in state `pending`, on any turn), working (the latest turn, by `createdAt` then greatest `id`, is not terminal), unread reply (the latest turn is terminal, a failure included, and its id is not `threads.readTurnId`), and quiet. Display order is pinned first, then needs input, unread, working, quiet; inside a band, `lastActivityAt` descending, ties by thread id. `lastActivityAt` is the latest of the thread's `createdAt`, its latest turn's `updatedAt`, and its latest request's `updatedAt`, never `threads.updatedAt`, so pinning, renaming, or reading a thread cannot reshuffle the list. `ConversationThread.activity` carries these facts; the coordinator computes them in SQL and `MirrorStore` in SQLite, both against `Tests/Fixtures/sync/attention.json`, and `Attention` in `WorkspaceProtocol` computes bands and order on both platforms; nothing about bands is stored or synced. `readTurnId` is Brian's, not a device's, so reading on the Mac clears unread on the phone. `thread.markRead` is sent when a thread is open and its latest terminal turn is on screen, once per (thread, turn); "on screen" is `WorkspaceModel.isDetailOnScreen`, which the views set only while the scene is active, the Mac's window is active, and on a compact width the detail column is the one showing, because the open thread stays loaded behind the iPhone's list and the Mac's inactive window, so a reply arriving there stays unread until the thread comes back on screen, and the store accepts a terminal turn not earlier than the current marker and never touches `threads.updatedAt`; "Mark as Unread" (set to null) is offered only for quiet threads. The Mac sidebar has "Pinned", then one collapsible section per project ordered by its best band and then its most recent activity, then "Other" always last; collapsed state is `@SceneStorage` and never syncs. The iPhone has one flat list whose filter menu replaces the connection picker (All projects, each project, Other, Archived, then the connections). Each row shows a status dot, title, project, connection kind, and a reason line ("Waiting for your approval", "Has a question for you", "Replied 3m ago", "Failed", "Working"). **The status dots follow D-036's one accent, not the per-state colours the plan first named:** needs input is a filled accent dot, unread a filled ink dot, working an ink ring that pulses gently only when Reduce Motion is off (never paler than the quiet dot), and quiet a small muted hollow ring, each with an accessibility label naming its band. Known limitations: projects and their folders are created and changed only on the Mac; the iPhone still shows the Mac's working directory (D-046); rows are three lines tall (a design call to revisit on the owner's word); every `thread.updated` makes the model refetch the whole thread, so a large pull is many reads (debounced about 200 ms per thread); the "New Project" and rename sheets compile on iOS but are unreachable there (the phone renames the project selected in its filter menu, through an alert, added in the live run); a folder whose symlink target changes can keep a thread out of its project until the next backfill; and the live gate for this decision passed on 2026-11-01 (`docs/verification.md`).
