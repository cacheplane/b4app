## 2026-11-02 (Apple callback scheme)

- **D-140 Each hub hands Sign in with Apple's web flow back to one app scheme, its flavour's, set by `B4HUB_APPLE_CALLBACK_SCHEME`; begin refuses any other.** Resolves D-114. `Hub/crates/b4hub/src/config.rs`, `routes/apple.rs`. The setting is one of `b4app`, `b4app-beta`, `b4app-local`; it is required with `B4HUB_APPLE_SERVICES_ID` (the web flow) and refused without it, and an invalid value or either half alone exits 2 at start, as D-112's Apple settings do. `POST /v1/auth/apple/begin` and `POST /v1/me/apple` still take `scheme` (the wire and `Tests/Fixtures/sync/auth.json` are unchanged): a value off the list is `400 invalid_request` as before, and another flavour's scheme is now `400 invalid_request` too, whose message names the scheme this hub serves, with no ceremony made. The ceremony no longer stores a scheme; the callback redirects to the configured one, so nothing a caller sends can choose where a handoff goes. A custom scheme rather than a domain-verified universal link, the other option D-114 named, because the flavours already map one-to-one to hubs (D-110) and the Mac's `ASWebAuthenticationSession` hands back through `callbackScheme`; with one scheme per hub, the attack D-114 describes needs a malicious app that claims the hub's own flavour's scheme on a Mac that has that flavour, which a custom scheme cannot rule out and which stays an accepted risk. The hosted hubs set `b4app-beta` (test) and `b4app` (prod): `Infra/scripts/deploy.sh` passes it per environment into `Infra/taskdefs/hub.json.tpl`, and `Infra/modules/hub/ecs.tf` does the same for Terraform's placeholder revision. The chart gains `hub.apple.callbackScheme` (version 0.3.0) and Compose's `.env.example` names the local value. The Mac already sent its flavour's `Flavor.urlScheme` and shows the hub's refusal as `protocol_invalid` with the hub's message, keeping no ceremony (`AccountCommandTests.appleStartsShowTheHubsSchemeRefusal`). A hub release that includes this exits 2 on a host that sets `B4HUB_APPLE_SERVICES_ID` without the new variable, so the variable goes in with (or before) the release.
