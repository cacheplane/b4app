## 2026-11-02 (sign-in build)

- **D-117 A device forgets a passkey only when the hub says no account holds it.** `ApiError::credential_unknown` (`Hub/crates/b4hub/src/error.rs`), `routes/auth.rs`, `AccountState.reportRejected`. A passkey sign-in's finish answers `401 credential_rejected` in every failed case, as before; only when no identity holds the asserted credential id (never registered, or its account deleted) does it add `details.reason: "unknown_credential"`. Signature, origin, relying-party, counter, user-handle, and malformed-response failures carry no reason. The coordinator and the phone pass `details.reason` on in the error's details, and the shared sign-in model then reports the asserted credential unknown through `PasskeyCeremony.reportUnknownCredential` (relying party from the options' `rpId`, id from the assertion), on both platforms; any other refusal reports nothing. So a deleted account's passkey stops being offered, while a misconfigured hub (a wrong RP id or origin, which refuses every passkey) can never make devices delete valid passkeys, which cannot be undone. The reason leaks nothing useful: credential ids are random, so it cannot be used to find an account.
