## 2026-11-02 (M8c follow-ups)

Fixes for phone transcript limitations found in the M8c live gate and build review (`fix/m8c-transcript`), and for the stopped reply found while checking them (`fix/stopped-reply-text`).

- **D-088 A reply stopped mid-stream keeps the text that streamed.** When a Codex turn is interrupted, the agent message it was streaming is not completed with its text (live on 2026-11-02 it was stored empty), so the item kept the empty text it was started with: the partial reply vanished from the Mac, the phone, and the store when the turn ended. `SessionService` now keeps each open message's streamed text in memory, by thread and native item id. When a completion carries no text, the streamed text is stored instead; a completion with text is the runtime's final word and is kept as it is. When the turn ends with messages still open, each is stored with its streamed text and announced as `message.completed` before `turn.finished`, so a client that clears live text at the turn's end (the Mac's model and the phone's) still shows the reply. Claude Code completions are matched to their streamed items by type and stream order, not by their position in the `assistant` frame, which named the wrong item; with the streamed text now stored, that showed a Claude reply twice. An abandoned turn (D-031) drops what streamed, since the runtime never said how it ended. The text is held only while the coordinator runs: a coordinator that restarts mid-reply stores the item as the runtime's history (snapshot) has it. `SessionServiceTests.aStoppedReplyKeepsItsStreamedText` (both the never-completed and the completed-empty cases, with a `partial` mode in `fake-codex.py`).
