## 2026-11-02 (M8f APNs, real notifications on the iPhone)

- **D-146 The phone backstop removes what the hub says is over, and judges only what it has already pulled.** `MirrorStore.stillOutstanding(keys:)` (`Sources/WorkspaceMirror/MirrorNotifications.swift`; no `UserNotifications` in the library) answers from the mirror: a `request:` is outstanding while the request exists, is `pending`, and its thread is not deleted; a `turn:` while the turn exists, its thread is not deleted, and the thread's `readTurnId` is unset or names an earlier turn (a read turn the mirror does not hold leaves it up); an unknown id, another prefix, or a malformed key is not outstanding. `MirrorHost` (`Apps/iOS/B4App/MirrorHost.swift`) runs it after every successful sync turn and every published batch, at most once a second (a streaming reply is one run at the end of the interval), and removes the delivered notifications that have ended, then sets the badge (D-144). Because an unknown id reads as ended, it judges only notifications delivered before a pull that has since been applied (`judgedThrough`, advanced when a turn of the loop that began after the previous report succeeds), so a notification whose row is not pulled yet is never removed by mistake. A push wake and a foreground both reach it, so a withdrawal that was delayed, dropped (Low Power Mode, an app swiped away), or never sent (D-148) is cleared by the next sync; signing out removes every delivered notification and the badge. Parked: when more than 1000 changes are outstanding the pull spans several pages and a judged notification's row can still be on a later page, so the backstop may remove it early during that catch-up (the badge is unaffected); closing that needs `MirrorSync` to report when it has caught up. An account-to-account switch heals itself through the same judging.
