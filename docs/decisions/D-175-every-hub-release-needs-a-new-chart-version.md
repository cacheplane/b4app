## 2026-11-04 (a chart version for every hub release)

Found when `hub-v0.4.0`'s "Publish the Helm chart" job failed after its production deploy had succeeded (`docs/verification/2026-11-04-production-on-hub-v0-4-0-and-two-tasks.md`). Numbered D-175 by `Scripts/docs-index.sh --next`.

- **D-175 Every hub release needs a chart version not yet published, and the release checks it before it tags or deploys anything.** A `hub-v*` release publishes the chart whose version is in `Hub/chart/b4hub/Chart.yaml`, with `appVersion` set to the release, so a release whose chart version is already out cannot publish. `hub-v0.3.0` had published chart 0.4.0, nothing bumped it, and `hub-v0.4.0` failed in its last job, with production already on the new image and the published 0.4.0 chart still naming hub 0.3.0. The runbook's rule ("bump when anything under `Hub/chart/` changed") was wrong: the `appVersion` changes with every release. Now the rule is to bump the chart version for every release, and `hub-release.yml`'s first job runs `chart-version-published.sh` against the version at the release commit and fails, before the image is tagged or production asked, when it is already published. `Chart.yaml` goes to 0.5.0, so the next release publishes a chart naming it; chart 0.4.0 stays as it is (it names hub 0.3.0, whose image it was tested with), since the chart has no users yet to mislead.
