## 2026-11-12 (environment form)

- **D-212 An environment is edited in a form in the Mac's main view, any environment can take another's folder or be deleted, and the phone no longer makes one (amends D-048 and D-180).** This builds "Editing an environment" from the thread list and environments design (`docs/superpowers/specs/2026-11-10-thread-list-and-environments-design.md`, mockup `grouped-v13`, card 4), the last step its build order names ("environment form"). It replaces the Mac's interim Rename sheet, Add Folder panel and Delete confirmation, and the phone's New environment.
  - **The Mac's form.** `EnvironmentForm` shows in the main view where a thread shows, titled "Environment" in the toolbar, while `WorkspaceModel.editingEnvironmentId` is set; opening a thread or the new-thread view closes it, and so does its environment leaving the list. It has the name as a 26 pt heading and the thread count under it ("No threads", "1 thread", "4 threads": threads the list holds in it); **Name**, a 32 pt field prefilled with the name shown, with "Taken from the folder name. Change it to anything."; **Folders**, a bordered list of paths in JetBrains Mono 12 with the home folder as "~", the first tagged "Threads start here" and each other with Remove; "Add folder…" (the system folder panel) and "Agents start in the first folder and can work in the others."; Done; and at the foot "Delete environment…", confirmed in place ("Its threads move to “No folder”. Nothing on disk is touched.") rather than in a sheet. Changes save as they are made: the name when the field is left or Return is pressed (and on Done), each folder change at once; a refusal shows in the danger colour under the folders and changes nothing. The form is at most 520 wide with 40 and 32 pt insets.
  - **Where it opens.** A "By environment" heading's hover buttons are now New thread here and Edit (`slider.horizontal.3`), the edit button centred on the marks' column; its context menu has New Thread Here and Edit Environment…, and VoiceOver gets both as actions. View options' submenu, renamed "Edit Environment", lists every environment and opens its form, so an environment can be edited under "Needs you first" and when it has no live thread.
  - **The rules (amends D-048 and D-180).** The `manual` flag no longer limits anything. A folder another environment owns, manual or automatic, is moved by `environment.create` or `environment.update` with its threads, and an environment that leaves with no folders is deleted. `environment.update` refuses to remove an environment's last folder ("needs at least one folder; delete it instead"); a removed folder that threads use still gets an automatic environment of its own, so every folder in use keeps one. `environment.delete` takes any environment: its folders go and its threads move to "No folder" (`environmentId` set null by the foreign key, which the change log records, so the phone sees it), nothing on disk is touched. So that the start-up backfill does not put those threads back, the delete first records their ids in the Mac's local setting `environments.detachedThreads`, which the backfill skips; a later edit that places their folder in an environment takes them in again, and a new thread in that folder makes a new environment while the old threads stay under "No folder", as the design says. Adding a folder still marks an environment manual; the flag is kept as data (dropping it would touch the hub and the fixtures for nothing).
  - **The phone.** "New Environment…" is gone from view options, and `EnvironmentSheetRequest` has only `edit`; the sheet keeps rename (through the change log, the Mac may be offline), folder edits and Delete (relayed to the Mac), now for every environment. The name field starts with the name shown, as on the Mac, and an untouched or emptied generated name saves nothing. Remove is off on the last folder; the folders offered are every other environment's on that Mac. `environment.create` stays a coordinator command and relayable; nothing in the apps sends it now.
  - **Shared.** `WorkspaceModel.editEnvironment` (a name alone is a rename, folders are one update) and `deleteEnvironment(id:)` serve both apps and return their failure to the caller; `createEnvironment`, `renameEnvironment` and `addFolder` are removed. `EnvironmentCopy` holds the words and the name rule both use.
  - **Builder's calls.** The first folder (the oldest) cannot be removed or moved down from the form, since the mockup offers neither; choosing another folder as where threads start is left for later. Done does not take Return, which saves the name. The delete confirmation is not rendered in the snapshot. A local B4 connection whose server folder was in a deleted environment gets a new automatic environment at once (its server still runs there), unlike harness threads.
