## 2026-11-19 (what an ended turn's line says it folds)

- **D-261 An ended turn's line names the messages folded behind it: `2 messages · 1 step · 17s`, and a failed turn whose line already reads `N failed` has no `Turn failed.` under it. The fold itself is unchanged. Amends D-255 and D-223's counting.** A turn that has ended draws its last message and folds everything before it behind one line (D-223, D-255). The line counted steps only, so a finished Codex turn whose first message was a heading, a table, a list and a code block read `1 step · 17s`, with nothing to say that a reply was inside. Research for the owner (`reports/Agent UI turn folding.md`, not committed) found that folding all interim text is what the Codex desktop app does and what almost no other agent UI does by default, and that no product counts a message as a step.
  - **The owner's choice.** Four rules were drawn: today's, the same fold with a line that says what it holds, long or structured messages standing outside the line, and all messages standing outside it. The owner chose the second, and chose to keep `N steps` for tool work over counts by kind.
  - **The rule.** `ActivityLine.messages` is the number of folded items that are the agent's own words: an `agentMessage` with text that is not a sub-agent's. An ended line draws `1 message` or `N messages` first, then ` · `, then what it drew before. A thought, a plan, an empty message and a sub-agent's message are not counted. A line that folds a message and no counted step reads `1 message` with `Show`, where it read `Show working`; it has no duration, as before. A running, waiting or stopping line names no messages, since a running turn draws them. The spoken form has the same words in the same order.
  - **The note under a failed turn (amends D-223's notes).** Shown the capture of a failed turn (`3 steps, 1 failed · 1m 12s`, the answer, then `Turn failed.`), the owner asked whether the last line was needed. It is not there: a failed turn whose line reads `N failed` draws no `Turn failed.` note, closed or open. The note stays wherever it is the only sign: a failed turn with no failed step (a turn that failed before or after its work, or with no items at all), a stopped turn (`Turn stopped.`) and a turn with no outcome (`Turn ended.`), whatever their steps did. The writer's call, since the owner's words were about the one case: a turn that completed with a failed step and a turn that failed with one now draw alike in the thread, and the sidebar's mark still tells them apart.
  - **Left out.** Keeping a long or structured message outside the line; reading Codex's `phase` (`commentary`, `partial_answer`, `final_answer`) in the adapter; counting tool work by kind.
  - **Tests.** `DenseTranscriptTests` (`theLineCountsTheMessagesItFolds`, `foldedMessagesAloneAreNamedAndNotShowWorking`, `onlyTheAgentsOwnWordsAreCounted`, `aRunningLineNamesNoMessages`) and `foldedMessagesLeadTheLine` for the drawn segments; two older expectations changed with the rule (`anEndedTurnIsMessageLineAnswer`, `aThreadFromHistoryIsGroupedAtUserMessages`). For the note: `aFailedTurnWhoseLineSaysFailedHasNoNote` and `aStoppedTurnWithAFailedStepKeepsItsNote`; `aTurnsNoteFollowsItsTurn` and one `TranscriptCorpusTests` scenario lost a note.
