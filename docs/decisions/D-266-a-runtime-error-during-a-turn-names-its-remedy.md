## 2026-11-21 (the notice for a runtime's error during a turn)

- **D-266 A runtime's error during a turn reaches the open thread's notice with its code, so the notice says what to do: an expired Claude Code sign-in offers Sign in to Claude, and the runtime's own words move to Details.** Claude Code whose OAuth session has expired answers a turn with an assistant message flagged `error: "authentication_failed"` and an error result (Claude Code 2.1.282, captured signed out). The adapter already mapped that to `auth_required` and the coordinator already marked the connection Sign-in needed (A15), but the app's model kept only the text of the `adapter.error` event, so the thread's notice repeated the runtime's words with only Dismiss. Found in the 2026-11-20 smoke test.
  - **The rule.** `WorkspaceModel` sets `lastFailure` from an `adapter.error` for the open thread: the code from `errorCode` (`internal` when absent or unknown), the message, and the message again as `nativeMessage`. The notice then takes its words and action from `Remediation` as for any other failure: Sign in to Claude for Claude Code, Sign in with ChatGPT for Codex, the endpoint's credential steps for B4; an uncoded error keeps the runtime's words and no action, as before. An error of another thread does not reach the open one.
  - **Left out.** The transcript still holds the runtime's error text as the turn's message and `Turn failed.` under it; this is the record of the turn, and the notice is the action. Claude Code's `auth status` reports signed in until its first failed refresh, so `doctor` and the Connections card can read signed in until a turn fails; not changed here.
  - **Tests.** `TurnErrorRemedyTests` (`anExpiredSignInDuringATurnOffersSignIn`, `anUncodedErrorKeepsTheRuntimesWords`, `anotherThreadsErrorLeavesTheOpenThreadAlone`).
