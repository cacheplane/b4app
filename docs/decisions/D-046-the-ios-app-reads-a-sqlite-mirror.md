## 2026-10-31 (M8a)

- **D-046 The iOS app reads a SQLite mirror fed by the hub's change log through an in-process `WorkspaceTransport`, so the SwiftUI shell is unchanged across platforms; only threads created in the app sync.** Nothing is read from `~/.codex`, `~/.claude`, or a B4 server's history. Three Foundation-only modules were added. `WorkspaceSecrets` holds `SecretRef`, `SecretStore`, and `KeychainSecretStore`, moved out of `WorkspacePlatform` (which re-exports them) so the iOS target can use them without the macOS-only module; on iOS the item is in the data-protection keychain with `AfterFirstUnlockThisDeviceOnly`. `WorkspaceSync` holds the wire types, `HubAPI`, `HTTPHubAPI`, `FakeHubAPI`, and the `HubURL` rule (https anywhere; http only for `localhost`, `127.0.0.1`, `::1`), enforced by the coordinator's `hub join` and the phone's Connect screen before any request. `WorkspaceMirror` keeps STRICT SQLite tables with the Mac's column names (WAL, `synchronous` FULL, foreign keys, `busy_timeout` 5000), replays a change batch with the same semantics as `WorkspaceDatabase.replay`, blanks `authReference`, `localServerId`, and `target` again on the way in, and stores a row that does not decode through the protocol types, skips it on read, and counts it in `SyncDiagnostic.undecodableRows` rather than dropping it or failing the batch. The Mac side is `HubSync` in the coordinator, the only code that talks to the hub: it pushes the trigger-written change log in batches of 500 rows or 8 MiB, marks rows `synced` only through the hub's `acceptedThrough`, is nudged by the event log, a 30 s timer, and wake, and suspends on a 401 until the next `hub join`. `SyncFilter` keeps only the 16 known `connections` columns on an insert (an allowlist; a non-object insert is dropped), blanks `connections.authReference`, `localServerId`, and `target` for every kind, replaces a `nativeScope` (on `connections` and `threads`) that contains `/`, such as a B4 origin URL or a Claude config directory, with `scope:` plus the first 16 hex characters of its SHA-256 (stable, so the mirror's uniqueness on connection, scope, and native thread holds), never uploads `localServers`, and replaces a `displayItems.payload` or `runtimeRequests.payload` over 1 MiB with `{"truncated": true, "bytes": n}` on inserts and updates; the wire carries no device id, the hub attributes every change to the authenticated device, and the Mac's `b4app.device_id` session setting is now set per write transaction from `hubLink`, so rows written before joining, recorded as `local`, need no rewrite. `database.restore` is refused while joined (`hub leave` first), because a restore rewrites the change log and its sequence, and reused device sequence numbers would count as already accepted at the hub and never be mirrored. `DiagnosticsReport.sync` is an additive optional field, and `ConnectionsView` hides an empty target path. `Tests/Fixtures/sync/changes.json` is the cross-language contract, decoded in place by the Rust and Swift suites; edit it only with both suites. Unimplemented behaviour (phone writes, the relay) throws `unsupportedCapability` naming M8b or M8c. `threads.context` (a harness thread's working directory, a B4 thread's route) syncs unchanged, by the owner's decision on 2026-11-01: transcripts already carry the same paths (a command item's `cwd`, file changes, output), so hashing this one column would only cost the phone its project label; keeping local paths off the hub altogether is a separate, larger decision (end-to-end encryption or transcript scrubbing), not taken in M8. *Amended by D-049 (2026-11-01): phone writes (titles, pins, archive, read markers, project names, drafts) exist as of M8b; the relay, turns, and thread creation from the phone still throw `unsupportedCapability` naming M8c, and project create, update, and delete name the Mac.*
