## 2026-11-12 (density and the sidebar setting)

- **D-218 Density is its own setting, and the sidebar setting is Shown, Collapsed or Hidden (amends D-208).** The settings row's four-way "Small, Tiny, Collapsed, Hidden" mixed two questions: how tall the rows are, and where the threads that do not need the owner go. They are now two settings in the same synced row. Design: `docs/superpowers/specs/2026-11-12-density-and-user-settings-design.md`, Part 2; plan: `docs/superpowers/plans/2026-11-12-display-settings.md`. The code is commits 0c8b71f (the type), c21cb77 and 23fef99 (the Mac's store), 229892c (the phone's mirror), 6302afe and 234a766 (the hub) and 7396046 (the screens).
  - **The owner's decisions.** Density is its own setting, normal or dense, set with a "Dense" switch on a new Display page in Settings; it is app-wide and synced per user. "Threads that don't need you" is a separate sidebar setting: Shown, Collapsed or Hidden. The old values convert as follows: `small` is normal and shown, `tiny` is dense and shown, `collapsed` is normal and collapsed, `hidden` is normal and hidden. The defaults are normal and shown.
  - **Storage.** One new text column, `density`, on `viewSettings` (`normal` or `dense`, read leniently and kept whatever text arrives, like the row's other columns). `quietThreads` is reused for the three-way value. Three migrations, each converting its own stored row: the hub's `0021_density.sql`, the Mac's store `0014_density.sql`, and the phone's mirror schema 9. Each logs no change and moves no clock, since every device converts its own copy; the hub gives the new `density` the clock of the row's `quietThreads` when it had one, so a write made before the upgrade cannot win over it, and a row with no such clock gets none. A density already stored is kept; a null or unknown `quietThreads` is left alone. `density` is in the clocked columns of the store's change trigger (`SyncColumns.clocked`), which a test reads back.
  - **Departures from the design, the builder's calls and not the owner's.** (1) The Display page is on the Mac only in this part; the phone gets it with the dense thread, since Dense draws nothing on the phone yet. (2) The switch's description says only what is true now: "Tighter rows for the threads that don't need you." (3) Old values are also understood when read: `tiny` with no density stored reads as dense and shown, and `small` as shown. The hub's change log keeps old entries, and a newly paired phone replays them, so a value can arrive from the log after the migrations have run. (4) "By environment" is unchanged at either density. (5) `quietThreads` is reused for the three-way value instead of a new column.
  - **The write rule.** Replacing an old `tiny` through the sidebar setting also writes density dense, so the rows keep their size when the old value is replaced; this happens only when no density is stored. A stored density this build does not know is a newer build's value and is never overwritten (23fef99).
  - **Deleted.** `ViewSettings.shown(on:)`, and the phone's "Tiny shows as Collapsed" fallback and its menu note. No stored value is left that a device cannot draw, because every value is either one it draws or one it reads as a default.
  - **Where tight rows are drawn.** On the Mac, with Dense on: the lower list, the rows opened from Collapsed or Hidden, and the selected row kept out of the stow. Not drawn tight: the top list, "By environment", archived rows, the "N more" row, and the phone (which keeps its 44 pt rows at either density).
  - **Builder's calls made during the build.** The Display page's icon is `textformat.size`. The switch is not disabled while offline; a refused write puts the old value back, like the view-options menu.
  - **What is not done.** The phone's Display page, the dense thread, and the dense composer. Old values already in a phone's outbox, not yet pushed, are left as they are; devices read them. VoiceOver on the switch was not checked on a running app (the label and description are the switch's own label, so it should read as one).
  - **Numbering.** Pull request 188, from another branch, also holds a hub `0021`, a store `0014` and a mirror schema 9. Whichever merges second renumbers; the numbers in this entry are as built.
