## 2026-11-02 (M8f, attention on the phone)

- **D-127 The sync loop pauses before the app is suspended.** iOS ends an app that is suspended while it holds a SQLite lock on a file in a shared container (`0xdead10cc`), and the mirror is now in the App Group. `MirrorSync.suspend()` cancels a long-poll or backoff, lets a push or apply already running finish, and returns once the loop is parked between turns; nothing reaches the hub or the store until `resume()`. `MirrorHost` suspends under a background task when the scene goes to the background (and a loop started while already in the background starts suspended) and resumes when it is active; a background wake resumes, waits for the next batch or 8 s, and suspends again before calling the system's completion handler. Since sign-in the phone's account owns the sync (`MirrorAccount`), so the host suspends and resumes through `MirrorAccount.suspendSync()` and `resumeSync()`, which keep the choice: a sync the account starts meanwhile (a sign-in, a restart after a refused call) begins parked (`MirrorSync(startSuspended:)`). Found in the task review, not seen in the Simulator (which does not enforce the rule).
