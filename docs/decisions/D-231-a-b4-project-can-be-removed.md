## 2026-11-14 (removing a B4 project)

- **D-231 A B4 project can be taken off the Mac; its threads stay, read-only.** At the owner's direction, after a clean-up of the local hub could delete every thread and environment but not the registered project: "Yes, add it." Until now a registration could not be removed (`docs/compatibility.md` said so), and because the project stayed, the coordinator made its folder's environment again as soon as that environment was deleted.
  - **The command.** `server.remove { serverId, force? }` answers `{ serverId }`. It stops the server first, with a stop's own rules: refused with `owned_process_conflict` (`reason: turn_active`) while a route connection has a running turn unless `force` is set (D-030), and a process that is not provably the app's is left running (D-025). Then, in one write, the project's route connections are disabled and its row is deleted; the app's own log file for it is deleted after. Nothing in the project's folder is touched.
  - **The connections are disabled, not deleted.** Threads refer to their connection, here and on the hub, and deleting a thread still needs it. `enabled = false` is the column the schema already had for this and nothing had set; it syncs, so the phone sees it too. A disabled connection is left out of Settings → Connections, of its background checks and of the palette's destinations (`WorkspaceModel.enabledConnections`); the sidebar's connection filter still lists it, since its threads are still there to filter to.
  - **The threads.** They are kept and can be read. A message to one is refused with `endpoint_unavailable` (`reason: server_removed`) before anything is sent: with no server row there is nothing to start, and the old loopback port may now be another process's. Deleting such a thread removes it from the app only, as for any disabled connection (D-119).
  - **Adding the folder again** makes a new project with new connections. The old threads stay on the old, disabled ones; they are not re-attached (my call: the route keys could be matched, but a `.b4` store that was moved or reset in between would make the old threads' continuity a guess).
  - **The environment** of the project's folder is left as it is, with its threads. It is no longer re-made once deleted, because no enabled connection serves it.
  - **Where.** Settings → B4 projects, "Remove…" in a project's "…" menu, behind a confirmation that says what stays and names a running turn when there is one; the confirmed removal is forced. `agent-workspace server remove <name> [--force]`. Clients learn of it from a new event, `server.removed`. The phone answers that running local servers is done on the Mac, as for the other server commands.
  - **Tests.** `LocalServerRemoveTests` (a running project is stopped, its connection disabled and kept, its thread read and its send refused, the folder re-added; the refusal while a turn runs and the forced removal; an unknown project) and `ServerRemoveModelTests`. Not checked on screen.
