## 2026-11-10 (no-folder starts)

- **D-203 A Codex or Claude thread can start with no folder (amends D-048).** D-048 put every Codex and Claude thread in the environment of its folder, and a `thread.create` with no working directory was refused. A start with "No folder" now works from the Mac, the phone and the CLI: the coordinator makes a private folder for the thread, and that thread has no environment. D-048's rule that a thread joins its folder's environment holds for every folder except one the app made.
  - **Root.** `PlatformPaths.threadFoldersDir`: `~/.b4app/projects` for prod, `~/.b4app/projects-beta`, `~/.b4app/projects-local`. When `B4APP_DATA_DIR` is set it is `<dataDir>/projects`, so tests and experiments stay out of the home directory.
  - **Folder name.** `<yyyy-MM-dd in UTC>-<first 8 characters of the thread id>`; if that path exists, `<date>-<whole thread id>`. An existing folder is never adopted. Mode 0700: the root through `PrivateFiles.ensurePrivateDirectory`; the thread's folder is created with permissions 0700 (`FileManager.createDirectory`, never with intermediate directories) and set to 0700 again right after, so the umask cannot loosen it; a recorded folder that is gone is made again through `PrivateFiles.ensurePrivateDirectory`.
  - **Where it lives.** `SessionService.threadCreate` (`appFolder(forThread:)`), so the CLI gets it too (`thread new --no-folder`; `--cwd` together with it is refused). `thread.start` passes no folder through. The `appFolders` table (coordinator migration `0012_app_folders.sql`) records each folder by thread id and path. It is local to the Mac: not in `ChangeLog.syncedTables`, no change-log trigger, never sent to the hub; it is in the `db backup` archive tables.
  - **No environment, ever.** A folder is an app folder when it has an `appFolders` row or sits under `threadFoldersDir`. `EnvironmentService.folder(forThread:connection:)` returns nil for one, so neither the insert nor the start-up `backfill()` gives its thread an environment.
  - **Relay.** `ThreadStart.Params` gains `deviceId: String?`. The hub routes `thread.start` by `environmentId` when it is present and by `deviceId` otherwise (the same device lookup as `environment.create`); the Mac ignores `deviceId`. `Tests/Fixtures/sync/relay.json` gains a no-folder `thread.start` and both suites were updated. No hub migration.
  - **Which Mac, from the phone.** "No folder" on the phone offers the ready Codex and Claude connections of the primary Mac (`primaryHostId`) and sends its id as `deviceId`; with no primary Mac, or while it is offline, the start is blocked. With no ready Codex or Claude connection to start it, "No folder" says "No ready Codex or Claude connection can start a thread with no folder." on the Mac and "No ready Codex or Claude connection on your Mac can start a thread with no folder." on the phone; the phone's Mac-offline notice comes first. A remote or local B4 is never offered "No folder".
  - **Default place.** The remembered environment if it still exists, else "No folder" (the spec's fresh-install default). The newest environment is no longer a fallback. A Codex or Claude start with no environment and no folder clears the remembered environment; a remote B4 start leaves it alone. The composer keeps a hand-picked "No folder" through a refresh.
  - **Words.** A thread with no environment reads "No folder" in the composer row, whatever its folder is called. The sidebar group and the phone filter formerly titled "Other" are now "No folder" and also hold threads whose environment is not known. The code names (`EnvironmentFilter.other`, `otherId`) are unchanged.
  - **Folder gone.** `turn.send` on a Codex or Claude thread whose folder is not a directory is refused before a turn is inserted, with `reason: "folder_gone"`, for every thread and not only app folders; the interface says the folder is gone. Nothing recreates the folder on send.
  - **Deviations from the plan.** (1) The app folder is made before the runtime's session is created (the runtime starts in it), not immediately before the thread row is inserted. Every refusing check still runs first, and a failure up to the insert removes the folder only while it is empty, then its row. The removal is `rmdir(2)`, which refuses a folder with anything in it, so a file written at any moment before it is never deleted; a folder that is not empty stays, and so does its row, so it is still known as one the app made. That removal is the only deletion in this change, and only of a folder made moments earlier. (2) From another device, a start with an unknown connection and no environment answers `connection_missing` (it was `environment_missing`). (3) On the phone a no-folder thread's owner, and the not-confirmed lookup, fall back to the Mac the start named (`deviceId`), since the thread has no environment to name its owner. (4) `ComposerPickerRow` puts a "No folder" toggle after the environments on both platforms (a divider between them only when there are environments), then "Choose folder…" on the Mac.
  - **Later.** The palette plan (a quicker way to pick a place), choosing among several Macs from the phone, and a cleanup service for old app folders (nothing deletes an app folder, empty or not, once the thread is made).
