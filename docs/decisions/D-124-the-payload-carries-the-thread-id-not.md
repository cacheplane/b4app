## 2026-11-02 (M8f, attention on the phone)

- **D-124 The payload carries the thread id, not a link.** `{"aps": {"alert": {"title", "body"}, "sound": "default", "content-available": 1, "thread-id"}, "threadId", "reason"}`; the spool adds `Simulator Target Bundle`. The app builds `<its own scheme>://thread/<id>` (`ThreadLink`) and sends a notification tap and a widget row through the one path that `onOpenURL` uses (`MirrorHost.handle(url:)`), so the hub never needs to know a flavour's URL scheme. A thread link on a signed-out phone is swallowed, never handed to sign-in or pairing. A request that arrives before the model is connected (a cold launch from a tap) is held and opened once the first snapshot is in, without delaying the event stream, and the iPhone moves to the thread column even when the request predates the view. In the foreground a notification shows unless its thread is open and on screen.
