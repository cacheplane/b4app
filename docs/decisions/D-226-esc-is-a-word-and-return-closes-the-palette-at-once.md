## 2026-11-14 (palette keys and closing)

- **D-226 The Escape keycap is the word "esc", the palette's Back hint names Escape, and Return on a thread closes the palette at once (amends D-221 and D-207).** At the owner's direction after using the Local app: "Use the word esc on the Escape keycap. After hitting enter and selecting a thread, it feels like there is a slight lag before the command palette is hidden. It says 'shift tab' (I think) to go back in the command palette - this is wrong, it's just esc to go back."
  - **Escape.** D-221 drew every key as an SF Symbol, Escape included, against its research, which recommended the word. The cap now prints "esc" (`HintKey.legend`), at the 11 pt medium a printed character has; `HintKey.escape.symbol` is nil. VoiceOver and the tooltip still say "Escape". Every other key keeps its symbol.
  - **Back.** The footer's Back hint showed Shift and Tab. It now shows the esc cap, which is the key people use to go back one level. No key binding changes: Escape and Shift-Tab both still go back, and Tab still shows a row's actions.
  - **Closing.** Opening a thread from the palette chose the thread, then waited for the coordinator's read of it before reporting done, so the palette stayed on screen for the length of that read. The command now chooses the thread, starts the read without waiting for it, and reports done; the palette closes at once and the thread fills in behind it, as it does when a row in the sidebar is clicked. A read that fails is reported where a sidebar click reports it, not in the palette, which is gone by then.
  - **Commands.** The Commands row showed Shift, Command and P in caps. It now shows a single "/", the key that opens Commands from inside the palette, at the owner's direction ("it should just be a single slash '/' - though we can keep the global shortcut"). Shift-Command-P still opens Commands from anywhere; it is no longer advertised in the row.
  - **Checked.** `HintKeyTests` (Escape has no symbol, prints "esc", is said "Escape") and `PaletteModelTests.openingAThreadFinishesBeforeTheThreadIsRead` (the palette finishes while the read is held, and the thread shows once it answers). Not yet looked at in the running app.
