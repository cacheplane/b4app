## 2026-11-01 (sidebar redesign)

- **D-053 The sidebar becomes a chat-app sidebar; Connections, Local servers, and Diagnostics move to a Settings window reached from a profile menu.** At the owner's direction (design `docs/superpowers/specs/2026-11-01-sidebar-profile-settings-design.md`, approved 2026-11-01). The sidebar holds, top to bottom: New thread (⌘N, also a `CommandGroup` in the Mac's File menu), Search (⌘K, a palette over the window on the Mac and a sheet on the iPhone, matching shown titles, so "untitled" finds an untitled thread), and More (on the Mac the "Show archived" switch that replaces M8b's inline one, and the connection filter; on the iPhone the project filter that used to sit in the toolbar), then M8b's thread list with no "Threads" label, then the profile button. There is no mark or title at the top and no surface rows; `Surface` is gone and the model has `SettingsPage` and a `settingsRequest` counter that the root view turns into `openSettings()` (Mac) or the Settings sheet (iPhone), so a remediation such as "Open Connections" now opens Settings at that page.

  Thread rows are one line: the attention dot, the title, and the runtime's mark in a ghosted grey (`LLA.Color.ghost`, light `#B8B8BC`, dark `#5A5A5E`). The reason line and the connection moved into the row's accessibility label, with "Pinned" and the connection's trouble when it is offline; the iPhone keeps a pin glyph, since its flat list has no Pinned group. The marks are real: the Anthropic mark from Simple Icons 16.36.0 and the OpenAI mark from Simple Icons 15.22.0, the last release that has it (16.0.0 removed it); both are CC0 path data, vendored in `Resources/Brand/` with a comment saying so, and the trademarks are their owners'. B4 has a "B4" monogram. The ghost colour is exempt from the 3:1 graphics floor because the marks are supplementary. The brand SVG reader gained arcs and run-together decimals, which those files use.

  The profile button shows initials (or a person glyph), the hub user's name (or "Not signed in"), and the coordinator state in a few words. The coordinator's error, the host's note, and a version mismatch appear as a notice above the button, three lines at most, because the footer sits outside the scroll view (D-047). The menu is the app's own panel rather than SwiftUI's `Menu`: a `Menu` opens downward from its label on the Mac and as a context menu on the iPhone, and the design needs it to open upward at the button's width on both. It holds Settings (⌘,), GitHub (https://github.com/cacheplane/b4app in the default browser), and Log out. The panel is lifted by the button's measured height; an alignment guide on the overlay was ignored and the panel drew over the button.

  Settings on the Mac is a `Settings` scene: a 200 pt sidenav in the sidebar's style beside the page, in a plain `HStack` (a nested split view would give the window a second collapsible sidebar), with a 760 × 500 minimum. A page's one action (Re-check runtimes, Refresh) sits in the page heading there, since the scene has no navigation toolbar; on the iPhone the pages push from a list in a sheet and keep the action in the toolbar.

  Log out on the Mac is `hub leave` after a confirmation: the device is revoked, its token forgotten, and the threads stay. Joining again is `agent-workspace hub join` with a new code; there is no join screen in the app. On the iPhone, Log out (`MirrorLogOut`) revokes the device (best effort), forgets the token and the link, empties the mirror (rows, the outbox of unsent edits, and the devices list), and returns to the Connect screen; unsent edits are discarded rather than uploaded under a later link. The iPhone shows "Host disconnected" in place of the list when the mirror's `devices` table, which M8b refreshes each sync cycle, is non-empty and has no unrevoked macOS device; an empty table (before the first fetch) is not a lost host, and a joined Mac that is asleep still counts (telling those apart is M8c presence). The menu still works there, so the phone can log out.

  The hub user's display name reaches the Mac through `HubStatus.Result.displayName` (optional, so an older coordinator decodes as absent). `HubSync` keeps it in memory, from the enrollment or from `GET /v1/me` when it starts on an existing link, so the link table needed no migration; while the name is unknown it asks again after each successful push or pull, and the Mac's window refreshes the account when it becomes active. The phone fetches `/v1/me` once per sync start. A sign-in screen (Apple ID or a passkey, gating the whole app) is a separate project that needs identity-provider work on the hub (M8d); until then the app stays usable after Log out and shows "Not signed in".

  *Amended by D-100, D-101, D-108 (sign-in):* the Mac's Log out is now the account log-out (the session ends, the device is kept), and `hub leave` is "Remove this Mac from your account" on Remote access; the iPhone's Log out ends the session and keeps the device instead of revoking it, and returns to the sign-in screen.
