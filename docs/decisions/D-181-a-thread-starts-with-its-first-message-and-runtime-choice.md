## 2026-11-04 (new-thread composer)

- **D-181 A thread starts with its first message and its runtime choice, on the Mac as from the phone.** `thread.start` (create a thread and run its first turn in one command) is no longer relay-only: the Mac's own app sends it over the local socket, and `SessionService.threadStart` owns its validation, which moved out of `RelayExecutor` with the same refusal reasons in the same order. The relay calls it with `requireProject` (a start with no `projectId` is refused `project_missing`, and a remote B4 connection `remote_b4`, as before); the router calls it without, so a Codex or Claude start may name only a folder, which joins the project that owns it or a new automatic one as the thread is inserted, and a remote B4 connection may start a thread. `ThreadStart.Params` gains `model` and `permission` (and `projectId` becomes optional; a phone that always sends it is unaffected): the permission is checked against the runtime's options and both are refused on B4, as `thread.update` does; both are stored on the new thread and handed to the runtime's new session, so Claude Code launches with `--model` and `--permission-mode` rather than being corrected by control requests. The thread is titled from the first non-empty line of its first message, cut at 60 characters on a word boundary with "…" (`ThreadTitle.fromFirstMessage`).
  - **Amends D-012.** The app still passes no approval policy or sandbox of its own: it passes a model or a permission only when the user picks one for the thread. "As configured" (no permission) and "Default" (no model) leave the runtime's configuration in charge, as D-012 had it.
  - **Amends D-048.** A thread's project's other folders are attached to every turn (Codex `writableRoots`, Claude `--add-dir`), but membership is unchanged: a thread belongs to the project of the folder it started in.
  - **The Codex limit.** The extra folders reach Codex only as `sandboxPolicy.writableRoots`, which Codex takes only under the "Auto" preset (`workspace-write`). Under "As configured", "Read only", and "Full access", Codex sees them only as far as its sandbox already allows: read-only or the configured sandbox may keep it out of them, and full access reaches them anyway.
  - **Left as they were.** `RelayExecutor` still runs `thread.start` once per command id and starts of one thread id one after another; the router replays a completed operation id, and the durable lookup by operationId answers a repeat after that. A local `thread.create` still cannot choose its thread's id.
