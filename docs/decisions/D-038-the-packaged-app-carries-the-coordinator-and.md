## 2026-10-31 (M6)

- **D-038 The packaged app carries the coordinator and the CLI in `Contents/Helpers` and a LaunchAgent plist in `Contents/Library/LaunchAgents`; the app registers the agent with `SMAppService` and hosts in-process only as a fallback.** Order on connect: an answering socket wins; otherwise a bundled agent is registered (`RunAtLoad`, `KeepAlive` on failure only, Aqua session) and the socket awaited for six seconds; otherwise the app hosts as before (Xcode runs, an agent awaiting Login Items approval, a failed registration). The link status says when approval is needed and opens Login Items. Restart is `launchctl kickstart -k` for the agent, a close for an in-process host, or SIGTERM for another process; the CLI exposes the same as `coordinator status|stop|restart`, and the app's Coordinator menu adds "Remove Background Agent", which unregisters. The coordinator version is the package's version (`CoordinatorVersion.current`, stamped into `MARKETING_VERSION` by `Scripts/package.sh`); a running coordinator that reports another version shows a restart note. Amends D-004 (the LaunchAgent exists) and D-032: with the agent hosting, Quit owns nothing and local work continues. Amended 2026-10-31 (M7 switch-over): launchd pins a lightweight code requirement to the registered program, and with an ad hoc signature that requirement is the binary's own hash, so a rebuilt bundle leaves the job loaded but unspawnable ("needs LWCR update", exit 78 EX_CONFIG) while the previous coordinator keeps serving from its deleted file. The app therefore calls `SMAppService.register` on every launch (idempotent; it refreshes the requirement), `Agent Workspace --register-agent` does the same for scripts, `coordinator status` prints launchd's job state and last exit code, and `coordinator restart` gives launchd 90 s for the orderly shutdown that now stops the cluster. A Developer ID signature would make the requirement stable across rebuilds.
