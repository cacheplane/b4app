## 2026-11-11 (marks and rows)

- **D-204 The thread list has six states, one mark per state, and a single-line row (amends D-036, D-048, D-053, D-126).** The four attention bands and their dot are gone. A thread is in one of six states, each drawn by one mark in the row's trailing 12 pt, and the Mac's new thread, search and view options moved to the window's top bar. Design: `docs/superpowers/specs/2026-11-10-thread-list-and-environments-design.md`. The code is commits 1a8904d, 8c2592d, 566f6b4, e6be925, c3f4f96 and 5fa4471.
  - **Six states.** `ThreadState` (`WorkspaceProtocol`, `Attention.swift`): `approve`, `reply`, `failed`, `finished`, `working`, `quiet`, raw values 0 to 5 in that display order. `Attention.state(of:)` decides, first match wins: no activity is quiet; a pending approval is approve (it wins over a pending question); a pending request is reply; no latest turn is quiet; a latest turn waiting for the user is reply; a latest turn that has not ended is working; a latest turn that failed is failed, read or not; a latest turn that is not the thread's read turn is finished; otherwise quiet. `AttentionBand`, `Attention.band(of:)` and `AttentionDot` are removed, not aliased.
  - **Failed and cancelled.** Only `TurnOutcome.failed` is failed. A cancelled turn (the owner stopped it) is finished, then quiet once read. A failure's reason line says "Failed" with its time, read or not.
  - **Approvals.** `RuntimeRequestKind.isApproval` is true for `command_approval`, `file_change_approval` and `tool_permission`, and `pendingApprovals` counts those. `user_question`, `elicitation` and `unknown` are replies.
  - **Top list and order.** `isTopList` is true for the first four states and `isActLevel` for the first three. `Attention.ordered` sorts by state, then pinned first, then newest activity, then id, so a pin no longer lifts a thread above a more urgent state. The Mac's separate "Pinned" group stays as it is until the arrangements plan.
  - **Badge unchanged.** `needsYouCount` counts approve, reply and finished, plus failed only while its latest turn is unread: the same numbers as "needs input or unread" before. The hub's badge SQL and `Tests/Fixtures/sync/attention.json` are untouched. Ruling: a turn waiting for the user with no pending request shows as reply but does not count toward the badge, because the hub's SQL does not count it and the badge must not change; the plan's wording ("reply counts") lost to that constraint (`countsTowardBadge`).
  - **One mark per state** (`ThreadMark`, `Theme/ThreadMark.swift`, 12 pt box). Shape carries the meaning and colour only reinforces it, so the list reads in greyscale: approve is a ring around a dot, reply a large solid dot, failed a cross, finished a small solid dot, working a faint ring with a short arc, quiet nothing. Only two things are coloured: the failed cross (LLA danger, `#962E1F` light, `#E07A6A` dark) and the working arc (lime `#B4CE37` in both modes). The cobalt accent no longer appears in the list.
  - **Motion.** An approve mark pulses until the thread has been opened on this device since its latest activity (`WorkspaceModel.isAcknowledged`, from `acknowledgedActivity: [threadId: lastActivityAt]`, in memory only, never synced or stored). The working arc orbits and a working title shimmers (`workingShimmer`). With Reduce Motion on there is no slide, lap, shimmer or pulse; the orbit is a still ring with a lime arc and an arrival shows its hairline only. Text never blinks.
  - **The row** (`ThreadRow`). One line on a 4 pt grid: title from x 16, mark in a 12 pt box at x 212 to 224, the selection and press fill across x 8 to 232 of a Mac sidebar fixed at 240 pt. 28 pt rows on the Mac and touch, 44 pt minimum on the phone with Dynamic Type, Hanken Grotesk 13/16 titles. Act-level titles are medium (weight 500); a quiet title is muted and fades with the age of `lastActivityAt` in five steps (`QuietFade`: under 1 day 1.0, under 3 days 0.9, under 7 days 0.82, under 14 days 0.76, otherwise 0.72). The pin glyph and the runtime mark leave the row on both platforms; both stay in the row's spoken label and the context menu, and the spoken label adds the state.
  - **Arrivals** (`ArrivalTracker`, `Theme/ArrivalTrace.swift`). A thread that enters the top list traces its arrival for 10 s: it slides in, draws a hairline on its fill's edge, and a point of light laps the edge twice in 3.5 s. One lap at a time: a thread that arrives while another is lapping gets the slide and the hairline but no lap. Nothing traces on the first load, on an environment or connection filter change, or when the list is rebuilt after sign-in.
  - **Weight 500.** `HankenGrotesk-Medium.ttf` joins the bundle (source and SHA-256 in `docs/compatibility.md`). It is the unmodified static Medium from the designer's repository, `github.com/marcologous/hanken-grotesk`, because Google Fonts ships only a variable font.
  - **The Mac's top bar** (`TopBar.swift`). View options (`line.3.horizontal.decrease`, the former "More" menu with its contents unchanged), search and new thread are borderless 28 pt buttons in one toolbar item beside the system's sidebar toggle. With the sidebar hidden the detail column carries search and new thread. New thread and search are File menu commands, so ⌘N and ⌘K work with the sidebar hidden. The accessibility identifiers `thread-row`, `new-thread-toolbar` and `sidebar-search` keep their names.
  - **"New Environment…" leaves the Mac sidebar**, and `NewEnvironmentSheet` with it; nothing replaces it (an environment is made when a folder is first used). The phone's create-environment sheet is untouched.
  - **Widths.** The Mac sidebar column is fixed at 240 pt (`LLA.Metrics.sidebarWidth`); the iPad's stays `min: 240, ideal: 290`. The Mac's minimum window is still 900 by 600, so the detail column gets 660 pt (it had 610). The container is whatever the system draws; this change does not restyle it.
  - **The widget shares the mark** (amends D-126). The widget's dot is `ThreadMark(state:animated: false)`: the same shapes, never moving.
  - **Amends.** D-036: the list no longer uses the accent; lime and danger are the only colours in it. D-048: the four bands become the six states and the order above. D-053: the row shows a title and one mark, with no leading dot, pin glyph or runtime mark, and the sidebar's action rows moved to the top bar. D-126: the widget's dot is the shared mark.
  - **Three LLA rules the owner knowingly bent**, per the design's Constraints: motion on several rows (orbit, shimmer, pulse, arrival trace); one gradient (the shimmer and the trace); and a soft shadow on the palette only, which this change does not touch.
  - **Deviations and rulings.** (1) The row has no hover fill: the design says "selection, hover" but names no colour, so none was built; a Mac hover fill is a follow-up. (2) The arrival's point of light uses an `AngularGradient` about the row's centre, so on a 224 by 28 row it does not move along the edge at constant speed. (3) ⌘N and ⌘K are File menu commands ("Search…" is new) rather than shortcuts on sidebar rows. (4) The Mac's "New Environment…" row is gone with no replacement. (5) The sidebar is 240 pt on the Mac only. (6) The medium font is a static file from the designer's repository, not from Google Fonts.
  - **Follow-ups** (a fix wave follows and will update this record). The selected, open thread should count as acknowledged: activity arriving while it is open re-pulses its approve mark. A Mac hover fill (the raised surface at 60% opacity, same geometry). The trace should lap at constant speed (a trimmed stroke along the rounded-rect path). The owner's own "Mark as Unread" and a mark-read rollback should rebase the tracker rather than trace. `refreshEnvironments` does not feed the arrival tracker, so a thread moving into "No folder" under that filter can trace on the next event. The view-options button's hit area is 29 by 16; it should be 28 by 28 like the other two. Deferred minors: no pending `file_change_approval` in the query tests; the approval kind list is written three times (Swift and two SQL); no mirror-level test that a waiting turn with no request is not badged; the fallback font test near-duplicates `fallsBackWhenMissing`, and `working` is not in the "13 resolved colours" test list; no test pins `animated: false` (the widget) to no motion, and the accessibility2 gallery row is a no-op on macOS; the collapsed section header's mark is acknowledged only when every thread in that state was opened; the shimmer's dim colour mixes over the Mac sidebar surface, so the phone's row background needs checking; no direct test of `Dynamic.mixed`; the spoken-state dedupe is a `hasPrefix` heuristic; the row couples to the sidebar's 10 pt padding by a -2 outset; the trace's timeline redraws every frame for its static stretch; `noteThreadList` re-sorts and invalidates all rows on every event; the tracker and the view use different clocks under a replaced `now()`; the menu guards differ (New Thread by `accountState`, Search by `rootScreen`); the new-thread button has no selected look while the composer is open; no structural test that the sidebar's action rows are gone. Accepted as they are: a reconnect snapshot traces threads that entered the top list while the link was down, archived rows never trace, and unarchiving a top-list thread traces.
