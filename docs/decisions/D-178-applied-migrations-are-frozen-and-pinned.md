## 2026-11-04 (applied migrations are frozen)

Found when every hub deploy after D-174 (cacheplane/b4app#108, `9d79481`) failed at the migrate task on the test hub: "migration 7 was previously applied but has been modified". Numbered D-178 by `Scripts/docs-index.sh --next`.

- **D-178 A migration, once committed to `main`, is never edited, and a test pins every hub migration's SHA-256.** sqlx stores each applied migration's checksum and refuses to migrate a database whose applied migration has since changed, so D-174's rewrite of a `docs/decisions.md` link inside a comment of `0007_apple_handoffs.sql` stopped every deploy: the test hub stayed on its previous revision from 01:59 UTC, and the next production release would have stopped the same way. `0007` is restored byte for byte (the comment keeps its old link; the decision it names is D-092), and `Hub/crates/b4hub-db/tests/migrations_frozen.rs` checks every file in `migrations/` against a pinned SHA-256 (failing on a change, a removal, or a new migration not yet pinned), so the next edit fails in CI rather than at deploy. A change to an applied migration goes in a new migration. Links inside SQL comments are left as they are by repo-wide rewrites.
