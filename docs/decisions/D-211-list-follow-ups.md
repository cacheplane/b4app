## 2026-11-12 (thread list follow-ups)

- **D-211 Four follow-ups from the thread list work: overtaken settings reads are made again, the palette's highlight keeps its row, folder rows name their environment, and offscreen test windows never count as the app's window (extends D-208, D-210).** Each was recorded as left undone in D-208 or D-210, or found while gating them.
  - **View settings reads (D-208's follow-up).** A read that a set or an event overtook was dropped, so a set made during the first-connect read left the other fields on their defaults until the next snapshot. `refreshViewSettings` now reads again, three times at most, and gives up after that until the next snapshot. A read that answers while a set is still out may carry the row from before the set: it is not shown, and the read is made again when the last set out has settled (`viewSettingsSetsOut`, `viewSettingsReadOwed`). Both are reset when the account ends, and a set answered after its account ended touches neither, so it cannot hold back or use up the next account's read.
  - **The palette's highlight (D-210's "not ported").** When the environments change under an open palette the highlight stays on the row it was on, by id (`PlacePalette.highlight(_:keeping:in:)`); if that row is gone it stays where it was, inside the list, and the row now there becomes the remembered one. A filter change still puts it on the checked row, else the first.
  - **Reading the rows.** A folder's row carries the hint "In <environment>" on the Mac's palette and the phone's sheet, for a reader who cannot see the indent (`Row.environmentName`). The phone's sheet closes when its draft finishes, as the Mac's palette does.
  - **Test windows.** `AppleSignInTests.appleSheetSaysItHasNoWindow` expects the sign-in code to find no window, and failed in the full suite whenever another suite had a snapshot window open: the lookup takes any visible window that can become main. The snapshot harness's offscreen windows are now a `BackgroundWindow` that can become neither key nor main. The one on-screen window, used only under `B4APP_SNAPSHOT_ROOT=1`, is unchanged. No product code changed for this.
  - **Still open.** The hub keeps one `view` row per org (D-208); the hub accepts any `viewSettings` row id (D-208); VoiceOver on macOS can still reach the sidebar while the palette is open (D-210).
