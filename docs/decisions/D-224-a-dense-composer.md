## 2026-11-13 (a dense composer)

- **D-224 A dense composer shows one line where the pickers were (amends D-218 and D-223).** Part 4 of the density design: when Dense is on, the Mac's composer draws one muted line in place of its row of pickers, in a thread and on the new-thread screen. Design: `docs/superpowers/specs/2026-11-12-density-and-user-settings-design.md`, Part 4; plan: `docs/superpowers/plans/2026-11-13-dense-composer.md`. The code is commits 0798f9af (the line's words), 632d0140 (tests of the thread's line), 5af6423e (Choose folder), e2f70170 (drawing the line) b050200d (Choose folder needs the new-thread screen; a failed start sits under the line), 14b92aa2 (the folder panel returns the cursor however it closes), and the last fix round (the words VoiceOver reads, and the path on a folder row).
  - **What dense draws.** `ComposerSummary` (`Sources/WorkspaceUI/NewThread/ComposerSummary.swift`) builds the words and `ComposerSummaryLine` draws them as one muted line; `ComposerView` (a thread) and `NewThreadView` draw it instead of `ComposerPickerRow` when `WorkspaceModel.denseComposer` is true. The line names, in the pickers' order, the place, the runtime and model, and the permission, joined by ` · `. On the new-thread screen the place is the environment (with the starting folder's name when it has several), a chosen folder by its own name, or `No folder`. In a thread the place is left out. A B4 agent shows its route's start label and no permission; a draft with no connection reads `No runtime`. The permission is named only when one is chosen, as the picker would show it. VoiceOver reads the line as one text, for example "Runs in b4app with Claude Code, Opus"; every ` · ` is read as a comma, and the permission is its label alone ("Runs with Claude Code, Sonnet, Plan mode"), since some labels already say "permissions". The line is text, not a control: it opens nothing, and it changes as soon as a command changes a choice. The picker row builds its place and runtime text from the same statics, so the two cannot disagree.
  - **The Mac only.** `denseComposer` is `false` on iOS, so the phone and the iPad keep their pickers at either density, as the spec said. The field, Send, the turn row and the status line stay at both densities. At normal density the composer draws as before; "Choose folder…" (`/browse`) and the folder panel's focus handling apply at both densities. Nothing is stored and nothing on the wire changed; there is no migration and no hub deploy.
  - **The commands the palette already had.** For the place of a new thread, `draft.environment` ("Choose where it starts…", `/environment`); for the runtime and model, `draft.runtime` ("Choose runtime and model…", `/model`) on a new thread and `thread.model` ("Choose model…", `/model`) in a thread; for the permission, `draft.permission` and `thread.permission` ("Choose permissions…", `/permissions`). Each already changes its choice, so hiding the pickers strands nothing except the next item.
  - **The new command.** The place palette's "Choose folder…" (the system folder panel, which starts a thread in a folder that is not yet an environment) had no command, so with the row hidden there was no way to reach it. `draft.chooseFolder`, "Choose folder…", slash `/browse` (aliases "browse", "open folder", "other folder"), is offered on the Mac's new-thread draft, after `draft.environment`. It is unavailable on a Mac that relays through the hub ("This Mac's folders cannot be browsed from here.", as the palette's footer button is disabled), and on iOS. It has no shortcut: ⌘O stays the place palette's own key. Running it counts `chooseFolderRequest`, which `NewThreadView` answers by closing the place list and opening the panel; the focus handler for the palette's own dismissal now leaves focus alone while the panel is up.
  - **Two rulings changed during the build, both the builder's calls.** (a) The spec gave the status line's row to "Starting…" and to a failed send. Only "Starting…" takes the row. A failed start sits under the line, like a blocked reason, because a failure stays until the next Send and would hide the line for as long as the owner is changing the place to fix it. The blocked reason ("No ready connection can start a thread in this environment.") also sits under the line and the line stays. (b) "Choose folder…" is refused with "Open a new thread first." when the new-thread screen is not showing (`WorkspaceModel.newThreadViewIsShowing`, which repeats the tests of `ThreadsView.threadOrComposer`; the two are to be changed together), because only `NewThreadView` answers the request and with another screen up nothing would open.
  - **The plan's other rulings, unchanged.** In a thread the line is always shown. A draft with no connection reads `No runtime`. No new shortcut for the model or the permission: ⇧⌘P and `/` in the field reach them. If the runtime and permission alone are wider than the row (the narrowest window, a long connection label) they truncate at the tail after the place has gone to its floor; the spec's "never truncate them" cannot hold below that width.
  - **Folder rows carry their path.** In "Choose where it starts…" a row for one of an environment's several folders is titled with the folder's last name, so two folders with the same name looked alike, and at dense this list is the only way to choose one. Each such row now has the folder's path as its detail, written as the place palette writes it (the home folder as `~`).
  - **The Display page's description changes** (amends D-223 call 11). On the Mac it reads "Tighter rows for the threads that don’t need you, answers without the steps in a thread, and a composer without its pickers."; the phone's is unchanged.
  - **Not built.** Shortcuts for the model and the permission. The line on the phone and the iPad (their pickers stay). A command that opens the place palette itself; `draft.environment` takes its choice as an argument and `draft.chooseFolder` opens the panel only.
  - **Not checked.** The running app. The folder panel opened from the palette or `/browse` on a real screen, and cancelling it returning the focus to the field: the focus handlers were changed for it and have no test. VoiceOver on the line. The narrowest window on a real screen. The iOS-only branches of the tests, which `swift test` does not run; the iOS build and the iOS layout run cover them.
