## Diagnosis and retained change

NIO's `executeThenClose` scopes still finish writers and close channels while unwinding. Cancelling those scopes and shutting down their event-loop group immediately allowed cleanup to schedule on a dead loop. Strict mode reproduced a fatal failure in the baseline and repeated-close regression. Client and server now share one close task per instance and join the I/O owners before shutting down the group. Server dispatch uses a cancellation-aware reply box so a request ignoring cancellation cannot keep that I/O scope alive. Late work retains no channel/writer and sends no reply. Four regressions cover repeated/concurrent close, late send, idle clients, and a held external request. The required CI Test step now uses strict NIO checking; it does not suppress the diagnostic.

Both fake B4 entry points used Python `HTTPServer.server_bind`, which invokes `socket.getfqdn` solely to populate `server_name`. The fixture handlers do not use that canonical name. A shared `FixtureHTTPServer` keeps real TCP bind/listen, threading and HTTP/SSE behavior, and fills the unused field from the numeric bound address. Both entry points close their server on exit. A negative regression patches DNS to fail and exercises both actual entry points; it failed twice on the baseline and passes on the candidate. Existing HTTP/SSE, permission, interruption, reconnect and restart tests remain in the full suite.

The historical run 41519013466 had a 751s Test step and 580.089s library span, including many roughly 35s B4 cases. It is a different source/test population and is not a comparable candidate baseline. [The setup-python maintainers independently reproduced macOS 26 loopback resolver delays above 30s](https://github.com/actions/setup-python/issues/1223). That primary evidence plus the exact fixture call supports the DNS explanation; this repository's hosted per-process lookup was not instrumented then, so attribution remains an inference. The added CI bind profiler records both real binds, Python/platform/source identities and a bounded advisory unpatched DNS probe for the next authorized run.

## Path and rollback

CI's lint, package, apps and hub jobs are independent. Within package: checkout/Xcode → SwiftPM restore → format → bounded fixture profiler → PostgreSQL restore/fetch → build → full strict tests. Within a B4 test: fixture process → numeric socket bind → readiness → HTTP/SSE assertions → shutdown; the resolver dependency was removed from that fixture startup path. NIO shutdown is owner cancellation/channel close → owner completion → event-loop shutdown. No release path dependency or cache policy changed.
